# 同步缺口手动恢复目标订阅，事务成功后解除屏障

历史决定：2026-09-09。补录日期：2026-09-30。

投影缺口先暂停该任务相关发送，由用户在现有连接内手动更换目标订阅，不为单任务故障重连整个 GUI，也不重建并丢弃任务的内存状态。选择手动恢复而非自动尝试，使用户明确控制恢复时机；代价是发生缺口后需要一次操作。

新快照、待处理事实与候选订阅事件在原任务的持久化事务内核对，保存成功且连接、成员和恢复尝试身份仍有效后，才发布新权威基线并解除对应暂停。保存失败保留旧内容与草稿，不把请求返回或连接就绪当作恢复成功；迟到订阅与重入事件也不能复活失效能力。

连接不可用、同步暂停、刷新后的恢复暂停及结果未知是独立屏障，恢复其中一项不能顺带清除其他项。未知发送与压缩仍保留原关联身份，重复快照不证明执行完成，避免恢复过程触发重复执行。

恢复证据与现状核对：[连接与同步恢复 #192](https://cnb.cool/jiangshengdev/codex/-/issues/192)。
