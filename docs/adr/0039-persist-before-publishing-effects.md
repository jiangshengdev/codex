# 候选状态先保存，再发布并执行发送效果

历史决定：2026-09-06；未知合并记录完整移除修订：2026-09-08。补录日期：2026-09-30。

提交、恢复及相关队列变更先准备候选状态，通过完整性检查并保存成功后，才发布新状态和执行允许的发送效果。保存失败保留原状态与输入，阻止新提交，不以警告后继续发送来掩盖失败，也不因此停止后端已有运行。

移除未知合并记录时，必须释放合并容器及全部原消息归属，将删除与允许的后续推进纳入同一准备和保存边界。失败回滚，不提前显示成功或发送；成功后仍受其他未知记录、恢复暂停和发送门禁约束，不能通过放宽验证容忍孤儿归属。

此取舍让可恢复记录先于不可撤回的发送副作用成立，代价是存储失败影响提交可用性，并要求内存发布与持久化事务协同。保存成功不代表服务端已接收，发送结果仍按其独立交付事实核对。
