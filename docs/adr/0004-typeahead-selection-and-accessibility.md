# Skill 候选保持单一键盘选择归属

历史决定：2026-08-29；多编辑器例外确认：2026-09-01；滚动修订：2026-09-02。补录日期：2026-09-30。

Skill 候选的键盘选择和首尾循环由 Lexical 统一管理，视觉组件不建立第二套选择状态。完全沿用库内固定标识会破坏同时打开多个 Composer 时的 ARIA 关联，因此保留每个编辑器的最小标识同步适配；这是明确接受的库能力例外，而非重写键盘导航。

候选渲染后只将活动项滚入内部可见区域，状态横幅位于该滚动区域之外，不以手写索引几何或第二个键盘处理器补偿。该边界承担多编辑器无障碍与滚动整合成本，同时避免双重选择归属；升级编辑器库时仍须核对这些职责。

恢复证据与现状核对：[Skill 候选与结构化提交 #186](https://cnb.cool/jiangshengdev/codex/-/issues/186)。
