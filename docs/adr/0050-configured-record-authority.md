# 项目配置决定正式记录权威，领域文档保留单一上下文

历史决定：2026-09-14。补录日期：2026-09-30。

正式记录载体按项目配置选择，不由通用 skill 强制所有项目使用 CNB 或本地日期文档。本项目的规格、任务、正式调研、验收、完成说明及状态以 CNB 为权威；本地草稿、日志和待补录结果只是临时材料，不形成第二套任务状态或自动同步。

共享领域术语和 ADR 继续保存在仓库的 single-context 布局，覆盖 GUI 与 Rust，不按实现语言拆分。旧 `docs/superpowers/` 保持 ignored 历史，不迁移全部旧内容，也不通过取消跟踪抹除 Git 历史。

CNB 不可用但必要信息充分时，继续已经授权的本地工作；恢复后先重读最新记录，再在授权范围内写回并回读验证。本地完成不代表远端已更新，未知写入不能盲目重试，载体规则也不额外授予外部写权限。

此取舍减少跨位置查找和双重权威维护，同时保留历史与短暂离线工作的连续性；代价是阶段、工作树及发布工具共同遵守项目记录配置。领域文档保留于仓库是知识模型边界，不是 tracker 的镜像。

恢复证据与现状核对：[后期工程治理来源恢复 #206](https://cnb.cool/jiangshengdev/codex/-/issues/206)、[项目 tracker 配置](../agents/issue-tracker.md)、[领域布局](../agents/domain.md)。
