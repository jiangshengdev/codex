# Storybook 复用真实生产能力，隔离演示专用产物

历史决定与修订：2026-09-14、2026-09-16、2026-09-18、2026-09-22。补录日期：2026-09-30。

Storybook 使用真实组件、业务 owner、路由和投影，只模拟外部事实，不复制生产状态机或为场景反向修改产品语义。关键状态可直接预置并继续本地操作；仅必要瞬态允许冻结，必须明确且可解除，场景数据仍须满足真实业务约束。

生产 JS、CSS 与语言包排除专为演示创建的场景、虚构数据、模拟控制和专用资源，但生产构建仍受 Storybook 类型错误约束。用户明确选择产物隔离而非连类型检查也隔离；主题切换等生产能力即使暂时只有 Story 使用，也不因此归为演示专属。

DEV 辅助区与产品组件分开，隐藏时不渲染辅助 DOM，但保留业务状态和 owner；页内辅助可在显示时影响布局，隐藏后应忠实反映产品，不用虚构高度或占位修饰产品问题。只允许以辅助操作准备产品场景，不把调试辅助自身重新设为产品测试对象。

此取舍需要跨构建、翻译、状态与预览入口维持依赖边界，换取可控演练而不产生第二套产品。Storybook 与模拟平台的证据不等于真实运行时、原生 IME 或可见桌面验收，各次验收范围分别记录。

恢复证据与现状核对：[测试支撑与开发展示边界 #207](https://cnb.cool/jiangshengdev/codex/-/issues/207)。
