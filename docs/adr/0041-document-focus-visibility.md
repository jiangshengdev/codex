# 保留浮动布局，按实际上下遮挡最小显露焦点

历史决定：2026-09-28。补录日期：2026-09-30。

保留当前任务 sticky Composer、历史任务 fixed Continue、既有动态底部占位和整页文档滚动，不改为独立正文滚动容器。正文中的按钮或链接获得焦点且被遮挡时，只滚动必要距离；已经可见、底部输入区内部聚焦或用户手动滚动时不追随移动。

可用上下界来自实际顶部导航、sticky 提示及底部区域的布局几何，随尺寸变化更新；先完成底部处理后，用户又明确补上顶部遮挡。过高目标优先显露顶部，避免反复上下振荡，而非无条件 scrollIntoView 或添加重复占位。

此取舍保持既有浮动阅读体验，代价是共享布局 owner 协调异步尺寸、原生焦点滚动与可见区域。它仅覆盖已确认的遮挡问题，不宣称解决全部焦点圈裁切、菜单或 portal、完全离屏目标，也不把历史自动化证据冒充真实运行时验收。

恢复证据与现状核对：[可访问布局与控件约定 #202](https://cnb.cool/jiangshengdev/codex/-/issues/202)。
