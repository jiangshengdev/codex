# 重试按业务结果解除故障

历史决定：2026-09-09。补录日期：2026-09-30。

恢复入口保持具体动作名称，异步执行期间原位显示进度和进行中文案、防重复点击，并保留当前失败；失败后更新原因并恢复原动作，业务真正恢复才解除相应故障。同步操作不人为增加 loading，历史轮次错误不因之后成功而删除，请求 resolve 也不自动等于业务成功。

此取舍使重试期间仍可查看有效诊断，代价是业务必须提供真实 pending、失败和成功状态，不能只依据 Promise 控制外观。规则尊重后续明确的业务差异：上传重试进入上传中并隐藏旧上传失败，预览重试仍保留旧失败，见[上传与预览状态](0007-upload-and-preview-states.md)。未知发送、部分 Skill 目录和仅重试导航各按自己的成功判据处理。

恢复证据与现状核对：[错误与诊断反馈 #200](https://cnb.cool/jiangshengdev/codex/-/issues/200)。
