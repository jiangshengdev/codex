# 手动压缩以本地互斥和运行时事实管理生命周期

历史决定：2026-09-03；恢复边界修订：2026-09-09。补录日期：2026-09-30。

GUI 使用现有 `thread/compact/start`，在本活动会话内保留请求归属并与发送互斥；观察到活动时禁用入口，不预约压缩。响应空对象只表示请求提交，运行和完成反馈由权威事件驱动，自动压缩仅在观察到时展示，不插入临时正式消息。

本地保留覆盖请求到轮次被接受的空窗，但不承诺跨客户端原子空闲，也不增加排队压缩、自动重试、服务端请求身份或压缩专用重连协议。首个接受轮次仅是尽力关联，不能充当强请求关联。未接受的启动失败可由用户重试；已运行的失败或中断沿用正式记录的真实语义。

结果未知时保留归属与限制，不自动重发，也不凭空闲快照或连接恢复解除。后续原位恢复保留这些状态并在事务成功后核对；重复快照本身不证明请求完成，关联轮次的权威完成事实才可结算。此取舍限制 GUI 的承诺范围，代价是某些未知结果需要继续保留，而非提供可能重复执行的快捷清除。
