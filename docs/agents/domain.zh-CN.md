# 领域文档

## 布局

采用 single-context：

- 根目录 `CONTEXT.md`：共享的领域术语、关系和约束。
- 根目录 `docs/adr/`：需要长期保留的架构决策。

同时覆盖 GUI 和 Rust 后端，包括两者之间的协议与职责边界。编程语言不同并不意味着领域上下文不同。

## 探索代码前

阅读 `CONTEXT.md` 和与当前任务相关的 ADR，同时遵守实际适用的目录级 `AGENTS.md` 指令。

领域文档不存在时，直接继续任务，不报告缺失，也不建议预先创建空文档。在术语和决策实际明确后，使用 `domain-modeling` 按需记录，并遵守当前授权及文档流程。

## 术语

在问题标题、方案、假设和测试中使用术语表定义的术语，避免使用术语表明确排除的同义词。

所需概念尚未定义时，先检查项目现有术语。确有缺口时，将其记录为领域建模的输入。

## ADR 冲突

明确指出方案与哪些现有 ADR 冲突，解释冲突内容以及可能需要重新讨论的理由，不得静默覆盖原有决策。
