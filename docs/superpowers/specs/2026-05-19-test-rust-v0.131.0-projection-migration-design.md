# test rust-v0.131.0 Projection Migration Design

## 背景

`test` 是长期维护分支，基于原始 `rust-v0.130.0` 开发。它不能合并回 `main`，后续只能通过官方发布 tag，把 `main` 的变化一次一次单向合并到 `test`。

本次迁移目标是在新的 `dev` 分支上吸收官方 `rust-v0.131.0`，同时保留 `test` 上的本地核心 overlay：thread projection。

thread projection 不是 `rust-v0.131.0` 的官方功能。0.131 提供了相近但不等价的 thread history 能力，例如 `thread/read(includeTurns)`、`thread/turns/list` 和普通 turn/item notification stream；它没有 `thread/projection/attach`、`thread/projection/detach`、`thread/projection/event`，也没有 projection subscription、`subscriptionId`、`headCommitId`、`commitId` / `parentCommitId` commit chain，或 connection-scoped projection fanout。

因此，本次设计采用 `tag merge + overlay re-integration`：先以官方 tag 为底座，再把 projection 作为本地 overlay 重新接回 0.131 的真实结构。

## 目标

- 在 `dev` 分支上完成正式设计和迁移工作。
- 把官方 `rust-v0.131.0` 完整吸收到 `test` 的后续迁移线中。
- 保留 projection 的 API、runtime、lifecycle、测试和文档语义。
- 让 projection 适配 0.131 的 app-server、app-server-protocol、TUI 和 generated schema 结构。
- 保持官方 0.131 已有功能不被 projection overlay 破坏、削弱或覆盖。
- 让本次迁移方式能复用于后续 tag 合并，减少未来冲突面。

## 非目标

- 不把 `test` 合并回 `main`。
- 不把 projection 改写成 upstream-ready PR。
- 不把 projection 退化成 `thread/read`、`thread/turns/list` 和普通 notification stream 的薄组合。
- 不用整文件覆盖方式回退 0.131 的结构性改动。
- 不为 projection 引入通用 extension framework。
- 不覆盖 GUI 后续、长期 release 治理或 upstream-ready 方案。
- 不在设计阶段修改生产代码或运行大范围测试。

## 已确认决策

- 迁移模型采用 `tag merge + overlay re-integration`。
- `dev` 分支同时承载正式设计文档和实际迁移工作。
- 冲突处理以官方 `rust-v0.131.0` 的结构和功能完整性优先。
- projection 是本地核心 overlay，不能被官方相邻 API 替代。
- projection snapshot 对齐或复用 0.131 官方 thread reconstruction 语义。
- projection attach 继续强制 listener-ordered。
- projection subscriber 参与 thread unload 判断。
- TUI 对 `ThreadProjectionEvent` 只做 no-op / global-none 处理。
- projection runtime/manager 保持独立，只在官方热路径加 thin hooks。
- schema / TypeScript 生成物后置，最终状态以 generator 输出为准。
- projection lifecycle 与普通 thread subscription lifecycle 保持独立。
- 默认只做窄范围验证；全量测试需要单独明确授权。

## 总体迁移策略

迁移分两层处理：

1. 官方层：合并 `rust-v0.131.0`，保留官方新增模块、官方重构、官方 API 和官方行为。
2. overlay 层：把 projection 的协议、runtime、request processor、fanout、lifecycle 和 TUI no-op 重新接到 0.131 的真实结构上。

冲突解决时先恢复官方 0.131 的结构，再重新插回 projection thin hooks。不要把 0.130 时代的 projection diff 机械套到 0.131 上，也不要为了让 projection 接入更容易而重排官方控制流。

## 薄接线原则

projection 主体必须继续放在自有模块中，官方热文件只承担接线职责。

projection 自有模块包括：

- `codex-rs/app-server-protocol/src/protocol/v2/thread_projection.rs`
- `codex-rs/app-server/src/thread_projection.rs`
- `codex-rs/app-server/src/thread_projection_runtime.rs`
- `codex-rs/app-server/src/request_processors/thread_projection.rs`
- projection 相关 focused tests

官方热路径只允许增加薄 hook：

- protocol registry 追加 projection request / notification variant。
- app-server module registry 追加 projection module。
- request processor dispatch 追加 projection handler。
- `ThreadListenerCommand` 追加 projection attach response command。
- typed notification fanout 追加 projection event fanout。
- unload watcher 追加 projection subscriber watch。
- connection close tail 追加 projection cleanup。
- TUI exhaustive match 追加 no-op / global-none。

薄 hook 的边界：

- 不把 projection 主体塞进官方大文件。
- 不为了 projection 抽象或重排官方 0.131 控制流。
- 不复用 ordinary subscribe 作为 projection attach 的实现。
- 不让 `thread/unsubscribe` 隐式 detach projection。
- 不让 projection event 改变普通 notification 的发送目标或顺序。

未来合并新 tag 时，先接受上游文件的新结构，再按这些稳定 choke point 重新插回 hook。这样即使上游继续重构，冲突面也集中在少数接线点，而不是散落在 projection 的核心逻辑里。

## Projection 协议设计

保留当前 projection wire surface：

- `thread/projection/attach`
- `thread/projection/detach`
- `thread/projection/event`

保留 projection attach response 语义：

- 返回 `subscriptionId`。
- 返回 `snapshot`。
- `snapshot` 包含当前 `thread` 和 `headCommitId`。

保留 projection event envelope：

- `threadId`
- `subscriptionId`
- `commitId`
- `parentCommitId`
- wrapped event

wrapped event 只覆盖四类 thread notification：

- `turn/started`
- `turn/completed`
- `item/started`
- `item/completed`

0.131 的官方 `thread/read`、`thread/turns/list` 和普通 notification stream 可以作为实现支撑，但不能成为 projection 协议的替代品。

## Snapshot 设计

projection snapshot 继续是 projection attach 的一部分，但 snapshot 内部的 thread/turn 构造必须对齐 0.131 官方 thread reconstruction 语义。

迁移时优先复用或严格对齐这些 0.131 能力：

- persisted rollout history 到 API turns 的 reconstruction。
- live `ThreadState::active_turn_snapshot()`。
- live active turn 与 persisted turns 的合并。
- stale in-progress turn 的状态修正。

设计约束：

- 不直接照搬 0.130 时代独立的 live-turn 合并路径。
- 不让 projection snapshot 与官方 `thread/turns/list` 对同一个 live turn 给出不同状态或不同顺序。
- 保留 projection 自己的 `headCommitId`，不把 commit chain 交给官方 thread history API 推断。

## Attach 设计

projection attach 继续保持 listener-ordered，不在 request processor 内直接完成注册。

attach 的顺序语义：

1. request processor 校验参数并准备 thread context。
2. snapshot 读取逻辑对齐 0.131 thread reconstruction。
3. attach response command 进入 `ThreadListenerCommand` 队列。
4. listener task 内检查 thread closing 状态。
5. listener task 内确认 connection 仍 live。
6. listener task 内注册 projection subscriber。
7. listener task 内处理 late close cleanup。
8. listener task 内发送 attach response。

这个顺序保留 attach / connection-close race 防护，也避免 projection attach 隐式创建 ordinary thread subscription。

## Fanout 设计

projection fanout 接在 0.131 的 typed thread notification fanout choke point 上。

fanout 原则：

- 官方普通 notification 仍发给普通 thread subscribers。
- projection runtime 从原始 typed notification 中生成 projection event。
- projection event 只发给 projection subscribers。
- projection manager 维护 `commitId` / `parentCommitId`，不依赖普通 notification consumer 自行推断 ordering。
- 不改变官方普通 notification 的目标连接集合。

projection 只投影四类事件：turn started、turn completed、item started、item completed。

## Lifecycle 设计

projection lifecycle 与 ordinary thread subscription lifecycle 保持独立。

明确边界：

- `thread/projection/attach` 创建 projection subscription。
- `thread/projection/detach` 移除 projection subscription。
- `thread/unsubscribe` 只处理 ordinary subscription。
- connection close 清理 projection subscriptions。
- thread teardown 清理 projection entries。

projection subscriber 必须参与 unload 判断。thread 只有同时满足以下条件时才允许 unload：

- 没有 ordinary thread subscribers。
- 没有 projection subscribers。
- thread 非 active。
- idle 时间达到 unload delay。

projection detach、connection close 和 thread teardown 都必须更新 projection subscriber watch，让 unload watcher 能被唤醒。

## 接线边界

迁移时需要重新定位 0.131 的真实 owner 文件，不按 0.130 旧位置硬套。设计上只允许 projection 在少数稳定 choke point 接入，避免把 overlay 逻辑扩散到官方业务分支里。

允许的接线边界：

- `app-server-protocol`：注册 `ThreadProjectionAttach`、`ThreadProjectionDetach` 和 `ThreadProjectionEvent`。
- `app-server` module registry：追加 projection 自有模块。
- `request_processors`：追加 projection request processor dispatch。
- `ThreadListenerCommand`：追加 projection attach response command。
- `ThreadScopedOutgoingMessageSender::send_server_notification`：追加 projection fanout。
- `UnloadingState`：追加 projection subscriber watch。
- connection close path：在 official processors close 完成后追加 projection cleanup。
- TUI notification handling：在 0.131 的 exhaustive match owner 文件中对 `ThreadProjectionEvent` 做 no-op / global-none。

connection close 的设计约束是：先完成官方 processors close，再让 thread processor 标记 connection 不再 live，最后清理 projection manager 中该 connection 的 projection subscriptions。

## TUI 设计

TUI 不是 projection client。本次迁移只保证 TUI 能接受新增 `ThreadProjectionEvent` variant，不把 projection event 接入 TUI 状态模型。

处理原则：

- 先定位 0.131 的真实 exhaustive match owner。
- 在新的 owner 文件中增加 no-op / global-none。
- 不把旧的 `chatwidget.rs` 当唯一目标。
- 不让 TUI 复用 projection event 驱动普通 thread UI。

## Generated Schema 设计

schema JSON 和 TypeScript 生成物后置处理。

冲突解决时不要把手工拼接的 generated files 当最终状态。最终状态必须以 generator 输出为准，并确认官方 0.131 新类型和 projection 类型都存在。具体生成、提交拆分和验证安排放到后续计划文档中展开。

## 变更组织约束

正式迁移必须区分官方合入、本地 overlay、生成物和验证修复。设计文档只规定这个边界，不展开具体提交安排。

release/version 文件如果发生冲突，应单独看待，不和 projection runtime 语义修复混在一起。

## 验证边界

默认只做窄范围验证，不跑全量 Rust 测试、workspace-wide 测试或 crate-wide 大测试。全量验证需要单独明确授权。

设计上需要覆盖的验证对象包括：

- projection protocol surface。
- projection attach/detach/event runtime。
- snapshot 与 0.131 thread reconstruction 的语义对齐。
- projection subscriber 对 unload 的影响。
- connection close cleanup。
- TUI 对 `ThreadProjectionEvent` 的 no-op handling。
- generated schema 同时保留官方 0.131 API 和 projection API。

具体验证命令和执行顺序放到后续计划文档中展开。

## 风险与处理

### Snapshot 语义分叉

风险：projection snapshot 继续使用 0.130 独立合并逻辑，导致它与 0.131 `thread/turns/list` 对同一 live active turn 给出不同状态或顺序。

处理：projection snapshot 对齐或复用 0.131 reconstruction。focused test 覆盖 loaded thread、persisted turns 和 live active turn 的组合。

### Lifecycle 混合

风险：projection attach 复用 ordinary subscribe，或 `thread/unsubscribe` 隐式 detach projection，导致两套 lifecycle 混合。

处理：保留专用 live connection check / thread state access。detach 只通过 `thread/projection/detach`、connection close 或 thread teardown 完成。

### 官方热文件冲突扩大

风险：为了快速迁移，把 projection 主体写进 0.131 官方热文件，导致未来每次 tag merge 都重复冲突。

处理：projection 主体留在自有模块；官方文件只做 thin hooks；hook 优先放在稳定 choke point。

### Generated schema 漂移

风险：手工解决 generated schema 冲突时丢掉官方 0.131 类型或 projection 类型。

处理：generated files 后置，以 generator 输出为准，单独 review generated diff。

### TUI 旧位置失效

风险：按 0.130 的旧 `chatwidget.rs` 位置处理 `ThreadProjectionEvent`，但 0.131 已经拆分 notification handling。

处理：先定位 0.131 的真实 exhaustive match owner，再添加 no-op / global-none。

## 成功标准

- `dev` 上存在正式设计文档，并与已确认决策一致。
- `dev` 后续迁移完成后，目标状态等价于 `test` 包含官方 `rust-v0.131.0` 和 projection overlay。
- 官方 0.131 功能没有因 projection overlay 退化。
- projection API surface 仍存在。
- projection attach/detach/event runtime 保留 independent lifecycle 和 commit chain。
- projection snapshot 与 0.131 thread reconstruction 语义对齐。
- projection subscribers 参与 unload 判断。
- connection close 能清理 projection subscriptions，且不改变官方 close 顺序。
- TUI 能处理 `ThreadProjectionEvent` variant，但不消费 projection 数据。
- schema / TypeScript 生成物同时包含官方 0.131 API 和 projection API。
- 官方合入、本地 overlay、生成物和验证修复的边界清楚，便于下一次 tag 合并复用。
