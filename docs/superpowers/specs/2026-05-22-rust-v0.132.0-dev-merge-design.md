# rust-v0.132.0 dev Merge Design

## 背景

`dev` 是当前 fork 的集成分支，已经吸收官方 `rust-v0.131.0`，并在其上重新接回本地核心 overlay：thread projection。当前目标是把官方 `rust-v0.132.0` 单向合入 `dev`，同时保留 fork 专属功能和 release/update channel 约束。

本次不是从零迁移 projection。0.131 迁移后，projection 已经以本地 overlay 的形式存在于 `dev`，包括：

- `thread/projection/attach`
- `thread/projection/detach`
- `thread/projection/event`
- projection subscription、`subscriptionId`、`headCommitId`
- per-thread `commitId` / `parentCommitId` chain
- listener-ordered attach
- projection generation gate
- projection snapshot canonical reconstruction reuse

官方 `rust-v0.132.0` 仍然没有 thread projection API 或 runtime。因此本次继续沿用 `tag merge + overlay preservation` 模型：先接受官方 tag 的真实结构，再保留本地 overlay 的最小接线。

## 已确认现状

- 当前分支：`dev`
- 当前 `dev` HEAD：`b5211de48df0096d0c0c22284f431dafeff7010c`
- `rust-v0.131.0`：`05eb8678451435cbc8d79c6d8254276289f2bdf1`
- `rust-v0.132.0`：`13595c36e218fcbd13df118eeadf00d4eb0e6d31`
- `dev` 已包含 `rust-v0.131.0`。
- `dev` 尚未包含 `rust-v0.132.0`。
- `git merge-tree --write-tree --messages HEAD rust-v0.132.0` 预演显示当前明确内容冲突集中在 generated TypeScript 文件 `codex-rs/app-server-protocol/schema/typescript/ClientRequest.ts`。

这个冲突集中在生成物上，不代表迁移风险只有一个文件。source 层的真实风险在 app-server protocol registry、permissions API、plugin installed API、thread history image detail reconstruction、TUI notification match 和 fork release/update channel 约束。

## 目标

- 把官方 `rust-v0.132.0` 合入 `dev`。
- 保留官方 0.132 的 source、protocol、schema、TUI、exec、goals、plugins、remote executor 等行为。
- 保留本地 projection overlay 的 API、runtime、lifecycle、测试、schema 和 README 契约。
- 保留 fork 专属 release/update channel guard，不恢复上游 OpenAI-only side effects。
- 让最终树状态能作为后续 tag merge 的干净基线。
- 让验证范围聚焦在本次真实改动面，而不是默认跑全量测试。

## 非目标

- 不把 `dev` 合回 `main` 或上游。
- 不把 projection 改写成 upstream-ready PR。
- 不把 projection 退化成 `thread/read`、`thread/turns/list` 或普通 notification stream 的组合。
- 不通过整文件覆盖回退 0.132 的结构变化。
- 不手工维护 generated schema/TypeScript 的最终内容。
- 不在本设计阶段修改生产代码或执行真实 merge。
- 不主动运行全量测试或 release build；全量测试需要单独确认。

## 推荐执行模型

采用 integration branch 预合并：

1. 从当前 `dev` 创建 `codex/merge-rust-v0.132.0`。
2. 在 integration branch 上执行 `git merge rust-v0.132.0`。
3. 解决 source 层冲突时优先保留官方 0.132 结构。
4. 把本地 projection/fork overlay 作为最小接线重新落回官方结构。
5. source 编译面稳定后统一 regenerate app-server schema/TypeScript。
6. 通过窄验证后，再把结果合回 `dev`。

不建议直接在 `dev` 上做第一次 merge。0.131 迁移历史里已经出现多次 merge/revert/reapply；integration branch 能保留可丢弃的试错面，避免污染 `dev`。

## 合并原则

### 官方 0.132 优先

冲突解决默认接受官方 `rust-v0.132.0` 的 source 结构和行为，再插回本地 overlay。不要为了让 projection 接入容易而恢复 0.131 或本地旧结构。

必须保留的 0.132 变化包括：

- `plugin/installed` API、processor、schema 和 TypeScript。
- `experimentalFeature/list` 的可选 `threadId` 参数。
- `command/exec.permissionProfile` 从完整 `PermissionProfile` 改为 `ActivePermissionProfile`。
- v2 API 不再导出完整 `PermissionProfile` / `PermissionProfileFileSystemPermissions` / `PermissionProfileNetworkPermissions`。
- `UserInput::Image` 和 `UserInput::LocalImage` 的 `detail` 字段。
- `UserMessageEvent` 的 `image_details` 和 `local_image_details`。
- thread history reconstruction 对 image detail 的保留。
- `view_image.detail` 支持 `high` 和 `original`。
- TUI startup terminal probe 批处理。
- TUI session picker paste、renamed thread resume hint、shutdown feedback。
- in-progress MCP replay、elicitation route-to-request-thread 修复。
- `ThreadGoalStatus::Blocked` 和 `ThreadGoalStatus::UsageLimited`。
- exec resume `--output-schema`。
- remote executor standard Codex auth registration 和 websocket keepalive。

### Overlay 最小重放

projection 仍然是本地 overlay。允许重放的内容限于 projection 自有模块和少数稳定 choke point：

- `codex-rs/app-server-protocol/src/protocol/v2/thread_projection.rs`
- `codex-rs/app-server/src/thread_projection.rs`
- `codex-rs/app-server/src/thread_projection_runtime.rs`
- `codex-rs/app-server/src/request_processors/thread_projection.rs`
- app-server protocol registry 中的 projection request / notification variant。
- app-server message dispatch 中的 projection processor。
- listener command 中的 projection attach response command。
- typed notification fanout 中的 projection event fanout。
- unload watcher 中的 projection subscriber watch。
- connection close tail 中的 projection cleanup。
- TUI notification handling 中对 projection event 的 no-op / global-none。
- focused projection tests 和 schema fixtures。

projection hook 只能做 dispatch、delegation、watch 组合或 cleanup 调用。hook 内不保存 projection 状态，不实现 commit chain，不重排官方主控制流。

### Fork guard 保留

本地 fork 对 release workflow、npm update channel、OpenAI-only side effects 已有定制。合并 0.132 时必须防止这些 guard 被官方文件覆盖。

需要重点复核：

- `.github/workflows/rust-release.yml`
- `.github/workflows/rust-ci-full.yml`
- `codex-rs/tui/src/npm_registry.rs`
- `codex-rs/tui/src/update_action.rs`
- `codex-rs/tui/src/update_prompt.rs`
- `codex-rs/tui/src/updates.rs`

如果官方改动与 fork guard 冲突，优先保留 fork guard，再按 0.132 的真实新字段或新控制流做最小适配。

## 关键冲突面设计

### app-server protocol registry

`codex-rs/app-server-protocol/src/protocol/common.rs` 是高风险文件。0.132 新增 `PluginInstalled` request，dev 上已有 projection request/notification。

最终状态必须同时包含：

- `PluginInstalled => "plugin/installed"`
- `ThreadProjectionAttach => "thread/projection/attach"`
- `ThreadProjectionDetach => "thread/projection/detach"`
- `ThreadProjectionEvent` server notification

不要用整段旧 registry 覆盖 0.132 registry。应在官方 0.132 registry 上插回 projection variant。

### app-server dispatch

`codex-rs/app-server/src/message_processor.rs` 和 `codex-rs/app-server/src/request_processors.rs` 必须保留 0.132 新增 dispatch，同时接回 projection dispatch。

最终状态必须同时包含：

- `PluginRequestProcessor::plugin_installed`
- `CommandExecRequestProcessor::new(..., config_manager.clone())` 等 0.132 参数变化。
- projection request processor construction。
- `ClientRequest::ThreadProjectionAttach` / `ThreadProjectionDetach` dispatch。

### permissions API

0.132 把 app-server v2 API 中的完整 `PermissionProfile` 移除，`command/exec.permissionProfile` 只接受 `ActivePermissionProfile`。

设计决策：

- 接受 0.132 的权限 API 方向。
- 不恢复 v2 `PermissionProfile` 作为 client-facing payload。
- projection 不依赖完整 v2 `PermissionProfile`，因此不应成为回退该 API 的理由。
- generated TypeScript 中不应重新出现 `v2/PermissionProfile*.ts`，除非 source 中确实重新引入了官方 API surface；本次不允许这样做。

### thread history image detail

0.132 让 image fidelity 成为 user input 和 persisted history reconstruction 的一部分。projection snapshot 必须继承这个语义。

设计决策：

- `thread_history.rs` 以官方 0.132 为准。
- projection snapshot 继续复用 canonical reconstruction。
- 不恢复旧的 compatibility/fallback shape。
- 若 projection snapshot 测试需要更新，应断言 `UserInput::Image { detail }` 和 `UserInput::LocalImage { detail }` 被保留。

旧 shape 的回归信号仍然是：

- `read_projection_base_thread_view`
- `merge_live_projection_state`
- `read_thread_view(thread_id, /*include_turns*/ true)`

这些不应重新成为 projection snapshot 主路径。

### generated schema and TypeScript

merge-tree 预演中的唯一内容冲突在 `schema/typescript/ClientRequest.ts`。这是 generated file。

设计决策：

- source 层先合正确。
- 不以手工编辑 generated file 作为最终修复。
- source 合并完成后运行 `just write-app-server-schema`。
- schema/TS 最终必须同时反映 0.132 官方 API 和本地 projection API。

最终 generated surface 应满足：

- 有 `PluginInstalledParams` / `PluginInstalledResponse`。
- 有 projection attach/detach/event types。
- `ClientRequest.ts` 同时包含 `plugin/installed` 和 `thread/projection/*`。
- `ServerNotification.ts` 包含 projection event notification。
- 不恢复 0.132 已删除的 v2 full `PermissionProfile*.ts`。

### TUI notification handling

0.132 修改了 TUI app event、replay、session picker、goal menu、terminal probe 等多个区域。projection 对 TUI 的要求仍然很窄。

设计决策：

- 保留 0.132 TUI 改动。
- 只在 exhaustive match owner 中对 `ThreadProjectionEvent` 做 no-op / global-none。
- 不为了 projection 回退 TUI startup probe、resume hint、goal status 或 settings persistence。

### goals 和 state db

0.132 新增 `Blocked` / `UsageLimited` goal statuses，并把 state DB goal access 收敛到 `thread_goals()` accessor。

设计决策：

- 接受 0.132 goal status 扩展。
- 接受 `state_db.thread_goals().*` 调用形状。
- projection 不修改 goal semantics。
- 如果 projection tests 触达 thread resume / status notification，必须兼容新增 status enum。

## 验证策略

默认执行窄验证，不主动跑全量测试。

### source-shape checks

合并后至少做以下 grep 级检查：

```bash
rg -n "PluginInstalled|plugin/installed" codex-rs/app-server-protocol/src codex-rs/app-server/src
rg -n "ThreadProjection|thread/projection" codex-rs/app-server-protocol/src codex-rs/app-server/src codex-rs/tui/src
rg -n "read_projection_base_thread_view|merge_live_projection_state|read_thread_view\\(thread_id, /\\*include_turns\\*/ true\\)" codex-rs/app-server/src
rg -n "PermissionProfileFileSystemPermissions|PermissionProfileNetworkPermissions|export .*PermissionProfile" codex-rs/app-server-protocol/schema/typescript/v2
```

期望：

- `PluginInstalled` 和 projection 都存在。
- 旧 projection snapshot compatibility shape 不存在。
- generated v2 full `PermissionProfile` 类型不被复活。

### formatting and generation

```bash
cd codex-rs
just fmt
just write-app-server-schema
```

如果 source 没有改 config schema，不运行 `just write-config-schema`。

### protocol and app-server tests

```bash
cd codex-rs
cargo test -p codex-app-server-protocol
cargo test -p codex-app-server thread_projection --no-fail-fast
cargo test -p codex-app-server plugin_installed --no-fail-fast
cargo test -p codex-app-server experimental_feature_list --no-fail-fast
cargo test -p codex-app-server command_exec --no-fail-fast
cargo test -p codex-app-server turn_start --no-fail-fast
```

如果 exact filter 名称与当前测试不匹配，先用 `rg -n` 定位真实 test name，再跑最窄 filter。

### TUI tests

如果 TUI source 或 snapshots 被合并修改，执行：

```bash
cd codex-rs
cargo test -p codex-tui
```

如果产生 snapshot 更新，必须逐个检查 `.snap.new`，确认变化来自 0.132 官方 UI 改动或本地已授权 UI 改动，再决定是否 accept。

### lint

在 Rust source 合并完成并通过窄测试后，按改动 crate 运行 scoped fix：

```bash
cd codex-rs
just fix -p codex-app-server
just fix -p codex-app-server-protocol
```

如果 TUI source 也有实质 conflict resolution：

```bash
cd codex-rs
just fix -p codex-tui
```

不要在 `fix` 或 `fmt` 后重复跑已通过测试，除非 `fix` 做了非机械改动。

## 风险与缓解

### 风险：generated file 冲突被手工修成半旧半新

缓解：只把 generated conflict 解决到可继续 merge 的临时状态，最终以 `just write-app-server-schema` 输出为准。review 时看 source 和最终 generated diff，而不是信任手工 conflict edit。

### 风险：`plugin/installed` 被 projection registry 覆盖掉

缓解：source-shape check 明确要求 `plugin/installed` 和 projection request 同时存在。

### 风险：v2 full `PermissionProfile` 被本地旧 schema 复活

缓解：接受 0.132 source 中 `ActivePermissionProfile` API，不从旧 generated files 或旧 tests 恢复 `PermissionProfile*.ts`。

### 风险：projection snapshot 丢失 image detail

缓解：projection snapshot 继续复用 0.132 thread history reconstruction；必要时补 focused test 断言 image `detail`。

### 风险：fork release/update channel guard 被上游覆盖

缓解：把 release/update channel 文件列为固定复核项，不用上游整文件替换 fork guard。

### 风险：TUI 为 projection 回退 0.132 UI 修复

缓解：projection 在 TUI 的职责只是不处理 projection notification；不要恢复旧 startup probe、settings persistence、goal menu 或 resume picker 逻辑。

## 完成标准

- `dev` 或 integration branch 的祖先链包含 `rust-v0.132.0`。
- projection API、runtime、schema、tests 仍存在。
- 0.132 `plugin/installed`、`ActivePermissionProfile` command exec API、image detail reconstruction、goal statuses、TUI startup probe 等上游变化仍存在。
- generated app-server schema/TypeScript 是重新生成后的最终状态。
- fork release/update channel guard 保持有效。
- 窄验证通过，或失败项有明确 blocker 说明和下一步。
