## 目标

修正今天 GUI 展示改动中的 HeroUI 组件组合与动作语义偏差，让错误提示清楚表达问题和可执行动作，原始诊断按需查看，并复用现有队列查看入口。

本设计是新的展示修正工作，不覆盖或改写此前错误归属、多会话及持久化设计的历史记录。

## 已确认决策与边界

- 审查和修正范围是今天提交涉及的 GUI 展示，不扩展为整个应用的历史样式清理。
- 错误提示首屏显示简明说明及适用的恢复动作，原始诊断统一通过“查看诊断信息”打开，完整保留。
- 查看队列沿用现有 Pending 入口；不新增重复的“查看”按钮、队列弹窗或检查页面。
- 将恢复暂停提示中的 `Review and continue` 改为“继续发送”，准确表达点击结果。查看和继续发送保持独立，打开或关闭队列抽屉不触发发送。
- 保留现有恢复机制、发送结果未知消息的展示与阻塞规则；不把未知消息自动重发，也不要求用户必须先打开抽屉才能继续。
- 不调查或修复底层 `no rollout found`，不改变错误归属、重试调用、队列业务规则、协议或持久化格式。
- 不在本轮修复既有 `retryError` 通用提示覆盖错误详情的业务优先级；按需诊断完整保留展示层当前已收到的诊断，不以此扩大为错误状态模型改造。

## 反馈与诊断展示

### 首屏反馈

使用 `Alert`、`Alert.Indicator`、`Alert.Content`、`Alert.Title`、`Alert.Description` 表达反馈。失败使用 `status="danger"`，恢复暂停及发送结果未知继续使用 `status="warning"`。不把原始 JSON-RPC 字符串、错误码或长标识符作为首屏主要说明。

标题和说明基于当前已知失败上下文表达，例如任务加载失败、任务操作失败、任务列表更新失败、保存失败。没有结构化原因时不得猜测网络、权限或数据损坏，也不通过新增协议解析器推断原因。

恢复动作与其对应提示放在同一反馈容器内。宽屏可将简短动作放在内容旁，窄屏允许换行至说明下方；使用明确间距，避免按钮紧贴描述、挤压文本或产生不可达溢出。HeroUI 示例提供参考，不将右侧位置视为强制规范。

对于只有全局错误、但当前任务页承担既有恢复入口的情形，保留原有错误归属和恢复能力，不为视觉组合复制全局诊断或把错误迁移到另一个 owner。

### 动作语义

| 动作 | HeroUI 选择 | 约束 |
| --- | --- | --- |
| 加载失败重试、重试保存 | `Button variant="primary"` | 作为对应失败上下文的主要恢复动作 |
| 继续发送 | `Button variant="primary"` | 保留现有可用性和调用条件，仅明确动作文案 |
| 查看诊断信息 | `Button variant="secondary"` | 辅助查看，不改变失败状态 |
| 删除发送结果未知的本地记录 | 保留 `Button variant="danger"` | 既有破坏性动作；不扩大为服务端撤回 |
| 关闭诊断 | `Modal.CloseTrigger` | 保留可访问名称与焦点恢复 |

其他操作重试按原操作语义及所处上下文确定主次，不把所有重试机械改成 `danger` 或把同一上下文的所有动作都提升为主要动作。错误状态色与动作 variant 分别表达反馈严重性和操作意图。

### 原始诊断

在本次范围内，将原始诊断入口统一为“查看诊断信息”，使用 HeroUI `Modal` 的既有组合方式。弹窗具有标题、关闭入口、内部滚动、长文本换行和窄屏宽度约束；保留 Escape 关闭及返回触发按钮的焦点行为。

原始诊断按当前展示层输入完整呈现，不截断、隐去错误码或用通用说明替代；没有原始诊断时不制造空入口。不改变错误的生成、存储、清除、归属和重试优先级。简明说明与原始诊断是同一失败的两种展示，不形成第二份错误状态。

可提取复用的纯展示组合，但不创建通用错误 owner、恢复控制器或统一业务错误模型。各功能继续拥有自己的失败解释、恢复调用和状态生命周期。

## 队列查看与继续发送

Pending 入口及其现有队列抽屉继续负责查看与管理排队消息。恢复暂停提示负责说明“先检查队列、其他页面和历史，再继续”，按钮仅表达“继续发送”。两者已有各自入口，无需在恢复提示中再添加查看按钮。

继续发送仍调用 `resumeRestored`，保留保存失败或会话不可用时的禁用条件。发送结果未知的消息仍由现有提示展示并保持阻塞，其本地记录删除动作保持原有语义；不把这类消息强行并入普通待发送抽屉。

本设计不更改抽屉列表、分页、编辑、排序、删除和焦点生命周期，也不增加查看记录、强制确认或自动发送触发条件。

## 组件、样式与权威来源

- 组件使用 `@heroui/react`，样式使用 `@heroui/styles`。本地源码与 GUI 解析的 react/styles 版本均已核对为 `3.2.4`。
- 本地文档：`codex-gui/.heroui-docs/react/getting-started/(overview)/design-principles.mdx`、`components/(feedback)/alert.mdx`、`demos/en/alert/basic.tsx` 及 Modal 文档。
- 遵循语义 variant 与现有 surface、foreground、muted、separator 等主题 token，不引入硬编码状态色。
- `primary` 表达主要推进动作，`secondary` 表达辅助或替代动作，`tertiary` 表达取消、跳过等动作，`danger` 表达破坏性动作。Alert 示例中红色 Retry 不覆盖该语义原则。
- 保留有语义的 `main`、列表、文本节点及诊断正文结构，不把普通文档标签一律视为自定义控件。
- 本次仅消费已有会话快照、队列快照及错误输入，不新增或复制跨模块协议 DTO、运行时校验器或持久化契约。
