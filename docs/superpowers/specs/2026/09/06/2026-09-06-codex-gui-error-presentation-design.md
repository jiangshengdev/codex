# Codex GUI 错误展示归属与任务菜单设计

## 1. 主目标与范围

解决同一次失败在全局提示、当前任务正文及菜单任务卡片中重复展示的问题。按实际影响范围明确错误展示归属，并覆盖首次启动、多会话并行、切换、后台失败和恢复场景，避免重复提示或遗漏必要错误。

本设计同时包含用户在评估期间明确选择的菜单简化：任务标题、更多操作下拉及异常红点。

本轮不处理重试后通用提示覆盖错误详情的问题，不调查或修复底层 `no rollout found` 错误，不增加新建会话、自动重连或自动恢复执行能力。

相关历史设计：[多会话激活设计](2026-09-06-codex-gui-multi-session-activation-design.md)。本文替换其中菜单展示状态文字、当前查看文字及直接展开错误和操作的呈现规则；多会话运行、持久化、恢复门禁和安全移出语义保持原约束。历史文档不回写。

## 3. 展示归属

### 3.1 全局提示区

负责连接、鉴权、握手及会话集合读取／保存失败。集合错误可能使目标任务无法加入列表，必须在菜单关闭、任务尚不存在时仍然可见。

同一个全局错误只展示一次详情。任务页和历史页可以说明当前功能受限，但不能复制该全局错误详情。不同来源的独立失败不能因全局区域已有错误而被吞掉。

单个任务的加载或激活失败不再写成“无法启动 Codex GUI”。任务已经可用但持久化失败等情形也不能误报为整个 GUI 启动失败；必须保留具体失败信息和实际影响范围。

### 3.2 任务页面

负责该任务的错误详情和重试入口。首次加载、切换目标任务及后台恢复失败使用相同归属规则。

后台任务失败不覆盖正在查看的其他任务正文，不自动切换任务。用户通过异常任务行进入对应页面查看详情和处理。

全局失败与独立任务失败同时存在时，分别保留其归属与信息；不能将两个不同失败当作重复内容删除。现有失败恢复和状态清理语义不因展示去重而改变。

本设计仅调整详情和重试入口的展示位置，不修复现有 `retryError` 优先显示通用提示的逻辑；后者需要单独任务。

### 3.3 菜单

每个任务项的文字只显示任务标题；无标题时显示 UUID，不使用会话 preview 作为回退。

不再展开状态文字、“当前查看”文字、错误详情、重试按钮、移出说明或移出阻塞说明。保留必要的无障碍名称和当前项语义，不要求通过可见说明文字表达这些信息。

任务标题作为切换入口；旁边提供紧凑的更多操作按钮，下拉中保留“移出列表”。菜单其他导航入口不因本次任务行简化而重新设计。

移出仍只结束当前 GUI 中的驻留，不删除历史或草稿。现有安全移出判断继续生效，不能把隐藏说明解释为解除阻塞或允许强制移出。移出当前查看任务后的既有路由行为保持。

### 3.4 异常红点

菜单入口汇总当前仍未解决的异常；对应异常任务行显示红点。只显示红点，不显示数量或错误文字。

集合级错误只触发菜单入口红点，不把同一集合错误分配给所有任务行。连接级错误由全局提示表达；不能仅因共享连接异常而虚构各任务独立失败。

打开菜单或查看任务不自动清除红点。红点随其所属异常状态更新，异常解决后清除；多个异常并存时，一个异常解决不能清除其余异常的提示。红点不建立独立的“已读”或历史通知状态。

红点是错误状态的摘要，不替代具体错误的可访问内容，也不把普通空闲、正常加载、正常运行或正常恢复等待自动当成错误。

## 4. 场景边界

| 场景 | 预期展示及行为 |
| --- | --- |
| 首次打开目标任务，加载失败 | 该任务正文展示失败；任务行及菜单入口显示异常红点；顶部不复制为 GUI 启动失败 |
| 当前任务正常，切换目标任务失败 | 目标任务页承接其失败；其他会话保持后台运行 |
| 后台任务初始化或恢复失败 | 对应任务行与入口显示红点；当前任务正文不被覆盖 |
| 多个任务独立失败，错误文字相同 | 各自保留错误归属与红点，分别在对应任务页查看 |
| 集合读取失败，尚无任务项 | 全局显示集合错误，菜单入口显示红点；不能依赖不存在的任务项提供详情 |
| 新任务加入集合时保存失败 | 全局显示集合错误；目标页面可以说明不可用，不复制详情；原会话继续遵守既有运行语义 |
| 任务已可用，但选择或集合持久化失败 | 全局保留持久化错误，不能误报任务未加载或整个 GUI 未启动 |
| 鉴权、握手或共享连接失败 | 全局展示其详情一次；当前任务、历史列表和历史详情不重复同一错误 |
| 全局错误与独立任务错误同时存在 | 各自保留，不通过统一优先级隐藏独立错误 |
| 主操作失败且清理也失败 | 保留主体与清理失败信息；按实际归属展示，不在去重过程中丢弃附加失败 |
| 任务恢复成功 | 对应任务提示跟随实际状态更新，不残留首次启动错误；不影响其他异常 |
| 切换任务或打开菜单 | 不视为解决错误，不自动清除红点 |
| 安全移出任务 | 沿用既有安全门禁和路由行为；该成员不再参与菜单异常汇总，其他异常继续保留 |
| 断连、页面恢复或刷新 | 沿用既有会话生命周期及持久化恢复边界；本设计不承诺自动重连、自动重发或自动继续队列 |

## 5. 实现约束

错误展示应消费实际状态所有者，保留连接、集合和单会话之间的区别。不要创建按错误文字匹配的去重缓存，也不要额外复制一份错误状态来维护红点。

`GuiHostStatus` 不再承载单会话激活失败。移除现有跨层写入前，需要逐项确保集合错误、激活警告及清理错误已有可见归属，不能仅删除顶部卡片条件。

使用 HeroUI v3：异常点参考 `Badge.Anchor` 与 `Badge color="danger" size="sm"`；任务入口和更多操作参考 `ButtonGroup`、`Button`、`Dropdown`；详情区域沿用 `Alert`。使用组件语义与设计 token，具体 API 和交互细节在计划前通过本地文档核验。

没有标题时 UUID 的来源仍是该会话标识，不引入示例头像、外部资源或示例代码中的无关功能。

用户可见文案遵循现有 Lingui 流程。禁止为通过验证放宽断言、删除有效覆盖或新增临时兼容路径。
