# Codex GUI Storybook 真实渲染环境设计

日期：2026-09-13

阶段：设计落盘；尚未进入实施计划或实现。

## 问题陈述

前端已经配置 Storybook 依赖、框架、插件和启动脚本，但预览入口尚未接入应用样式、主题和语言上下文。仅完成工具初始化，还不能保证组件在 Storybook 中呈现与产品一致的效果。

本轮唯一主目标是先打通真实渲染环境。错误反馈组件已经存在并被业务复用；重新提取组件、搬迁目录和建立完整业务展示目录不属于本轮目标。

## 解决方案

为 Storybook 提供基于应用真实样式、主题、语言资源及必要 Provider 的预览环境。复用应用的权威实现，不建立另一套主题解析、翻译目录或业务状态模型。

预览支持 `light`、`dark`、`system` 三种主题偏好，首次打开默认 `system`。使用太阳、月亮、显示器表达浅色、深色、跟随系统，三段式选择始终保留一个选中项。

主题能力可供产品与 Storybook 共用，但产品暂不开放切换入口，继续跟随系统。选择仅在当前页面生命周期内有效，不持久化；刷新或重新打开后恢复 `system`。

6. 作为预览使用者，我希望选中项表达我的主题偏好，以便区分明确选择深色与跟随深色系统。

## 实现决策

### 真实环境边界

- “真实”指复用产品的渲染依赖、资源与主题规则，不代表接入真实后端或加载整个产品运行时。
- 预览加载应用全局样式，保持 Tailwind 与 HeroUI 样式的既有导入顺序。
- 构建侧需要支持应用现有 alias、React、Tailwind 和 Lingui 转换及目录加载；实施时核验 Storybook 对现有 Vite 配置的实际继承结果，不能仅凭框架名称假定已覆盖。
- Provider 相对顺序遵循实际应用入口：主题、Lingui、Redux、Router。Redux 和 Router 按 Story 依赖接入，不为了展示纯组件而挂载整个应用路由树。
- 通过现有 store 工厂创建隔离实例，不复用产品全局 store 单例作为所有 Story 的可变状态容器。
- 需要路由上下文的预览使用隔离路由环境，避免影响 Storybook 自身导航，也不因渲染基础组件自动启动产品连接流程。

### 主题能力与控件

- 扩展现有主题 Provider，使其管理主题偏好和最终显示主题。系统主题仍由现有 `matchMedia` 机制提供。
- `light` 和 `dark` 为显式偏好；`system` 根据系统状态解析成最终深浅色。显式偏好不随系统变化，重新选择 `system` 后使用当前系统状态并继续响应变化。
- 继续使用既有根节点 class 与 `data-theme` 表达最终主题，只保留一套权威应用逻辑。
- 三段式控件读取主题偏好作为选中值。系统为深色且偏好为 `system` 时，显示器仍保持选中。
- 使用 HeroUI `ToggleButtonGroup` 和 `ToggleButton`，单选且禁止空选；图标按钮具备可访问名称、选中语义和键盘操作能力。外观采用组件系统的语义 token。
- 官网截图作为三态交互和外观参考。已核验官网的 `ThemeToggle` 实际使用原生按钮和 `next-themes`，并非 `ToggleButtonGroup`；本项目沿用已有 Provider，不引入 Next.js 或为此引入 `next-themes`。
- 产品不挂载主题选择入口。Storybook 的选择只影响预览环境，不把主题能力扩展为 Storybook 管理界面的换肤需求。
- 不写入 localStorage、sessionStorage 或其他持久存储，也不从持久化的预览参数恢复主题选择。页面刷新和重新打开以 `system` 初始化。

### 语言与状态生命周期

- 复用应用语言解析和目录加载能力，覆盖现有 `en` 与 `zh-CN`，不维护 Storybook 专用翻译副本。
- 在组件首次渲染前完成语言激活，文档语言与实际激活语言一致。
- 本轮不增加产品语言切换入口，也不扩展新的语言偏好产品需求。
- Story 的业务状态实例相互隔离；主题属于当前预览页面的环境偏好，不随业务状态重置而被当成业务数据保存。
- 订阅和 Provider 生命周期应正常清理，避免重挂载后重复响应系统主题变化。

## 测试决策

以下为待实施的验证要求，并非已经运行或通过的结果。优先在 Storybook 渲染入口验证用户可见行为，辅以现有 Browser 测试方式，不为验证而增加生产诊断接口。

- 以最小真实组件预览证明全局样式、HeroUI 样式、语言资源及必要上下文实际生效。该预览只用于环境验收，不扩展为完整错误反馈状态目录。
- 验证三种偏好、选中状态、系统主题变化、显式偏好不被系统变化覆盖，以及恢复跟随系统后的表现。
- 验证刷新或重新打开后恢复 `system`，不能把仅卸载重挂载组件当作刷新证据。
- 验证主题选择的键盘交互和可访问名称，通过 DOM、交互与渲染结果断言外部行为，不断言内部函数组织。
- 复用已有国际化 Browser 测试中“先激活语言再首次渲染”的验证方式，检查英文与简体中文目录及文档语言。
- 参考现有错误反馈 Browser 测试的真实 Provider、窄容器和用户交互方式，验证环境中的实际组件，而不是只检查配置文本。
- 对依赖 Redux 和 Router 的最小预览验证上下文可用、Story 状态隔离以及导航不会替换 Storybook 自身页面。
- 产品回归需证明仍跟随系统、没有新增主题切换入口；共享 Provider 的变化不能只凭 Storybook 结果宣告产品验证完成。
- Level 1 覆盖聚焦自动化回归及 Storybook 环境检查；Level 2 以无头方式检查真实应用中的共享主题行为。Level 3 不适用于本轮，不启动可见桌面窗口。
- 实施阶段按项目规则完成相关类型、lint、格式和 Storybook 构建检查；不得扩大豁免或关闭检查来达成验收。

## 范围外

- 产品主题切换入口及其摆放位置。
- 主题偏好的持久化、跨标签页或跨设备同步。
- 新主题、自定义配色和主题编辑器。
- 错误反馈组件重构、目录迁移、组件规范全面治理和独立组件包发布。
- 完整业务 Story 目录、真实 WebSocket 会话模拟、后端连接和真实消息发送。
- 新增语言和产品语言切换设置。
- Storybook 管理界面换肤、远程发布、远程 issue 更新及依赖安装。
