# 新建会话工作目录展示设计

日期：2026-09-10

状态：已按对话决策整理，待文档审阅；尚未编写实施计划或修改产品代码。

## 问题陈述

新建会话页面目前把“工作目录：完整路径”作为独立灰色段落放在输入框上方。目录是当前草稿的上下文，但视觉上与输入区域缺少明确归属，完整路径也占据了默认界面的注意力。

本次只优化工作目录的展示与完整路径查看方式。用户提供的输入框和 HeroUI Table 图片是视觉参考，不要求完全复刻，也不将参考图中的其他功能纳入范围。

## 解决方案

在输入框顶部设置附属目录信息条，默认只显示文件夹图标和目录末级名称，例如 `codex`。点击该入口后，显示可选中的完整路径，例如 `/Users/jiangsheng/cnb/codex`。不提供复制按钮。

参考 HeroUI Table 的浅色外壳与内容区层级：目录信息条使用较弱的背景层次，下方输入区使用主要内容表面，两部分共用圆角外壳。只借用视觉层级、圆角和留白，不使用表格列线或表格语义。

断连时仍显示目录信息条，允许查看完整路径。此要求不扩展为断连时保留可编辑输入框，也不改变现有发送限制与连接恢复逻辑。

## 用户故事

1. 作为新建会话的用户，我希望默认看到简短目录名，以便快速确认草稿所属目录。
2. 作为用户，我希望目录信息与输入区域形成整体，以便理解输入将在何处创建会话。
3. 作为需要确认目录身份的用户，我希望点击目录名查看完整路径，以便区分末级名称相同的目录。
4. 作为需要取用路径的用户，我希望完整路径可以选中，以便使用系统已有的文本操作。
5. 作为用户，我希望路径查看界面不增加复制等额外控件，以便保持界面简洁。
6. 作为键盘用户，我希望能够聚焦目录入口并展开、关闭路径内容，以便无需鼠标也能查看路径。
7. 作为窄屏用户，我希望长目录名和长路径不会撑宽页面，以便继续正常使用输入区域。
8. 作为深色主题用户，我希望目录信息条保持清晰的层级，以便辨认目录与输入内容。
9. 作为连接中断的用户，我希望目录信息仍然可见，以便确认当前草稿的上下文。
10. 作为切换任务后返回新建会话的用户，我希望目录仍属于原有草稿，以免误认为草稿已跟随其他任务切换目录。

## 实现决策

### 已确认的产品决策

- 默认显示文件夹图标和目录末级名称，不再常驻显示“工作目录：完整路径”。
- 点击后查看完整路径，路径文本可选中，不添加复制按钮。
- 目录入口位于输入框顶部的附属信息条中。
- 目录信息条与输入区域共用圆角外壳，参考 HeroUI Table 的表面层级。
- 断连时保留目录信息。
- 不添加本地环境、分支或其他参考图中的控件。

### 展示与交互

- 使用 HeroUI `Surface` 组织外壳与内容表面；采用 `surface`、`surface-secondary`、`foreground`、`muted`、`separator` 等语义 token，具体映射以本地组件文档为准，不硬编码浅色主题颜色。
- 目录入口使用 HeroUI `Button` 的 `ghost` 语义变体，配合文件夹图标；它是查看上下文的辅助入口，不使用主操作强调。
- 使用 HeroUI `Popover` 承载完整路径，遵循其键盘、焦点和关闭行为；不使用只依赖悬停的提示作为唯一查看方式。
- 完整路径保留原始字符，可换行、可选中。目录名过长时限制入口宽度并截断显示，完整内容通过展开查看。
- 图标作为装饰处理，入口具有表达“工作目录”用途的可访问名称；键盘焦点必须可见。
- 根目录等没有普通末级名称的合法路径，应显示能表达其身份的原路径，不显示空名称。
- 不照搬表格组件。此处不是行列数据，不引入 `Table`、列标题、排序或选择行为。

### 数据与责任边界

- 新建会话页面负责目录信息条的展示与组合。
- 目录数据继续来自新建会话草稿快照的 `cwd`；短名称只是展示派生值，不能回写或替换完整路径。
- 新建会话 owner 继续拥有草稿及其固定目录，不增加第二份目录状态或新的目录选择能力。
- 创建会话仍使用原始完整 `cwd`，不改变请求协议、持久化、创建、发送、失败恢复或任务切换行为。
- 展开状态是局部 UI 状态，不新增后端接口、schema 或持久化字段。
- 输入区只做与共用外壳直接相关的布局适配；编辑器、技能菜单和发送按钮的业务行为保持现有契约。
- 尚无本次原型，不附加未经验证的代码片段。

## 测试决策

优先复用现有新建会话页面的应用级 Browser 测试入口，通过真实菜单进入页面并执行用户操作。现有测试已经覆盖草稿绑定目录、切换任务后返回以及发送时传递完整 `cwd`，不新增测试专用产品接口。

以下为设计提出的验证范围，尚未执行，也不将其标记为用户单独确认的测试计划：

- 默认目录名可见，完整路径通过点击或键盘展开后可见；完整路径可以选中，没有复制按钮。
- 路径展开与关闭不创建会话、不改变草稿内容和目录；创建请求继续收到原始完整 `cwd`。
- 返回草稿后仍显示草稿固定目录；断连时目录入口与完整路径查看仍可用。
- 长名称、长路径和根目录均能表达正确身份；窄屏没有横向溢出，弹出内容不被外壳圆角裁切。
- 复用现有发送、草稿保留和失败状态覆盖，避免为视觉调整削弱原有行为断言。
- 测试用户可见结果与交互，不锁定内部组件拆分、CSS 类名、固定像素值或 DOM 层数。

验收证据分开记录：

- Level 1：应用级 Browser 自动化覆盖目录展示、展开、键盘交互及已有目录契约；当前未执行。
- Level 2：在真实应用无头验收浅色与深色主题、宽窄视口、弹出层定位及文本选择；当前未执行。
- Level 3：本设计不依赖可见桌面状态，默认不适用，不启动可见浏览器窗口。
