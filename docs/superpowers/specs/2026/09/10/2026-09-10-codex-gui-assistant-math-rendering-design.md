# Codex GUI 助手回答数学公式显示设计

> 日期：2026-09-10
> 状态：已接受并进入计划落盘；尚未实现
> 接受依据：用户要求「计划落盘」，并明确「确认」两个任务的拆分及依赖
> 落盘依据：用户在需求访谈后要求使用 `to-spec`「落盘设计」
> 已确认范围：助手回答；实时输出与历史消息；四种公式分隔符；沿用 Streamdown 默认展示行为

## 问题陈述

用户阅读数学解答时，公式中的 LaTeX 命令直接显示为文本，角度、分式、上下标等缺少应有的数学排版。
截图对应的原始助手回答使用反斜杠括号作为公式分隔符；普通 Markdown 解析会消费括号前的转义，
使显示结果只剩括号和裸露命令。

当前 GUI 已声明数学插件依赖，但共享 Markdown 渲染配置只接入代码和 CJK 插件，未接入数学插件和
KaTeX 样式。静态与流式消息共用该配置。仅启用数学插件默认支持的美元语法，也不能覆盖已有回答
使用的反斜杠括号。

## 解决方案

在助手回答的现有 Markdown 展示链路接入 Streamdown 数学插件，使行内公式和块级公式得到正常排版。
同一能力覆盖正在输出的回答、输出完成后的回答及重新打开的历史消息，不要求重新生成旧回答。

支持以下输入约定：

| 写法 | 显示语义 |
| --- | --- |
| `\(…\)` | 行内公式 |
| `\[…\]` | 块级公式 |
| `$…$` | 行内公式，明确开启数学插件的单美元解析 |
| `$$…$$` | 沿用 Streamdown 的上下文语义：正文内可为行内公式，独立公式块为块级公式 |

公式的布局、溢出、字号、错误显示和流式处理沿用 Streamdown、数学插件及 KaTeX 的现成行为。
不新增「公式生成中」占位，不要求所有公式等待真实闭合才渲染，也不额外制定缩放或滚动策略。

## 用户故事

1. 作为阅读助手回答的用户，我希望句子中的公式按行内形式排版，以便连续阅读解释与数学表达。
2. 作为阅读数学解答的用户，我希望独立公式按块级形式展示，以便辨认多步推导。
3. 作为查看历史任务的用户，我希望已有回答中的公式直接显示，以便无需重新请求解答。
4. 作为等待助手输出的用户，我希望公式随消息更新采用渲染器默认行为，以便持续看到已有内容。
5. 作为阅读已完成回答的用户，我希望流式结束后仍能看到正确公式，以便继续阅读完整结果。
6. 作为阅读几何解答的用户，我希望反斜杠括号中的角度、垂直和平行符号正常显示，以便理解推理。
7. 作为阅读代数解答的用户，我希望分式、上下标和常用数学命令正常显示，以便辨认表达式结构。
8. 作为阅读美元分隔公式的用户，我希望单美元与双美元写法按约定解析，以便阅读不同来源的回答。
9. 作为阅读代码示例的用户，我希望代码中的公式写法仍然作为代码显示，以便准确查看原文。
10. 作为阅读普通文字的用户，我希望没有有效公式分隔符的内容继续按原有 Markdown 规则展示。
11. 作为手机上的读者，我希望沿用渲染器现有的公式布局能力，以便与桌面端阅读同一份回答。
12. 作为使用辅助技术的用户，我希望保留数学渲染器提供的语义输出，以便读取数学内容。
13. 作为回看自己输入的用户，我希望用户消息保持现有显示方式，以便本次改动只影响助手回答。

## 实现决策

### 职责与范围

- 助手消息的展示层拥有数学能力选择；当前消息渲染入口仍负责选择静态或流式 Markdown。
- 共用数学配置与必要的语法处理，避免实时回答和历史回答维护不同实现。
- 共享 Markdown 组件还被已完成思考内容等消费者使用。能力接入必须区分消费者，不能仅全局启用
  就使这些内容自动进入本次范围。用户消息、思考内容和工具输出维持现有行为。
- 保留现有 transcript 的分块边界、稳定消息身份和增量更新方式，不为公式拼接整个回合的消息。

### 数学解析与语法补足

- 使用现有 `@streamdown/math`，开启 `singleDollarTextMath`；数学排版继续由 KaTeX 负责。
- 在普通 Markdown 消费转义之前识别反斜杠括号，将其接入同一数学解析路径，保留行内与块级区别。
  这是现有插件缺失的语法支持，不另建数学排版引擎。
- 该处理必须理解 Markdown 的代码与转义边界，不能对整段文本无条件替换括号，也不能在已丢失
  转义信息的普通括号上猜测公式。代码围栏、行内代码、链接目标及明确转义的字面量不应被改写。
- 只处理展示输入；原始消息文本仍是权威来源。不得回写消息、持久化转换结果或修改发送给模型的内容。
- 不引入协议、schema、后端 API 或 transcript 状态模型变更；继续使用现有权威消息类型与派生视图。
- 单美元解析遵循依赖的规则，接受其与金额文本存在歧义的边界；不承诺自动区分所有货币表达，
  不新增自定义金额猜测规则。

### 默认流式行为

- Streamdown 的流式模式默认启用不完整 Markdown 处理，静态模式不走这项流式预处理。
- `remend` 默认会临时补齐未闭合的双美元分隔符，并尝试渲染已有内容；这不保证不完整的 LaTeX
  命令一定能成功排版。
- 单美元公式解析与单美元自动补齐是两个独立开关。本设计只开启前者，`inlineKatex` 保持默认关闭。
- 反斜杠括号没有内置补齐处理。本次语法补足不额外定义未闭合反斜杠公式的自动补齐规则；
  接入统一数学输入后，展示仍使用既有静态与流式路径，不建立额外的 pending 状态或完成屏障。
- 临时补齐不修改原始消息。输出结束、停止或失败后，继续服从既有消息生命周期与渲染模式切换。

### 样式与安全

- 接入数学插件要求的 KaTeX 样式与项目样式构建扫描，确保数学 DOM 有对应字体与排版样式。
- 继续使用现有 HeroUI 消息 `Card`、布局和语义 token，不新增交互组件、公式专用卡片或设计系统。
  公式内部使用 Streamdown/KaTeX 生成的语义标记，因为它们承担数学排版和可访问性职责。
- 保留现有 Markdown 清理、链接保护、图片限制和复制控件行为，不为了公式放宽安全检查。
- 不定制公式错误面板、错误颜色或静默隐藏失败内容；沿用依赖默认处理。
- 不安装或升级依赖，不修改作为参考的 Streamdown 源码仓库。

## 测试决策

优先使用现有消息展示入口作为最高的共同验证边界，向其提供合法消息视图并观察真实渲染结果。
复用项目已有的静态/流式 Markdown Browser Mode 测试惯例，以及现有 transcript fixture 和 builder。
不为了测试新增业务接口；仅当代码与转义边界无法通过该入口清晰定位时，补充少量语法处理单元测试。

测试关注用户可见结果与不变约束，不断言内部函数顺序、临时字符串实现或大段依赖生成的 DOM 快照。
依赖已覆盖的算法不在本项目重复穷举；集成测试验证本项目确实保留其默认行为。

| 场景 | 验证结果 |
| --- | --- |
| 四种分隔符与中英文混排 | 行内/块级符合输入约定，产生实际数学语义输出，不能仅以源码消失判定成功 |
| 真实回答的最小几何、代数例子 | 角度、分式、上下标等常用表达正确渲染；不复制私人聊天全文作为 fixture |
| 分隔符跨增量到达、静态/流式切换 | 累积消息内容完整，闭合后公式正确，不引入独立占位或额外等待机制 |
| 未闭合双美元与单美元 | 双美元保留默认临时补齐；单美元自动补齐未被顺带开启 |
| 不完整或无效 LaTeX | 消息其余部分仍可阅读，错误处理服从依赖默认行为 |
| 代码、转义字面量、链接与普通文字 | 不被反斜杠语法处理误转换，现有 Markdown 行为保持 |
| 用户消息、思考内容及工具内容 | 数学能力没有通过共享组件扩散至范围外消费者 |
| 已有 Markdown 功能 | 代码、表格、链接保护与复制控件没有回归 |
| 窄屏、长公式、字体和可访问性 | 样式真实生效，保留依赖默认布局及数学语义，不用新展示策略掩盖集成缺陷 |

验证等级分别记录：

- **Level 1：适用，未执行。** 使用项目现有无头 Browser Mode 验证上述消息展示契约，结合适用的
  类型、lint 与格式检查；后续计划确定实际命令及目标。
- **Level 2：适用，未执行。** 使用当前真实 Codex runtime 的完整 GUI URL，无头核验历史回答、实时
  输出及结束后的显示，以及桌面和窄屏样式。没有真实流式场景时必须单列缺口，不以静态 fixture 代替。
- **Level 3：不适用。** 当前结果不依赖操作系统窗口、IME 或跨应用焦点，无需打开可见桌面窗口。

## 范围外

- 思考内容、工具输出、文件预览等其他展示面的公式能力扩展。
- TUI 数学支持、后端改造、历史消息迁移或模型提示词调整。
- 完整 LaTeX 文档编译、超出 KaTeX 能力的命令实现、公式求解与正确性校验。
- 自定义流式占位、等待闭合策略、公式缩放策略、滚动策略或金额语义识别器。
- 本轮实施计划、生产代码修改、Git 提交以及外部 issue 发布。

## 补充说明

本设计依据用户重新开始后的决策：范围选 A；公式语法选 B；流式展示选择「用插件默认行为」；
用户随后明确要求展示细节交由 Streamdown 处理。被撤回的占位、等待闭合、缩放与滚动选项不是需求。

已核查本地 Streamdown 可读源码中声明的版本为 Streamdown 2.6.0、数学插件 1.0.2、remend 1.3.1，
与当前项目已安装包的声明版本一致；版本号相同不等同于已证明源码与安装产物逐字节一致。

这是语法覆盖的本地样本证据，不是对所有模型输出频率的保证；单美元支持来自用户明确选择。
