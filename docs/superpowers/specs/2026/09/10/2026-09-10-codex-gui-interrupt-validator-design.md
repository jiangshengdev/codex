# Codex GUI interrupt 权威契约校验设计

日期：2026-09-10

关联问题：QR-B09-003。

状态：用户已确认主目标，审阅设计摘要后要求设计落盘；本文仅记录设计，尚未编制实施计划或修改产品代码。

## 问题陈述

GUI 恢复持久化中断记录时，将 interrupt 的 `turnId` 改名为 `expectedTurnId`，补上 `input: []`，借用 `validateV2TurnSteerParams` 检查，再转换回中断参数。

当前相关字段要求兼容，没有证据表明这已经导致中断失败。问题属于可维护性问题：steer 协议变化可能影响正常中断记录的恢复，而 interrupt 自身约束变化可能未被借用的校验器捕获。

## 解决方案

让中断记录直接按 interrupt 自己的权威协议校验。合法记录继续正常恢复，非法记录继续报错，既有中断和恢复行为保持不变。

复用现有 GUI 协议生成机制，生成并使用 `validateV2TurnInterruptParams`，解除中断恢复对 steer 校验规则的依赖。

## 用户故事

1. 作为 GUI 用户，我希望合法中断记录在刷新后仍能恢复，以便继续处理原来的任务。
2. 作为 GUI 用户，我希望无效记录被拒绝，以免错误目标进入恢复状态。
3. 作为 GUI 用户，我希望恢复失败不覆盖当前有效状态，以便保留已有任务信息。
4. 作为 GUI 用户，我希望刷新时尚在发送的中断继续被视为交付未知，以免系统误判请求结果。
5. 作为 GUI 用户，我希望恢复时不会自动重复中断或发送排队消息，以便保持现有恢复控制。
6. 作为 GUI 用户，我希望已有记录中的额外字段仍被接受并丢弃，以免本次内部修正改变兼容行为。
7. 作为维护者，我希望中断参数按自身协议检查，以免 steer 独立演进影响中断恢复。
8. 作为维护者，我希望校验器机械派生自权威协议，以免手写规则与协议逐渐不一致。
9. 作为维护者，我希望影响消费者的不兼容协议变化能够暴露于生成或类型检查，以便及时修正真实契约冲突。

## 实现决策

- 权威来源是 Rust 的 `TurnInterruptParams`。它已派生 JSON Schema 和 TypeScript 定义；本次不修改 Rust、后端协议或已有权威 schema。
- 派生路径为：Rust 协议定义 → 已有协议 schema 与 TypeScript 产物 → GUI 辅助 schema 选择清单 → 现有协议生成器 → 专属运行时校验器及类型声明 → interrupt 持久化解码器。
- 在 `APP_SERVER_AUXILIARY_SCHEMA_IDS` 中加入 `v2/TurnInterruptParams`，通过现有生成入口更新产物。无需新增生成框架或手改生成文件。
- 解码器直接调用专属校验器，删除改名为 `expectedTurnId` 和补充 `input: []` 的转换。
- 校验成功后，从已收窄为权威协议类型的数据复制中断字段，并以 `Readonly<TurnInterruptParams>` 约束返回值，保持现有额外字段丢弃行为。该复制不承担协议校验，不新增手写 schema、字段校验表或独立 DTO。
- 当前权威 schema 要求 `threadId` 和 `turnId` 为字符串，没有新增非空、格式或额外字段禁止要求；本次不收紧这些条件。
- `pending.params`、非空 `pending.terminal` 和 `recentTerminals` 的每个目标都经同一参数解码入口检查。
- phase 合法性、pending 与 terminal 目标一致性、跨线程检查仍由既有领域逻辑负责。
- 保持完整解码成功后才采用候选状态；恢复时 `issuing` 变为 `unknown`，保留 `accepted`、`unknown` 及既有暂停和恢复语义。
- 不使用类型强转、静默 fallback 或消费者手写协议镜像掩盖不兼容变化。无关 steer 校验器继续服务原消费者。

## 测试决策

优先复用持久化解码、状态恢复和 coordinator 恢复入口；测试可观察结果，不断言局部变量、代码拼装顺序等实现细节。不新增测试专用生产接口。

- 通过既有持久化入口覆盖三处中断参数的合法恢复，以及必需字段缺失、字段类型错误时的拒绝。
- 覆盖额外字段被接受但不进入解码结果，保持原有归一化行为。
- 覆盖非法 phase、terminal 目标不一致以及恢复失败不覆盖已有状态。
- 复用现有 lane persistence 和 interrupt snapshot persistence 回归，验证 `issuing → unknown`、旧 claim 失效、恢复暂停、无自动发送及无重复中断。
- 沿用现有协议产物一致性检查和 TypeScript 检查，确认专属校验器及其类型声明由权威输入生成。通过依赖审查确认 interrupt 解码器不再消费 steer 校验器，不为证明这一点修改真实 steer schema。
- Level 1：适用，实施时运行相关自动化回归与契约检查；本次尚未执行。
- Level 2：本次仅影响内部持久化校验，无新增页面或交互行为，不要求真实 GUI 浏览器验收。
- Level 3：不适用，无可见桌面或系统交互要求。

## 补充说明

TUI 直接构造权威 `TurnInterruptParams`，由 Rust 类型与协议反序列化约束数据结构，服务端另行检查活动 turn。GUI 从持久化数据恢复的边界仍需要运行时校验；借鉴的是使用自身契约的原则，不是删除 GUI 的恢复检查。

本设计根据当前源码与已有测试的只读核对形成；测试存在不等于本次已经验证通过。
