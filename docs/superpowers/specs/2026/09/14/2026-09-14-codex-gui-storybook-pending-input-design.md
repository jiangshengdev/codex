# Codex GUI Storybook 待发送队列业务场景设计

日期：2026-09-14

状态：设计已落盘，待审阅；未进入实施计划或实现。

## 问题陈述

开发者目前可以在 Storybook 查看连接恢复的固定状态和本地交互演示，但不能直接查看和操作待发送队列的完整业务场景。实际使用中，队列同时受到发送进度、引导结果、编辑占用和恢复流程影响，部分中间状态难以稳定触发和停留，单独查看一个按钮或列表不足以检查完整反馈。

本次唯一目标是在 Storybook 中提供待发送队列的状态展示与可操作流程，覆盖抽屉管理和抽屉外的异常、优先发送及未发送恢复反馈。所有模拟在本地运行，不发送真实消息；发送状态由使用者手动推进。

## 解决方案

沿用现有 Storybook 的状态展示与交互演示组织方式，挂载真实队列业务组件和编辑器。提供可直接打开的典型状态，以及能够反复操作、手动推进并重置的业务流程。

产品区域保留现有文案、层级、按钮、限制和反馈。Story 的模拟控制区域单独标识，用于触发发送结果、外部状态变化和重新开始；不得把这些演示控件加入产品 UI。

编辑、删除、排序等直接操作即时反馈。涉及模拟发送的操作进入等待状态后保持不变，直到使用者明确推进。成功、失败和状态未知都采用确定输入，不依赖随机结果、自动倒计时或真实网络。

### 状态展示范围

| 场景 | 需要可直接检查的结果 |
| --- | --- |
| 空队列 | 队列区域按产品条件隐藏；已打开的抽屉在最后一条移除后展示空态，不新增空队列入口 |
| 普通排队与引导队列 | 数量、双通道列表、短消息与长消息预览、展开与收起 |
| 多页队列 | 两个通道各自的加载更多、数量与完整列表 |
| 正在编辑 | 真实编辑器、取消和保存、空内容限制、管理动作的现有限制 |
| 正在发送或不可管理 | 对应说明与动作限制；可读范围遵循当前产品行为 |
| 引导状态未知 | 队列区域中的未知反馈与相应管理限制 |
| 引导失败后优先发送 | 优先发送消息预览、数量及已加入队列的反馈 |
| 未发送恢复 | 未发送数量、继续发送可用或不可用、恢复进行中 |
| 编辑与队列变化冲突 | 目标已进入发送、目标 turn 关闭或会话失效时的现有反馈与编辑保留 |
| 排序与刷新失败 | 排序未生效、排序已生效但更新后顺序无法加载的不同反馈 |
| 完整队列组合 | 展示能够合法共存的队列区域与抽屉内容；不为拼满一屏制造不可能的组合 |

状态展示提供独立起点；互斥状态分别展示。不得将所有标志任意组合后称为真实业务状态。

### 交互流程范围

| 流程 | 操作与可见结果 |
| --- | --- |
| 查看队列 | 从真实入口打开抽屉，分别加载两组消息，展开长消息，关闭后焦点返回 |
| 编辑 | 打开消息、修改、保存后更新预览；取消后保留原消息；不覆盖主输入草稿 |
| 删除 | 发起删除后可保留或确认；确认后更新消息和数量，删除最后一条后显示空态 |
| 排序 | 上移、下移、置首、置尾后顺序即时变化，边界动作符合真实限制 |
| 普通发送推进 | 手动推进模拟请求结果和必要的运行时事件，队列数量与管理状态按现有业务规则更新 |
| 引导结果 | 分别演示成功、明确失败后进入优先发送、状态未知；未知不能冒充明确失败或自动重发 |
| 恢复发送 | 点击继续发送后保持恢复中；手动触发结果，成功和再次失败后的可见状态遵循产品逻辑 |
| 操作期间状态变化 | 手动触发消息进入发送、目标 turn 关闭或会话失效，检查编辑保留和操作反馈 |
| 无法保存后的处理 | 查看保留内容、复制内容及其成功或失败反馈；放弃前确认，可返回编辑 |
| 排序异常 | 明确区分未移动与已移动但刷新失败，展示现有后续处理，不将失败伪装为成功 |
| 重新开始 | 恢复当前场景的初始内容、队列状态与待处理操作，不继承上一轮结果 |

## 实现决策

### 真实组件与模拟边界

- 使用现有 `ComposerPendingInputRegion`、`ComposerPendingInputProvider`、`ComposerPendingInputDrawer`、`ComposerPendingInputList` 及真实编辑器形成业务组合。需要主输入上下文的流程复用 `ComposerTurnControl`，不复制队列展示 JSX、文案或管理交互。
- 复用 `ComposerPendingInputSession` 的抽屉应用状态与现有 host 绑定生命周期，保持编辑、确认、焦点和反馈由现有 owner 负责。
- 正常交互通过真实 `ComposerInputQueueCoordinator` 及其既有操作推进队列；使用它现有的发送回调和存储注入入口控制外部结果。不另写一份编辑、删除、排序或恢复状态机作为交互 Story 的权威来源。
- Story 装配负责模拟会话上下文、初始输入、待处理的外部结果和控制面板。固定状态与难触发失败可使用遵循现有接口的有界场景替身；明确其展示用途，不把注入结果当作生产队列算法已验证的证据。
- 既有 Browser 测试中的队列 harness、会话 harness 和失败样例作为行为先例。不得直接把依赖 `vi` 的测试运行器设施带入 Storybook 浏览器运行时。
- 复用现有 Storybook 样式、主题与 Lingui 环境；按实际依赖使用已有隔离的状态环境，不挂载真实业务连接入口。

### 权威契约与数据

- 队列快照、消息、分页、编辑和排序结果以现有 `ComposerInputQueueCoordinator`、`composerInputQueueContracts` 与会话角色契约为权威来源。场景类型直接引用或机械派生，不维护重复字段清单和状态联合。
- 涉及协议响应和投影事件时，直接使用现有协议类型与共享合法投影构造设施，保留类型错误的传播；不以断言、宽泛对象或静默 fallback 掩盖契约变化。
- 使用固定的虚构消息与场景身份。长内容、多条消息等数据为相应展示目标服务，不加载真实聊天、文件或凭据。
- 注入每个 Story 独立的内存存储，不读写产品的持久会话记录。队列计数、列表、编辑占用和排序能力来自同一场景的权威状态，不能各自手动维护而失去一致性。

### 手动推进与隔离

- 产品操作与模拟控制明确区分。编辑、删除、排序即时调用真实操作；模拟发送、引导和恢复的外部结果通过独立控制区推进。
- 控件仅在对应操作待处理且结果合法时可用，不能在空闲时注入一个无所属请求的成功或失败。
- 请求成功响应与消息被运行时确认不视为同一事件。需要投影事件才能完成的状态，按产品现有语义手动推进相应事件；不得收到成功响应就强行移除消息。
- 未知结果保留未知语义，不新增自动重发、额外兜底或产品恢复策略。
- 每个 Story 独立创建和释放模拟会话、队列、订阅与内存存储。重置和切换使旧待处理结果失效；旧操作不能修改新场景。
- 允许一个完整组合场景帮助整体检查，同时保留独立场景以定位具体反馈，不改变产品中状态能否共存的规则。

### 展示约束

- 保留真实 HeroUI 组件、变体与语义 token，不通过 Story 单独改写产品外观。
- 模拟控制优先复用 HeroUI 现有按钮等组件，与产品区域在视觉和可访问名称上明确区分。
- 主题、语言与容器尺寸复用 Storybook 既有能力，不把所有组合机械扩展为独立业务场景。
- 不新增协议、schema、后端 API 或产品配置。若后续发现必须改变产品行为或公共接口，应先说明影响并重新确认范围。

## 测试决策

- 主要测试接缝是 Storybook 中挂载的完整队列业务组合：从可见入口、模拟控制和用户操作进入，以文案、数量、列表内容、动作可用性、编辑内容和焦点等外部结果断言。
- 复用现有 Storybook E2E 入口与浏览器覆盖方式。现有连接恢复交互测试提供重置、Story 切换和业务连接隔离的先例；现有队列 Browser 测试提供编辑、删除、排序、分页与状态变化的行为先例。
- 验证代表性固定状态可直接打开，并验证交互矩阵中的成功、失败、恢复和取消路径。断言实际展示与结果，不测试私有字段、内部调用次数或场景数据的自我复制。
- 明确验证发送中间状态不会自行结束，必须使用手动控件推进；管理操作不需要额外的模拟完成按钮。
- 验证数量和列表一致、编辑不覆盖主草稿、边界排序限制、不可管理消息以及失败后的内容保留。
- 验证复制成功和失败反馈时使用现有剪贴板测试边界；复制行为确实属于产品操作，不能把按钮点击记录当作复制成功。
- 验证等待期间重置、切换 Story 和重复进入后均回到正确初态，旧结果无法污染当前场景。
- 验证没有真实业务 WebSocket 或消息请求，且不访问产品持久会话记录；Storybook 自身开发连接不算业务连接。
- 对抽屉、编辑区和确认界面检查键盘操作、焦点返回、长内容滚动及窄容器溢出。语言和主题选择代表性组合，不以截图基线替代业务断言。
- Level 1 适用：受影响的 Storybook 无头自动化，以及实施时实际变更所需的类型、lint 和前端构建检查。仅在产品接缝确有变化时补跑对应现有队列测试。
- Level 2 对限定的 Story 新增不适用：不声称完成真实消息发送、引导或恢复验收。若后续改变产品交互或运行时行为，重新评估真实应用验收范围。
- Level 3 不适用：设计不依赖可见桌面或系统窗口行为，自动化默认无头运行。
- 本轮仅完成源码核验与设计落盘，尚未运行上述验证。测试接缝与其余设计内容一起供用户审阅，不另造实现细节选择题。

## 范围之外

- 重新设计队列 UI，修改发送顺序、恢复策略、容量、未知投递处理或管理限制。
- 真实后端连接、真实消息发送、真实会话读取与持久化迁移。
- 完整聊天页、历史记录、连接恢复等其他业务目录的扩展。
- 自动定时推进、随机故障、后台持续模拟或可见桌面验收。
- 为场景展示新增产品调试入口、日志埋点或临时兼容路径。
- 升级或安装依赖，修改运行器，以及发布外部 issue。
