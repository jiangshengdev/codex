# Storybook 演示内容与生产产物隔离设计

日期：2026-09-14

状态：按重新对齐并确认的范围落盘，尚未实施。

本版为当前有效设计。错误旧版已按用户要求删除；本版完整定义有效边界，不继承旧版中的技术结论。

## 问题陈述

维护者希望减少 Storybook 演示内容对生产发布包的影响，同时保持生产能力和现有检查完整。

当前产品入口没有引用 Storybook 场景逻辑，但演示消息与产品共用 Lingui catalog，生产运行时加载完整语言资源。Tailwind 的源码扫描也没有明确划分演示输入与产品输入。因此，JS 入口隔离不能单独证明演示文案和样式已经隔离。CSS 的实际增量尚未测量。

用户明确选择产物隔离：生产构建继续检查 Storybook 类型，类型错误仍应阻塞构建。此次不隔离构建检查流程。

## 解决方案

只隔离为演示创建的场景、虚构数据、模拟控制及其专用资源，使这些内容不进入生产 JS、语言包和 CSS。Storybook 保留现有场景、交互、本地化与主题展示。

生产组件及配套资源继续归产品。主题切换控件是生产能力，其实现、文案、样式及相关主题能力不得移入 Storybook，不得因目前主要或仅由 Storybook 使用而清理。

归属由能力职责及用户确认的产品边界决定。引用关系用于检查打包可达性和影响面，不能决定能力归属。目录排除必须实现已经确认的边界，不能反过来定义边界。归属不明的内容先查证，不纳入专用资源清理。

## 实现决策

### 能力与资源边界

- 演示边界包含 Story 定义、演示装配、虚构 fixture、模拟推进控件、演示说明及这些内容专用的资源。
- 产品边界包含生产组件及其配套消息、样式和能力；ThemePreferenceControl、ThemeProvider 和主题偏好能力属于产品。不得移动、复制到预览侧或以此次隔离为由删除。
- 一个产品资源被演示使用，不会因此变成演示资源。一个资源同时服务产品和演示时，继续保留产品权威来源。
- 不以当前生产入口可达性实施通用死代码清理。正常 bundler tree shaking 继续生效，但不为强制展示隔离收益而删除生产源码或人为改变生产入口。

### JS 与类型检查

- 保持生产入口和 Storybook 入口分离，防止产品反向引用演示场景、模拟控制或专用资源。
- 保持现有 TypeScript 检查范围、项目引用和 noEmit 语义。Story 与预览入口仍参与生产构建前的检查。
- 不用依赖所属 dependencies 或 devDependencies 分类代替实际打包图证据。

### 语言资源

- 通过 Lingui 提取与加载边界分离演示专用消息。产品运行时只加载产品 catalog，Storybook 获得产品消息和演示消息。
- 主题切换控件及其他生产组件的消息继续属于产品 catalog，即使当前只在预览中显示。
- 只迁移能明确回指演示内容的专用消息；共享消息沿用产品权威翻译，不形成两套独立维护的共享翻译。
- 消息 identity、placeholder 和 ICU 结构沿用 Lingui，不人工镜像契约。生成机制消费明确的归属边界，不从调用次数推导消息归属。
- 保留现有中英文有效翻译和 translator context。迁移产生的 catalog 及 obsolete 变化纳入完整 diff 审查，禁止顺便清理无关历史消息。
- 沿用项目提取入口，生成输出集合及共享消息处理机制在计划前核验。重复提取必须稳定，不以运行时静默回退掩盖缺失翻译。

### CSS

- 为生产与 Storybook 明确各自的 Tailwind 扫描输入，排除已确认属于演示的专用输入，保留生产组件源码的扫描覆盖。
- 产品组件的样式，包括主题切换控件样式，不因当前调用位置而排除。共享 utility 的存在不构成演示泄漏。
- Storybook 继续消费真实产品样式、HeroUI token 和必要依赖样式，并生成演示所需的额外规则。不能复制产品 CSS 形成独立维护版本。
- 从源码扫描边界处理专用 utility，不在生成 CSS 上做字符串删除或选择器黑名单。排除规则不能导致 Storybook 自身丢失样式。

### 产品行为

- 保持现有产品和演示行为，不改变主题切换控件的生产归属，也不在此次任务中新增或移除其产品入口。
- 不改变协议、队列算法、消息发送策略、用户数据模型、组件接口或设计系统。

## 测试决策

主要接缝是实际生产构建与独立 Storybook 构建的产物边界；复用现有本地化、主题、真实渲染与业务场景浏览器测试作为正向保护。测试关注外部结果，不锁定内部文件组织。

1. JS 隔离：检查构建模块信息与产物，确认演示场景、虚构 fixture、模拟控制不在生产依赖图中。不能仅按文件名是否含 Storybook 判断。
2. 消息隔离：在生产语言资源中检查明确属于演示的消息缺席，同时确认产品消息仍保留，特别覆盖主题切换控件。验证 Storybook 中两类消息均正确显示。
3. CSS 隔离：检查演示专用 utility 在生产构建缺席、在 Storybook 存在；同时验证生产组件所需规则仍生成。相同 utility 被产品使用时不能要求删除。
4. 归属保护：审查主题切换控件及其他生产能力未迁入预览边界，产品 catalog 和样式扫描没有按当前引用关系缩减。不能要求把当前不可达的所有产品模块强行打进 JS 来证明保留。
5. 生成闭环：检查完整 catalog diff、有效翻译与消息状态，重复提取后稳定，共享消息无翻译分叉。
6. 演示回归：复用现有主题、真实渲染、ConnectionRecovery 和待发送队列 E2E，覆盖中英文、主题切换及代表性操作，确认真实 Provider 和 CSS 环境保持完整。
7. 产品回归：运行受影响的本地化和主题测试，验证产品组件及配套资源的可用性；必要的生产预览检查消费实际构建结果。
8. 检查能力：运行现有类型检查并核验 Story 与预览入口仍被收集，不缩减检查范围、不忽略错误。
9. 结果量化：记录相同工具和业务源码条件下隔离前后的产物及大小。无预设节省比例，总字节变化不能替代隔离与产品保护断言。

优先使用现有构建和浏览器测试入口。确需增加隔离回归时，在构建边界增加最小检查，不向产品添加探针或调试逻辑。

Level 1 适用，构建检查和自动化浏览器验收采用无头模式。本设计未改变真实运行时交互或桌面状态，Level 2、Level 3 当前不适用；若后续技术调查发现这类影响，须先重新评估范围与验收。

## 不在范围内

- 将主题切换控件或其他生产能力移入 Storybook。
- 根据当前调用者数量清理生产能力、文案或样式。
- 将 Storybook 类型检查从生产构建中拆出。
- 删除演示、取消本地化、减弱主题支持或复制产品组件。
- 泛化的死代码优化、测试资源清理、依赖安装或框架迁移。
- 后端变更、远程 issue 发布、Git 远程操作或部署。
