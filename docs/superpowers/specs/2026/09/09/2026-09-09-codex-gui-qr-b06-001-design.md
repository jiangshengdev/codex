# QR-B06-001：中途订阅协作活动的展示与完成事件去重设计

日期：2026-09-09  
阶段：设计落盘，尚未进入实施计划或实现。  
关联发现：QR-B06-001（P2）。

## 问题陈述

用户中途打开正在执行的会话时，如果 `wait` 或 `resumeAgent` 已开始但尚未结束，快照会包含对应的 `inProgress` 协作条目。当前界面按已完成条目的规则处理快照，不显示这条进行中的活动；之后真实完成事件又因相同 item ID 已在快照中而被当作重复事件忽略。

用户因而看不到这次活动及其完成结果，直至再次订阅取得完成后的快照。当前证据支持前端活动记录缺失，不支持后台协作执行失败或对话正文丢失的结论。

根因是把“快照包含该活动”当成“快照已经覆盖该活动的完成结果”，同时快照恢复没有采用现有进行中活动的展示规则。

## 解决方案

唯一主目标：让中途打开会话后，协作活动的后续完成结果正常显示，同时保留对真正重复事件的去重能力。

用户已选择方案 A：中途打开时立即显示进行中的协作活动，完成后更新原记录，与持续订阅时保持一致。

快照中的 `wait`、`resumeAgent` 按实际生命周期状态恢复展示。已有进行中活动收到有效完成通知后原位更新，显示真实成功或失败状态；真正被快照覆盖的重复通知不产生额外记录。

## 用户故事

1. 作为中途打开会话的用户，我希望看到正在等待子代理的活动，以便知道助手仍在等待结果。
2. 作为中途打开会话的用户，我希望看到正在恢复子代理的活动，以便理解当前执行状态。
3. 作为持续查看会话的用户，我希望进行中的活动完成后更新原记录，以便连续理解同一次操作。
4. 作为用户，我希望中途进入与持续停留能得到一致的活动完成结果，以免进入时机造成信息缺失。
5. 作为用户，我希望活动失败时保留真实失败状态，以免把失败误认为仍在运行或没有发生。
6. 作为用户，我希望重复的完成通知不会增加相同记录，以免误以为操作执行了多次。
7. 作为重新打开已完成会话的用户，我希望快照已包含的活动不会因重复通知再次出现。
8. 作为切换会话的用户，我希望活动更新只影响所属会话，以免其他会话的结果混入当前记录。

## 实现决策

- 修改边界为前端的 ActiveThreadProjection 快照重放分类，以及 transcript 快照恢复与协作条目投影。后端执行语义和协议保持不变。
- 去重分别判断活动开始与完成是否被快照覆盖。item ID 已存在只能证明活动已出现，不能单独证明完成事件重复；快照仍为 `inProgress` 的活动必须允许后续有效完成更新。
- 重放索引表达快照实际覆盖的信息，不成为另一份运行时活动状态。实时事件的连续性和重复处理仍由现有 ingress、提交去重与同一条目更新机制承担。
- 协作条目的进行中快照复用现有 started 展示规则，完成快照复用现有 completed 展示规则。`wait` 显示等待状态；`resumeAgent` 继续遵循已有 receiver 条件。其他协作工具的进行中展示不因本次修复扩大。
- 同一活动沿用既有条目身份与原位更新路径，完成后不新增第二份记录，也不移动到另一条无关活动的位置。
- 权威契约来自后端 projection 协议及其生成的 `@codex-protocol/v2` 类型。使用现有 `Turn`、item 与 notification 契约或机械派生类型，不手写协议副本、状态枚举或猜测性兼容层；保持编译期穷尽检查。
- 保留 thread、subscription、instance 隔离、提交链连续性、分页归属，以及未变化 chunk 的引用稳定性。
- 复用已有协作活动组件与文案，不新增控件、样式、翻译或用户操作。

## 测试决策

测试以用户可观察的活动状态、结果和记录数量为准，不锁定内部索引的数据结构。优先使用现有生产入口与共享 projection fixtures/builders，不新增仅供测试使用的生产接口。

主要回归边界采用“真实 ActiveThreadProjection 接受快照与事件 → read-model 应用事实 → transcript selector 输出”。这条边界同时覆盖错误分类和展示消费者，避免在测试中直接指定 `snapshotDuplicate` 后声称已经证明分类正确。

已有 ActiveThreadProjection 测试可作为合法事件输入与快照重复场景的先例；transcript replay dedup 测试可作为 read-model 和 selector 断言的先例；协作条目策略与 committed activity 测试提供进行中展示和原位结算的既有行为参照。具体测试组织及执行命令留待实施计划确定。

验收场景：

- 分别覆盖 `wait`、`resumeAgent` 的“开始 → attach 时快照为 inProgress → 完成”：attach 后显示进行中活动，完成后只有一份完成记录。
- 对照持续订阅路径，验证相同活动的最终状态与结果一致。
- 覆盖失败完成状态，确认不会被吞掉，也不会继续显示进行中。
- 覆盖重复完成通知，确认不会重复插入。
- 覆盖已完成快照后的重复开始与完成通知，确认不会倒退为进行中或新增记录。
- 保持既有会话隔离、分页与去重约束的检查能力，不通过删除覆盖或放宽断言通过验证。

验证等级：Level 1 为上述自动化回归；Level 2 为当前真实 Codex runtime 下的无头中途进入与完成更新验收；本设计不涉及依赖可见桌面的行为，Level 3 不适用。所有验证目前均未执行，后续不得用静态检查或 Level 1 通过替代 Level 2 结论。
