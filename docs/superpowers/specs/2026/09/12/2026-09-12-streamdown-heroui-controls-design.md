# Streamdown 操作控件采用 HeroUI 设计规格

日期：2026-09-12

状态：依据本次对话的最终范围落盘设计；尚未编写实施计划或修改产品代码。

## 问题陈述

Codex GUI 的 Markdown 正文由 Streamdown 渲染。代码复制、表格复制菜单和全屏操作虽然已经接入 HeroUI 的局部样式，但交互仍由 Streamdown 的原生按钮、自定义菜单和弹层管理，尚未采用 HeroUI React 组件。

HeroUI 采用审计记录了表格菜单方向键与 Escape 行为缺失，以及全屏焦点移入、圈定和恢复方面的问题。这些属于 Streamdown 自定义交互实现的边界。应用还存在独立的复制能力判断错误：代码复制使用 clipboard.writeText，表格复制使用 clipboard.write 和 ClipboardItem，但当前应用仅用 writeText 是否存在决定两类复制入口是否显示，也没有接入表格复制失败反馈。因此用户可能看到复制入口，执行后却没有结果或解释。

用户最终明确要求移除代码块和表格的下载功能。本规格不再保留下载按钮，也不再解决下载文件名或语言扩展名映射问题。

## 解决方案

在应用现有 Streamdown 局部替换接口上采用 HeroUI 控件：代码块只保留复制按钮；普通表格保留复制菜单和全屏入口；全屏表格保留复制菜单和关闭入口。以上所有位置均不提供下载入口。

表格复制继续提供 Markdown、CSV、TSV 三种格式。每次复制同时写入所选格式的纯文本和 HTML 表格，由粘贴目标选择支持的表示。保留的是结构化表格粘贴能力，不承诺粘贴目标复现原页面的视觉样式。

代码和表格分别检查各自需要的剪贴板 API。API 缺失时隐藏对应复制入口；API 存在但写入被拒绝时，明确反馈失败并允许再次操作。仅支持 writeText 的环境仍可复制代码，表格复制不可用，也不以纯文本降级替代已选定的表格复制语义。

Markdown 正文、代码高亮、数学与链接处理、滚动边界及 transcript chunk 性能边界继续保持。Streamdown 负责内容渲染，HeroUI 负责本次范围内的操作控件与弹层交互。

## 用户故事

1. 作为对话阅读者，我希望代码块提供统一的复制按钮，以便快速复制代码。
2. 作为代码使用者，我希望复制得到完整原始代码，以免显示层处理丢失换行或内容。
3. 作为对话阅读者，我希望代码块不再显示下载按钮，以便操作区只保留需要的功能。
4. 作为表格使用者，我希望能够选择 Markdown、CSV 或 TSV 复制，以便用于不同文本工具。
5. 作为富文本编辑器使用者，我希望复制时保留 HTML 表格表示，以便目标编辑器能够粘贴行列结构。
6. 作为文本编辑器使用者，我希望同一次复制也包含所选格式的纯文本，以便直接处理数据。
7. 作为浏览器能力受限的用户，我希望只看到环境支持的复制入口，以免操作后毫无结果。
8. 作为只支持文本复制的环境中的用户，我希望代码复制仍可用，以免受到表格复制能力限制的连带影响。
9. 作为复制操作被拒绝的用户，我希望得到明确失败反馈，以便知道尚未复制成功并能重试。
10. 作为成功复制内容的用户，我希望看到成功反馈，以便确认操作完成。
11. 作为键盘用户，我希望能通过键盘打开表格菜单、移动选项和执行复制，以便无需鼠标操作。
12. 作为键盘用户，我希望按 Escape 可以关闭菜单并恢复焦点，以便继续浏览。
13. 作为宽表格阅读者，我希望能够全屏查看表格，以便阅读较多列的内容。
14. 作为全屏表格阅读者，我希望保留复制菜单，以便无需退出全屏即可复制。
15. 作为全屏表格阅读者，我希望普通视图和全屏都没有下载入口，以便功能保持一致。
16. 作为键盘用户，我希望打开全屏后焦点进入弹层并留在其中，以免误操作背景内容。
17. 作为键盘用户，我希望关闭全屏后焦点回到打开它的入口，以便继续原来的阅读顺序。
18. 作为全屏内使用菜单的用户，我希望 Escape 优先关闭当前菜单，以便不会同时意外退出全屏。
19. 作为等待流式回复的用户，我希望原有操作禁用规则保持，以免复制尚在变化的内容。
20. 作为长表格阅读者，我希望保留表格内部滚动及原有流式滚动行为，以便页面不会被持续撑高或抢回阅读位置。
21. 作为窄屏用户，我希望菜单和全屏表格适应视口，以便操作区不会被裁切或造成页面横向溢出。
22. 作为使用不同主题的用户，我希望控件和弹层遵循 HeroUI 主题，以便保持可读性和交互一致性。
23. 作为长对话阅读者，我希望控件替换不使旧 chunk 随新内容反复重渲染，以便保持阅读性能。
24. 作为 Markdown 阅读者，我希望行内代码、代码高亮、数学、链接与表格正文保持原有语义，以免操作区改动影响内容。

## 实现决策

- 共用现有 Markdown 渲染配置，为静态 MarkdownText 与流式 LiveMarkdownText 提供稳定的 components.code、components.table 替换定义；不增加另一套 Markdown 解析入口。
- 代码块继续使用公开 CodeBlock 保留正文、高亮、语言标题、meta、incomplete、行号配置及限高行为，通过其 children 提供 HeroUI 复制按钮。替换 code 时同时保持行内代码与 fenced code 的实际分支判定，不能把行内代码转换成代码块。
- 复制代码使用原始代码值，不从高亮 DOM 反向拼接，也不使用仅为显示裁剪后的字符串。通过实际 writeText 操作成功与否更新反馈。
- components.table 接管唯一的操作区和全屏状态，直接消费 Streamdown 传入的语义表格 children；保留 thead、tbody、tr、th、td 等正文结构，不改用 HeroUI Table 重建数据或正文。
- 表格数据提取和格式转换直接使用 Streamdown 公开的 extractTableDataFromElement、tableDataToCSV、tableDataToTSV、tableDataToMarkdown。沿用现有配置语义，不维护手工序列化副本。
- 代码复制使用 HeroUI Button；表格复制使用 Dropdown.Trigger、Dropdown.Popover、Dropdown.Menu、Dropdown.Item；全屏入口使用 Button，弹层使用 Modal 的 compound API。复制与打开全屏属于辅助操作，使用小尺寸 ghost 按钮；关闭使用 Modal.CloseTrigger。图标控件必须有可访问名称。
- 全屏采用 Modal 的 full 尺寸与内部滚动。HeroUI 统一管理菜单键盘操作、弹层 Escape、焦点圈定、恢复和背景滚动锁定；不并存 Streamdown 旧弹层、自建 document 键盘监听或第二套 body overflow owner。
- 普通表格保留现有默认 300px 限高及横纵向内部滚动。自有表格外壳必须保持当前流式滚动语义：原先贴底时跟随新增内容，用户向上阅读时不强制抢回底部。全屏内容随当前表格内容更新，不另存正文快照；关闭后回到原阅读位置。
- 全屏中的表格菜单与正文属于当前弹层交互范围。菜单打开时 Escape 先关闭菜单，之后 Escape 才关闭全屏；不允许菜单 portal 破坏焦点圈定或被弹层裁切。
- 保留 StreamdownContext.isAnimating 作为操作禁用的权威状态；代码复制、表格复制菜单入口与全屏入口沿用当前流式禁用行为，不改用“代码围栏是否闭合”代替。弹层关闭操作保持可用。
- 代码复制要求安全上下文与可调用的 clipboard.writeText；表格复制要求安全上下文、可调用的 clipboard.write 和可构造的 ClipboardItem。两类能力独立判断，不因缺少 writeText 而隐藏实际支持富文本复制的表格入口。
- 能力检查只能说明 API 存在，不能证明用户权限或实际写入成功。表格一次写入 text/plain 与 text/html；写入失败必须走明确错误反馈，不能标为成功或静默改用 writeText。
- 复制成功反馈仅在写入完成后出现；失败通过操作附近的 HeroUI Alert 表达并可被辅助技术感知，允许重试。复用当前操作结果反馈时长，不建立全局业务状态或重新发送机制；卸载时清理局部定时资源。
- 代码块、普通表格与全屏表格全部移除下载入口和下载执行路径，不保留隐藏按钮、程序化点击旧按钮或替代下载菜单。不新增下载工具、扩展名映射或相关依赖。
- HeroUI 是全局主题权威。控件与弹层使用其组件样式及 surface、foreground、muted、separator 等语义 token；保留正文所需的局部 Streamdown 覆盖，清除仅服务已移除旧控件的覆盖，不增加全局 Tailwind 语义映射。
- 文案沿用项目本地化机制；复制名称、格式选择、全屏名称和成功失败反馈对静态与流式入口保持一致。
- 组件类型、controls 和 context 直接引用或机械派生自已安装 Streamdown 的公开类型。不得以宽泛断言、手工接口镜像或运行时静默兜底隐藏依赖不兼容。
- 保留 thread、turn fragment、chunk 和现有 selector 的职责边界；控件局部状态不驱动整个 turn 重新渲染，不拍平全部 entries，也不为全屏预渲染无关内容。
- 不修改 Streamdown 源码、安装包或参考仓库，不新增依赖补丁、fork、私有深层导入或从 bundle 提取私有映射。用户最终移除全部下载功能，已经消除了扩展名复用问题。

## 测试决策

主要验证接缝复用应用公开的 MarkdownText 与 LiveMarkdownText 渲染入口，在真实浏览器 DOM 中操作最终控件。无需新增产品测试接口或用仅验证底层按钮的测试替代集成行为。既有 MarkdownCopyControlsAvailable、MarkdownCopyControlsUnavailable、MarkdownCopyControlsMissingClipboardWrite 和 MarkdownScopedStyles Browser 测试是测试组织与环境构造的先例；其现有断言不能自动代表新行为已经覆盖。

以下是设计拟定的验证范围，尚未运行。测试验证用户可见行为、复制载荷和稳定性能约束，不锁定私有状态名、组件拆分或内部调用次数。

- 覆盖静态和流式渲染，确认代码与表格均没有下载按钮，表格全屏也不存在下载入口；键盘不能到达隐藏下载控件。
- 验证代码复制的完整原始内容，包括尾部换行；覆盖行内代码、高亮代码、incomplete、数学及链接的相邻回归。
- 覆盖仅有 writeText、仅有完整表格复制能力、两类能力均有、能力均缺失、非安全上下文，以及缺少 ClipboardItem 的组合；入口必须符合实际能力，不能只检查按钮存在。
- 使用模拟剪贴板捕获一次写入中的 text/plain 与 text/html，分别验证 Markdown、CSV、TSV 的内容与表格结构；覆盖特殊字符、换行与空单元格，不触碰系统剪贴板。
- 分别模拟写入成功和拒绝，验证成功反馈、失败可见性、没有虚假成功以及重试成功；不要用仅存在 API 的 stub 代替写入行为测试。
- 通过真实 Tab、方向键、Enter、Escape 操作表格菜单，检查可访问名称、菜单语义及焦点恢复。不得用程序 focus 冒充键盘自然到达。
- 验证全屏打开后焦点进入、Tab 与 Shift+Tab 圈定、Escape 和关闭按钮退出、退出后回到触发器、背景滚动恢复。覆盖全屏菜单 Escape 分层关闭及菜单复制。
- 验证流式操作禁用、静态入口恢复可用、滚动贴底跟随与手动上滚不被抢回；保留正文限高、宽表格横向滚动、关闭全屏后的阅读位置。
- 覆盖浅色与深色主题、窄屏菜单可见性、全屏边界及 focus-visible；以用户可见边界和焦点行为为依据，不用恢复旧 CSS 类或放宽断言掩盖失败。
- 复用 transcript 现有分块验证接缝，针对本次局部控件状态和流式更新确认没有引入全 turn 展开或无关 chunk 重渲染风险；不把固定测试数量作为完成条件。
- Level 1：受影响的完整 Browser 测试文件在项目配置的浏览器引擎下验证，并运行适用 lint、类型检查及本地化检查。具体命令、生成物范围与执行顺序属于后续实施计划；不自动扩展为全量测试。
- Level 2：使用当前真实 Codex runtime 的完整 GUI URL 做无头验收，覆盖实际对话中的菜单、全屏、焦点、滚动、主题及窄屏行为。仅在模拟环境挂载生产组件不能替代该层；运行时或 URL 缺失时如实标记未执行。
- Level 3：本设计不依赖 OS 窗口、IME 或跨应用桌面焦点，当前不适用。自动化剪贴板载荷验证不声称证明 OS 权限或所有富文本应用的粘贴结果。

## 范围之外

- 任何代码或表格下载功能，包括下载文件命名、语言扩展名映射和 CSV 下载 BOM 维护。
- 修改、打补丁、fork 或发布 Streamdown，以及改动用户提供的外部参考仓库。
- 将表格复制统一降为纯文本，或复制失败后静默降级。
- 替换 Markdown 解析器、高亮插件、数学插件、链接策略或语义正文表格。
- 修改 transcript 分块、分页、存储、协议、后端或会话状态模型。
- Mermaid、图片下载、链接安全弹层等当前未启用或不属于本次目标的控件。
- 本轮审计中的其他 HeroUI 采用项或不相关测试失败。
- 本次实施产品代码、创建实施计划、运行产品测试、提交 Git 或发布外部 issue。

## 补充说明

本规格依据 2026-09-12 HeroUI 采用审计中的 F01、F02、R01、R02、R04，以及本次对话后的当前源码核验形成。审计中的历史运行证据与本轮只读源码核验分开解释；本次没有重跑审计场景，也不声明问题已经修复。

参考 Streamdown 源码和当前安装包均标记为 2.6.0，但版本号相同不代表所有文件内容完全一致；实施以当前安装包的公开契约与实际构造行为为准。HeroUI 本地源码与当前依赖已核验为 3.2.4。

生效的用户决策为：表格保留纯文本与 HTML 双表示；代码块移除下载按钮；表格也移除下载按钮，包括全屏入口内的下载。此前“保留代码下载扩展名”的选择已被后续移除下载的指令覆盖；手写映射、机械提取私有映射及依赖补丁均不属于最终方案。

本次采用 to-spec 的规格结构，按用户“落盘设计”要求保存为项目本地设计文档。不连接 issue tracker、不应用外部 triage 标签，也不把参考材料中的动作描述视为发布授权。后续实施计划应在本设计基础上单独确认。
