# Codex GUI HeroUI 采用情况深度审计规格

日期：2026-09-12
状态：审计规格；不是审计结论或修复计划

## Problem Statement

当前前端已使用 HeroUI，但已有检查主要证明了组件导入和部分 JSX 使用，未充分回答所有适合使用 HeroUI 的控件是否都已采用。此前关于组件遗漏和 variant 不一致的结论缺少完整适配分析与运行证据，不能直接作为修复依据。

用户要求重新进行完整深度审计并出具正式报告。之前报告的项目也必须重新核验，不以旧结论作为前提。

## Solution

依据用户指定的 HeroUI Design Principles，对当前 Codex GUI 的生产界面建立可追溯的控件清单，逐项检查组件采用、语义意图、自定义实现理由及适用的交互行为。

采用用户已选择的严格标准：优先使用 HeroUI React 组件；存在适配组件时，自定义实现必须有具体、可核实的保留理由，仅复用颜色或样式不足以通过项目采用审计。同时明确区分官方规范允许的实现与本次更严格的项目采用标准，不能将后者误称为官方禁令。

执行源码追踪和无头浏览器验证，输出覆盖范围、证据、问题、保留理由、建议及验证缺口。最终结论放到用户指定的报告目录。

## User Stories

1. 作为项目维护者，我希望重新核验此前发现，以避免将不充分的初步判断当作事实。
2. 作为项目维护者，我希望看到生产页面与共享控件的覆盖清单，以判断审计是否遗漏区域。
3. 作为项目维护者，我希望区分实际组件使用、样式复用和自定义实现，以了解真实采用情况。
4. 作为项目维护者，我希望每项替换建议对应适配的 HeroUI 组件，以避免仅凭组件名称推断能力。
5. 作为项目维护者，我希望自定义控件的保留理由有实现证据，以避免无依据的例外。
6. 作为项目维护者，我希望合理的文档结构和布局元素不被机械替换，以保留语义和性能边界。
7. 作为用户，我希望主要、辅助、取消和破坏性动作具有清晰层级，以准确理解操作意图。
8. 作为键盘用户，我希望控件支持正确的导航、激活及焦点恢复，以完成实际操作。
9. 作为辅助技术用户，我希望控件名称、状态和关联关系清晰，以理解当前界面。
10. 作为用户，我希望禁用和处理中状态与实际可执行动作一致，以避免误操作。
11. 作为用户，我希望弹层打开、关闭和滚动行为一致，以正常使用菜单、抽屉和对话框。
12. 作为项目维护者，我希望审计包含 Lexical 集成中的候选菜单和技能标记，以覆盖编辑器内部控件。
13. 作为项目维护者，我希望审计包含 Streamdown 的复制、下载和全屏等实际启用控件，以覆盖第三方生成的交互界面。
14. 作为项目维护者，我希望源码结论与运行时验证分开记录，以正确理解证据强度。
15. 作为项目维护者，我希望报告列明不可达状态和环境缺口，以避免把未验证写成通过。
16. 作为项目维护者，我希望获得可定位、可复核的问题分级和建议，以支持后续独立决策。
17. 作为用户，我希望验证全程无头运行，以避免占用可见桌面。
18. 作为项目维护者，我希望本轮只做审计，以避免未经确认修改产品行为。

## Implementation Decisions

- 本轮对象是当前前端采用情况，不实现新功能，也不实施修复。
- 覆盖应用外壳、新会话、当前任务、历史列表与详情、输入与待发送管理、错误恢复、扫码入口、已提交对话内容，以及它们使用的共享控件。
- 不仅搜索导入和原生标签，还追踪包装组件、路由组合、实际挂载入口、动态生成及第三方集成路径。
- 每个候选项核对实际职责、HeroUI 对应组件的匹配版本能力，以及替换是否损害现有交互、状态所有权、文档语义或性能约束。
- 分开记录：组件采用遗漏、已采用组件的语义偏差、合理保留的自定义实现、证据不足的待验证项。
- 官方允许样式与逻辑分离不自动构成本次严格标准下的保留理由；也不因原生元素存在就判为遗漏。
- 延续现有状态所有权与内容渲染边界。审计建议不得隐含增加双重交互控制或替换编辑器模型。
- 不修改产品代码、依赖、配置、生成物或测试基线；不提交代码、不操作 Git 远程、不安装组件或可执行工具。

## Testing Decisions

- 已确认采用源码审计与无头运行验证。优先现有页面、组件 Browser 测试及真实应用入口，不新增测试专用接口。
- 好的验证检查用户可观察行为，不能仅断言导入、类名或组件内部结构。
- 依据现有相关测试核对已覆盖行为；需要执行时使用项目规定的工具链和受影响测试文件，不默认运行整个前端测试套件。
- 对候选问题验证适用的键盘导航、焦点进出与恢复、可访问名称、禁用及处理中状态、弹层开关和滚动行为。
- 现有输入区域、待发送抽屉、应用外壳及 Markdown 样式 Browser 测试是可参考的验证材料；执行前核对当前文件和实际测试入口。
- 优先通过生产页面的用户交互验证跨组件行为；组件测试用于难以在现有真实状态下触发的有界场景，结果不能冒充真实集成验收。
- 第三方控件检查实际启用及可达的路径，不能仅根据库的类型声明或导出符号判断运行能力。
- 启动验证前核对现有工具、运行环境及授权。缺少依赖时报告，不安装；需要原生后端构建时由用户执行。
- 区分静态证据、自动化回归与无头真实应用证据；逐项记录未运行、不可达、失败或通过。无头验证不等于完整无障碍认证。
- 不启动可见浏览器或桌面窗口，不以修改断言、放宽检查或隐藏失败获取通过结果。

## Out of Scope

- 本轮不实施 HeroUI 替换、按钮 variant 调整、样式修复或架构重构。
- 不把所有 HTML 元素替换为组件，不机械替换 Markdown 内容、语义布局、滚动边界或富文本编辑器。
- 不执行原生后端构建、依赖安装、Git 远程操作或可见桌面验收。
- 不把本规格当作已经完成的深度审计报告，也不将此前发现视作已证实缺陷。
