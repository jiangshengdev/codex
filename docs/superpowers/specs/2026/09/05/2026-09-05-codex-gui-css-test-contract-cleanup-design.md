# Codex GUI CSS 测试契约清理设计

设计状态：已确认

设计及确认日期：2026-09-05

## 唯一主目标

清理 Codex GUI 测试中将 CSS 实现细节和普通视觉取值写死的断言，降低后续样式调整的维护负担，同时保留少量明确约定的视觉关系及真实行为保障。

用户要求优先处理历史页面间距测试所代表的一系列问题，明确不接受只修正该测试的测量起点。经 `grill-me` 转交 `grilling` 评估，用户选择 B：保留少量明确约定的视觉关系，清理具体像素、类名、颜色和阴影等断言。随后要求“新设计落盘”。本文记录该设计，不包含实施计划，不授权实施或提交。

## 问题与当前证据

问题并非所有 CSS 都已被测试，而是部分测试把当前实现直接提升成长期契约：正常的视觉调整也会导致失败，且同一用例经常混合外观约束和真实功能保障。

## 清理原则

### 删除不必要的实现和外观断言

清理仅用于验证具体类名、固定 padding/gap、颜色、圆角、边框外观、阴影及其他普通视觉取值的断言。禁止以“当前 CSS 就是这样”“以前写过测试”或测试数量作为保留理由。

不将固定值替换成读取生产 CSS 变量、token 或同一公式再比较。这样的测试仍是在用实现验证自身，不能解决维护负担。

不以匹配到 `classList`、`getComputedStyle`、`getBoundingClientRect` 或数值字面量作为删除的充分条件。测试中的数值也可能表示输入规模、视口场景、交互预期或浏览器测量误差，需要按所保护的结果判断。

### 保留少量已确认的视觉关系

保留顶栏、正文与底部卡片的有效左右边界对齐，包括预览与聊天之间已确认的边界关系。历史列表按整体内容区域判断，宽屏多列卡片不要求每张卡片占满整个区域。

关系断言比较实际元素边界，不规定具体宽度、左右留白或 CSS 实现。必要的测量容差仅处理浏览器亚像素误差，不用于掩盖真实不对齐。

不把所有既有样式测试重新命名为“视觉关系”后保留。每条保留的纯视觉关系必须有明确的已确认用户要求；单纯改成两个 computed style 相等仍不构成理由。颜色、阴影、圆角的一致性不进入本次保留集合。

### 保留真实行为保障

继续保护内容与控件可达、未被遮挡、无意外溢出、滚动可用、键盘选择、焦点可见以及输入、导航、状态、错误恢复等原有功能。

CSS 可能参与这些行为，但尽可能验证行为结果。例如验证诊断展开后消息仍可访问和点击，而非仅要求某个定位类名；验证键盘选中项可见，而非强制某种 overflow 实现。

若某条 CSS 属性断言涉及真实回归，先核实其失败路径、现有行为覆盖及可替代性。需要保留的依据是已确认的行为保障，不是实现历史。不能在缺少等效保障时顺手删除，也不能以“可能影响行为”为由无限保留实现断言；证据未闭合的项应明确标为待判断。

## 混合测试的处理

以断言为基本评估单位，而非按测试文件整批删除。

- 混合用例删除不必要的外观断言，保留功能与可访问性检查，并让用例名称准确描述剩余契约。
- 纯粹验证外观实现、没有独立功能价值的用例可整项删除，同时清理仅被它使用的 helper、fixture 和 import。
- 行为检查绑定具体 CSS 实现时，依据实际用户结果调整检查方式，保留其原有失败检测能力。
- 不修改生产代码来迎合旧测试，不用扩大容差、跳过用例、关闭浏览器或更新快照基线掩盖失败。

## 范围与排除项

评估和后续清理覆盖 `codex-gui` 的测试及直接依赖的测试辅助代码，包括 `src/__tests__`、`src/features/**/__tests__`、sequential Browser 测试与 `e2e` 中同类断言，不局限于当前失败用例。

本设计不要求修改产品样式、组件、交互、HeroUI variants 或语义 token，不新增替代组件或共享生产模块。协议、DTO、状态 owner、生成链、Rust 和后端均不受影响，不新增或复制权威契约。

两个仍寻找 `button[name="View"]` 的路由测试属于独立的选择器失配问题，单独记录，不混入本次 CSS 测试清理。它们若阻塞执行，应如实报告，不视为本设计自动授权的修复项。

本设计不包含全局或项目规则文件、skills 的修改，也不将普通样式调整自动转成截图快照测试要求。

## 与旧设计的关系

保留同日历史列表、历史预览与聊天 UI 一致性设计作为历史记录，不覆盖原文件。

本设计调整相关要求的自动化验证方式：视觉设计中出现某个间距、外观或组件选择，不代表必须为其编写逐项 CSS 断言。已有产品外观保持不变；少量明确关系保留自动化覆盖，其他普通视觉取值由样式验收评估。

“普通视觉取值不进入自动化契约”不等于取消产品要求，也不意味着本次可以顺带修改这些取值。

## 验证与完成标准

实施计划需建立按断言归类的清理清单，说明删除理由、保留关系、保留行为以及需要改写的行为检查。不得以删除数量、文件数量或剩余测试数量判断完成。

完成标准是：范围内不再以普通 CSS 实现或取值作为无依据的失败条件；已确认对齐关系与原有交互、可访问性、遮挡及滚动保护仍具有有效断言；不出现仅换 helper、改取值来源后继续自我验证的测试。

### Level 1：自动化回归

运行受影响测试的权威入口，确认实际收集与执行目标。根据改动范围验证保留的行为和关系，完成适用格式、lint 与类型检查。只为保留契约有变化的检查补充必要验证，不为已删除的装饰性断言新增镜像测试。

对失败区分本次引入、既有失配和未执行部分。独立的 `View` 选择器失败不能被报告为通过，也不能要求以其修复作为本设计扩大范围的前提。

### Level 2：真实应用验收

仅删除测试断言且生产行为不变时，不因测试中出现 CSS 就自动要求重做真实应用全套验收。若改写某项行为检查需要真实应用证据证明其仍覆盖原失败路径，则按该场景执行无头验收，并取得当时完整的当前 GUI URL；不复用旧 URL 或以旧验收替代新增证据。

### Level 3：可见桌面验收

当前设计不涉及依赖操作系统窗口、系统输入法或跨应用焦点的产品变更，无可见桌面验收场景。若后续事实改变适用性，应单独说明影响并按既有规则取得授权。
