# Codex GUI 历史界面紧凑卡片与日期分组设计

## 唯一主目标

优化历史界面的空间利用，参考 HeroUI Card 布局指导和设计原则调整卡片内部布局，并按日期分组显示历史记录。

用户经过 grilling 确认四项产品决策，并明确授权将设计落盘。截图和参考文档作为视觉与技术证据，不作为额外动作授权。

## 已确认决策

| 决策 | 已确认结果 |
| --- | --- |
| 分组内布局 | 紧凑多列卡片，保留响应式网格 |
| 日期标题 | 今天、昨天，更早显示具体日期，跨年显示年份；卡片内仅显示时分 |
| 内容密度 | 标题最多两行，摘要最多两行 |
| 打开方式 | 整张卡片打开历史详情，底部保留“查看”提示，支持键盘聚焦和打开 |

## 当前实现与问题依据

当前 `codex-gui/src/features/threadHistory/ThreadHistoryListPage.tsx` 已使用一列、两列、三列的响应式网格。卡片把标题与摘要、时间与状态、查看按钮分为 Header、Content、Footer 三个区域。

本地 HeroUI 3.2.4 的 `packages/styles/components/card.css` 为 Content 定义了 `flex-1 flex-col`。页面对 Content 设置 `items-center justify-between`，没有改为横向排列，因此时间与状态沿纵向分散；Footer 又单独占一行。卡片拉伸与这些布局规则共同扩大留白。需要重新组织信息，不能仅缩小字号或隐藏溢出来压缩卡片。

当前时间显示取 `(thread.recencyAt ?? thread.updatedAt) * 1000`，使用浏览器本地时区。`threadHistoryListOwner.ts` 请求使用 `sortKey: "recency_at"`、`sortDirection: "desc"`，按当前工作目录查询未归档记录，通过 cursor 追加和 ID 去重保留返回顺序。

## 日期分组

分组和卡片时间共享现有 `recencyAt ?? updatedAt` 时间来源，以浏览器本地自然日确定归属，不能用 UTC 日期字符串切片替代本地日期。

- 当天显示“今天”，前一天显示“昨天”。
- 更早的本年记录显示月日；跨年记录显示年月日。
- 卡片只显示对应的本地时分，避免重复组标题的日期。
- 日期、时间和相对日期标签遵循当前界面语言与本地化机制。
- 保留现有记录顺序和分页所有权；同一天跨分页出现时合并到同一组，不生成重复日期区块。
- 日期标题使用有意义的标题层级，每个日期组包含自己的响应式网格。

本设计不增加分组折叠、日期筛选、重新排序或新的请求路径。

## 卡片布局与内容

保留手机一列、中等屏幕两列、宽屏三列的现有响应式拓扑。每组卡片沿用页面内容边界，不通过加宽其他路由来提高密度。

卡片上方集中展示标题和可选摘要；底部把时分、状态和“查看”提示集中为一个紧凑区域。空间不足时允许合理换行，不能挤压、遮挡状态与入口。同一网格行卡片保持整齐，底部信息对齐；不设置脱离内容需要的固定大高度，不让时间和状态纵向撑开。

标题和摘要均采用最多两行的视觉截断。完整字符串继续保留在 DOM 中，不在 JavaScript 中裁剪。长 URL、路径及连续无空格文本能够在卡片宽度内断行，不能撑宽卡片、网格或页面。

继续复用 `resolveThreadHistoryPresentation`：标题采用去除首尾空白后的 name、preview、本地化默认标题依次回退；只有 name 与 preview 均非空且不完全相同时展示摘要。不引入摘要清洗、路径提炼、Markdown 解析或语义改写。

## 整卡导航与可访问性

整张卡片作为进入现有历史详情的单一导航入口。底部“查看”是可见提示，不再嵌套第二个独立按钮。采用真实链接语义与现有路由集成，避免仅在非交互容器上绑定点击事件。

- 点击卡片内容或空白区域均可进入对应记录详情。
- Tab 可聚焦卡片，Enter 打开，焦点样式清晰且不被裁切。
- 完整标题提供清楚的可访问名称；状态和时间仍可读取。
- 不在卡片导航入口内嵌套链接或按钮，避免重复焦点和嵌套交互。
- 详情目的地及既有路由参数处理保持不变；打开历史卡片不直接恢复任务。

具体的 HeroUI 样式组合与路由链接适配属于实施机制，计划阶段核查现有入口后确定，不新增独立导航路径。

## HeroUI 设计规范

采用 HeroUI v3 的组合方式，按信息需要重组或省略 Card 子区域，不为保留完整 Anatomy 而强行保留空 Content。

卡片沿用 default 层级及对应 Card 样式；状态沿用 soft Chip，systemError 继续使用 danger 语义色。底部“查看”提示与卡片入口表达同一个动作。分页使用现有 secondary Button，错误使用现有 danger Alert。

使用既有 surface、foreground、muted、圆角和间距语义 token；不引入硬编码状态色、装饰图片或新组件依赖。明确区分内容层级、状态反馈和导航入口，并保证键盘可访问性。

## 与历史设计的关系及边界

本设计定向更新 [2026-08-17 历史任务响应式网格设计](../../08/17/2026-08-17-codex-gui-thread-history-responsive-grid-design.md)，旧文档保留为历史记录。本次明确替换以下规定：

- 摘要最多三行改为最多两行。
- 仅独立“查看”按钮导航、禁止整卡点击，改为整卡单一导航入口与“查看”提示。
- Header、Content、Footer 三段固定分工改为文字区与紧凑底部区域。
- 扁平网格改为按日期分组的网格，完整日期由分组标题承载。

其余相关行为以当前实现为依据保持：工作目录与未归档范围、cursor 分页、去重、加载更多、错误与重试、状态字段映射、标题摘要来源、历史详情与当前任务边界。

权威数据继续来自 `@codex-protocol/v2` 的 `Thread`。日期组是展示层对既有字段的派生，不复制协议 DTO，不新增服务端字段或第二套历史状态来源。本次不涉及 Rust、协议生成、历史详情布局、当前任务页或 Drawer 改造。

## 验收设计

### Level 1：自动化回归

覆盖本地自然日边界、今天/昨天/更早/跨年标签、recencyAt 为空时沿用 updatedAt、同日跨分页合组和现有记录顺序。验证标题与摘要两行上限、完整文本保留、长文本不溢出、响应式列数、整卡导航与键盘入口，以及分页、空状态、错误重试和状态展示。

断言以用户可观察行为为依据，不固化任意 padding、阴影或圆角数值，也不通过删除原有行为覆盖来通过测试。

### Level 2：无头真实应用验收

使用实施阶段确认的当前运行地址和真实历史记录，检查日期分组、卡片密度、长文本、多种视口、点击与键盘导航、焦点可见性、分页合组及页面无横向溢出。截图中的地址不自动作为本轮可用运行入口。

### Level 3：可见桌面验收

本设计不依赖操作系统窗口或输入法状态，预计不适用。如后续出现必须依赖可见桌面的结果，应单独确认窗口影响后执行。

上述内容是验收要求，当前仅完成设计调查，尚未执行实现测试或真实运行验收。
