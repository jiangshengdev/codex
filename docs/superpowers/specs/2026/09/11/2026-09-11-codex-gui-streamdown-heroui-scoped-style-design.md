# Codex GUI 富文本消费 HeroUI 样式设计

日期：2026-09-11

状态：根据重新对齐的对话落盘，待文档审阅；本版尚未实施。

## 问题陈述

用户希望现有富文本与 HeroUI 应用协调，同时尽可能采用 Streamdown 默认结构、布局和交互，并参考 Streamdown 官网呈现。当前表头将 HeroUI 的 muted 次要文字色用作背景，行内代码还存在额外的自定义边框和间距。

此前实现通过全局 Tailwind 主题映射接入 Streamdown 局部变量。虽然部分映射设置了回退，且原始 HeroUI muted 变量没有变化，但全局工具类的定义已经被富文本需求改变。这不符合“HeroUI 管全局主题，富文本消费 HeroUI 样式”的职责方向。外部暂时没有可见变化不能证明全局样式契约保持不变。

该实现已经回退。本版取代此前主题适配设计作为后续工作的设计依据；旧设计、旧计划及验收记录保留历史意义，不构成本版实现授权或验收证据。

## 解决方案

保持 HeroUI 全局主题和工具类语义不变，仅在现有富文本及其所属浮层范围内，用 HeroUI 视觉语义覆盖 Streamdown 的呈现。表格、代码及辅助控件使用协调的表面、文字和边界颜色，保留 Streamdown 默认组件及功能。

参考官网的默认内容结构和视觉层次，不照搬官网的全局主题接入方式或 Geist 配色。实现必须同时证明富文本呈现正确，以及 HeroUI 全局样式和外部组件保持原有语义。

## 用户故事

1. 作为应用用户，我希望 HeroUI 继续拥有全局主题，以便富文本调整不会改变其他组件的样式规则。
2. 作为消息读者，我希望所有现有 Streamdown 内容采用 HeroUI 视觉语义，以便与应用保持协调。
3. 作为表格读者，我希望表头使用表面背景色，以便识别列标题而不被过深的色块干扰。
4. 作为代码读者，我希望代码块保留默认布局和语法高亮，以便理解内容。
5. 作为代码读者，我希望不显示行号，以便保持简洁呈现。
6. 作为正文读者，我希望行内代码恢复默认结构和间距，以便不再出现额外自定义边框。
7. 作为消息读者，我希望普通段落保留原文换行，以便保留表达结构。
8. 作为等待回复的用户，我希望保留块状光标而不增加渐入动画，以便保持既有生成状态提示。
9. 作为历史内容读者，我希望流式和静态内容采用相同样式，以便完成后不发生不必要的外观切换。
10. 作为阅读不同角色内容的用户，我希望保留外层 Card 和完成思考的次要文字、斜体层次，以便辨别内容角色。
11. 作为窄屏用户，我希望长代码、宽表格和公式在自身容器滚动，以便页面不会被撑宽。
12. 作为浅色或深色主题用户，我希望富文本背景、文字及控件均清晰可辨，以便持续阅读。
13. 作为表格用户，我希望全屏表格沿用相同的 HeroUI 语义，以便浮层与正文协调。
14. 作为控件用户，我希望复制、下载、下拉菜单及悬停状态保持可用，以便继续完成现有操作。
15. 作为键盘用户，我希望保留可访问名称、焦点和键盘操作，以便不依赖指针操作。
16. 作为数学内容读者，我希望保留助手公式的解析、基线和局部滚动，以便样式适配不会损坏公式。
17. 作为处于不同浏览器环境的用户，我希望复制控件继续遵循剪贴板可用性，以便不会显示不可用操作。
18. 作为应用用户，我希望链接、图片、HTML 和消息处理边界不变，以便样式修改不引入其他行为变化。

## 实现决策

### 样式职责与硬边界

- HeroUI 是全局主题、语义颜色和工具类映射的权威来源。
- 禁止为 Streamdown 新增或重定义全局 Tailwind 颜色映射，禁止在全局工具类中引用富文本专属变量。带有回退的全局映射同样不符合本设计。
- 不改变 HeroUI 现有主题变量的含义，包括在富文本子树中将 muted 从文字色重新定义为背景色。
- 富文本适配直接消费 HeroUI 的 surface、surface-secondary、foreground、muted、border 等语义颜色；辅助控件仍为辅助操作。
- 通过富文本作用域和 Streamdown 元素标记约束覆盖范围，优先使用 data-streamdown 标记。没有独立标记的内部节点，可从其已标记祖先局部定位；具体选择器和 CSS 层叠由实现负责核验。
- 不以应用级通用元素选择器或重定义全局工具类处理富文本缺口。覆盖必须能说明它服务的富文本元素和状态，不能把上一版全局映射简单搬成另一套主题所有者。
- 仅颜色适配不要求重写默认 Markdown DOM、工具栏或交互逻辑；尽可能沿用 Streamdown 默认组件。

### 共享入口与浮层

- 静态和流式 Markdown 使用一致的富文本覆盖边界，覆盖现有通过这些入口渲染的内容。
- 全屏表格是当前启用功能中挂载到 body 的浮层，使用其 table-fullscreen 标记独立限定样式，不因此扩大到 body 或应用其他浮层。
- 表格复制、下载下拉位于 table-wrapper 子树，不是独立 portal。覆盖需包含其无独立标记的菜单、背景、辅助文字和悬停状态，不能只处理带标记节点。
- 当前未启用 Mermaid 插件，图片禁用，链接安全弹窗关闭；不为这些未启用功能扩展主题范围。

### 保留的结构与行为

- 恢复 Streamdown 默认行内代码组件，移除额外自定义边框和间距；代码块、表格及控件继续由默认组件拥有。
- 保留代码插件及其 GitHub 浅色、深色高亮主题，不新增插件或高亮库。
- 代码块不显示行号；普通段落保留 white-space: pre-wrap。
- 保留静态与 streaming 模式的分工、现有生成状态及 caret="block"，不启用 animated。
- 保留用户、助手和完成思考的外层 HeroUI Card 层次，以及完成思考的次要文字和斜体。
- 不把纯文本转换成 Markdown，不改变流式思考仅显示标题的当前行为。
- 保留宽度约束、必要换行、代码行块级显示及数学局部滚动。删除既有规则必须有默认实现等价承担的证据。
- 数学解析仍限助手内容，保留单美元符号及反斜杠公式处理。
- 保留本地文件链接转文本、rehype 处理、图片禁用、原始 HTML 跳过、linkSafety 配置和剪贴板能力判断。
- 不修改后端、协议、schema、状态模型或生成契约。

## 测试决策

- 沿用此前确认的最高层测试入口：通过已有 transcript 渲染组件、共享 Markdown 配置及 projection fixtures 检查结果，不新增仅供测试的主题接口。
- 正向验证富文本：浅深主题的表头、代码、行内代码、控件及全屏呈现；静态与流式一致；默认结构、无行号、原文换行及角色层次保留。
- 反向验证隔离：检查富文本外代表性的 HeroUI 组件和颜色工具类仍遵循 HeroUI 语义，并在富文本挂载、卸载及全屏打开、关闭过程中保持一致。
- 对全局样式契约进行源码及构建规则审查，确认没有为富文本重定义全局主题映射。仅断言根元素没有富文本变量，或仅观察外部当前颜色不变，不足以证明隔离。
- 覆盖表格菜单、代码工具栏和全屏控件的文字、背景、悬停、焦点及操作；验证真实存在的无标记子节点，不以给所有元素新增标记作为前提。
- 好的测试断言可见行为与隔离契约，不锁死完整 class 字符串、组件内部数量或官网像素值。复用现有数学、链接和剪贴板测试，不用大量低层测试替代共享入口验证。
- Level 1：对受影响 Browser 文件执行三浏览器自动化回归，并运行相关类型、lint 和格式检查。需要新增隔离覆盖，不能沿用旧版主题测试通过作为本版完成证据。
- Level 2：使用实施时有效的完整 GUI URL，无头验证真实浅深主题、宽屏和 390px 窄屏、长代码、宽表格、公式、默认控件及真实流式到静态转换。记录可用与受限剪贴板环境；没有对应内容或状态的场景标记未执行。
- 当前没有授权发送真实验收消息；需要新增对话时另行取得业务写入授权。历史静态页面或测试 fixtures 不能代替真实流式证据。
- Level 3 当前不适用，不打开可见桌面窗口。不得通过跳过、放宽断言或修改基线消除失败。

## 范围外

- 重设 HeroUI 全局配色、工具类映射或语义变量。
- 复制 Geist 品牌主题，要求与官网像素一致，或全面重写 Streamdown 控件。
- 新增 Markdown 功能、动画、行号、插件，改变角色、安全或剪贴板能力边界。
- 改变消息、路由、状态、协议、持久化或 transcript 分块性能边界。
- 修复此前发现的范围外 lint、页面布局及 E2E 问题，或修复 Streamdown 既有上游交互问题。
- 本轮代码实现、计划落盘、测试运行、本地提交、远程发布、安装依赖及后端构建。
