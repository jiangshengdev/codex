# Codex GUI 从已结束 turn 末尾 fork：设计规格

日期：2026-09-11

状态：设计已落盘，待审阅；未进入实施计划或代码实现。本文按 `to-spec` 整理本次对话中已经收敛的产品范围，并区分产品决策、接入设计与后续验证事项。

## 问题陈述

用户需要保留原聊天，同时从某个已结束的 turn 继续探索另一种方向。当前 Rust 已提供创建 fork 的能力，但 GUI-host 与 GUI 命令入口尚未接通，用户无法在当前聊天或历史预览中直接完成这一操作。

此前讨论的“从聊天中继续”来源入口任务已经停止。本设计的唯一目标是实现 fork 创建与进入新会话，不恢复来源入口或分支图任务。

## 解决方案

在当前工作聊天和历史预览的已结束 turn 末尾提供 fork 操作。用户选择某个 turn 后，新会话继承原聊天截至该 turn 的历史，包含所选 turn，排除其后所有 turn。

允许作为分叉点的状态为 `completed`、`interrupted`、`failed`；`inProgress` 不可选择。仅在现有已展示的 turn 上提供入口，不新增空内容判断或展示逻辑。原会话可以正在生成后续 turn，这不妨碍从此前已结束的 turn fork，原会话继续生成。

新会话创建并完成激活后，立即进入新会话的当前聊天页，后续输入发送到新会话。新会话沿用来源会话的工作目录，共享其中的文件；使用后端当前配置的模型，不增加模型选择或目录选择步骤。

## 用户故事

1. 作为当前聊天的使用者，我希望从指定已结束 turn 的末尾创建新会话，以便尝试另一个方向。
2. 作为历史记录的阅读者，我希望直接在历史预览中 fork，以便无需先切换回来源会话。
3. 作为用户，我希望新会话包含所选 turn，以便保留这一轮完整的结果。
4. 作为用户，我希望新会话排除所选 turn 后面的历史，以便分支上下文准确对应我的选择。
5. 作为用户，我希望从正常完成的 turn fork，以便继续扩展已有结果。
6. 作为遇到中断的用户，我希望从已经中断的 turn fork，以便保留已发生的上下文并继续尝试。
7. 作为遇到失败的用户，我希望从已经失败的 turn fork，以便在保留失败信息的情况下探索另一条路径。
8. 作为用户，我希望进行中的 turn 无法被选为分叉点，以免误把尚未结束的输出当作完整边界。
9. 作为正在等待后续输出的用户，我希望从此前已结束的 turn fork，以便同时推进新的思路。
10. 作为用户，我希望 fork 不停止原会话的生成，以便原任务继续完成。
11. 作为用户，我希望成功后立即进入新会话，以便后续输入直接发送到新会话。
12. 作为用户，我希望原会话保留，以便之后仍可查看和继续原来的方向。
13. 作为用户，我希望沿用来源会话的工作目录，以便继续在同一项目中工作。
14. 作为用户，我希望 fork 不要求重新选择模型，以便保持直接创建并继续的操作流程。
15. 作为长聊天的阅读者，我希望跨展示页的 turn 只有一个末尾入口，以便准确理解分叉边界。
16. 作为用户，我希望创建期间有明确的进行中反馈，以免重复点击造成重复创建。
17. 作为用户，我希望创建失败时能够看到错误，以便理解为何没有进入新会话。
18. 作为用户，我希望新会话已经创建但打开失败时能够继续打开该会话，以免重试产生另一份 fork。
19. 作为用户，我希望 fork 不自动发送原会话的草稿或待发送输入，以免消息被发送到错误的会话。

用户故事表达已确认目标及其必要的正确性约束；不代表这些行为已经实现或通过测试。

## 实现决策

### 术语与权威边界

- thread 表示持久化聊天身份；turn 表示一次轮次；turn fragment 与 context page 是 GUI 的展示分块和分页概念，不能作为后端 fork 位置。
- fork 产生新的 thread ID，原 thread 保留。所选位置由来源 `threadId` 与该来源中的 `lastTurnId` 表达，不通过消息正文相似度、消息序号或最后一个可见片段猜测。
- 已确认的是从已结束 turn 的末尾 fork。请求必须携带所选 `lastTurnId`，不能在目标不可用时改为不传边界的最新位置 fork。
- 不使用 `beforeTurnId`，不提供任意 turn 内 item 的分叉能力。

### Rust 与 GUI 命令契约

- 复用现有 `thread/fork` 及 `ThreadForkParams`、`ThreadForkResponse`，无需为 turn 末尾 fork 新增边界参数或持久化字段。
- Rust GUI-host 需要放行 `thread/fork`。前端协议方法集合、命令网关及权威生成的请求描述和校验产物同步接入该方法。
- Rust 协议仍是请求、响应、字段和枚举的唯一权威来源。TypeScript 类型与运行时校验通过项目生成链取得，禁止手写一份 fork DTO 或校验镜像。
- 创建结果以请求响应中的新 thread 身份为准，随后复用现有会话激活与 projection 读取。无需仅为识别创建结果而额外放行 `thread/started`。
- 后端负责验证所选 turn 的存在性、结束状态及历史边界。前端禁用状态只是操作反馈，不能替代服务端验证。

### 配置与工作目录

- 沿用来源 thread 的工作目录；两个会话使用同一目录的现有文件，不创建 worktree，不复制或回退文件系统。
- 不显式覆盖 `model` 等模型选择参数，使用后端当前配置加载结果。这与当前 GUI 新建会话不额外传入模型选择的方式一致。
- 不承诺恢复所选历史 turn 当时的模型，也不承诺复制来源会话最后使用的模型。TUI 普通 fork 显式传入当前模型的行为不直接沿用。
- 权限配置沿用后端已有 fork 解析与约束，不额外引入 GUI 权限选择步骤。现有逻辑会尝试恢复来源最新的 approval 与 permission profile；不是把所选历史 turn 当时的所有配置原样复制。
- 不因 fork 主动提交用户消息。原会话的草稿、待发送输入和恢复状态继续归原会话的现有输入管理机制所有。

### 页面与共享 transcript

- 两类页面复用同一个 fork 操作入口与请求生命周期，页面负责提供来源 thread 身份和可用操作能力，共享 transcript 负责提供实际 turn 身份及结束状态。
- 建议在 turn 最后一个 fragment 的末尾呈现操作，跨展示页不重复呈现同一 turn 的 fork 入口；位置依据现有 turn 与 fragment 映射。
- 没有最终 assistant 文本的失败或中断 turn 仍按 turn 状态判断，不能额外要求存在最终回答才允许操作。
- 复用现有展示规则；未展示的 turn 自然没有按钮，不新增内容筛选、展示、分页或定位逻辑。
- 保留 chunk 级 selector 和组件边界。添加操作不能在渲染路径把整个 turn 的所有 entries 展平，也不能为隐藏内容额外挂载全部 DOM。
- 展示采用现有 HeroUI v3：fork 使用 `Button` 的 `secondary` 语义，进行中反馈复用 `isPending` 与小型 `Spinner`；错误与恢复使用已有 `Alert` 和按钮模式。使用现有 surface、foreground、muted、separator 与 danger 语义 token，不新增硬编码配色。
- 用户文案经现有 Lingui 链路维护。按钮应明确表达“从此处分叉到新会话”，并能通过键盘操作；具体翻译按项目文案与翻译流程生成。

### 创建、激活与导航

- 将一次操作绑定到来源 thread、所选 turn 和当前连接身份。点击后保留该明确意图，不跟随原会话后续输出改变 fork 点。
- 依次创建新 thread、复用现有会话集合激活新 thread、导航至其当前聊天页。将历史预览中的 fork 目标与当前工作的 thread 区分，不能错误地 fork 当前工作的其他会话。
- 现有会话集合维护多个成员，选择新会话不要求移除原会话。fork 路径不调用原会话的 interrupt、remove 或关闭操作。
- 原会话的后续事件继续归原 thread；新会话输入经现有激活身份和输入归属检查发送，不能通过页面局部替换 thread ID 绕过这些检查。
- 原有连接、projection、输入恢复与会话激活检查继续有效。允许父会话正在生成，不意味着绕过其他已有恢复条件。
- 不将创建流程耦合到新建会话的首次消息发送动作；fork 创建后等待用户输入。

### 失败与异步一致性

- 进行中阻止同一操作的重复提交，并呈现明确反馈。
- 明确创建失败时显示错误，保留来源上下文；服务端拒绝所选边界时不偷偷选择另一个 turn。
- 创建成功后保留新 thread ID。后续激活或导航失败的重试复用该 ID，只恢复尚未完成的阶段，不再发送创建请求。
- 沿用网关对 `definitelyNotAccepted` 与 `deliveryUnknown` 的区分。结果未知时不能当作未创建而自动重发，不增加伪幂等保证。此时提示先到历史记录检查，不增加本次请求的专门重试按钮；用户仍可再次点击原 fork 入口，发起新的创建请求，上一次实际成功时可能产生额外会话。
- 用户离开页面、来源切换或连接更换后，旧响应不得把用户强制拉到过期目标。已知成功创建的会话仍保留，不能把局部请求取消解释为后端已撤销创建。
- 复用现有失败与重试展示模式，避免引入平行的会话恢复系统。已有新 thread ID 时提供可访问的继续打开入口，恢复激活或导航；没有 ID 的未知结果不承诺关联找回本次创建。

## 测试决策

优先从用户点击页面入口到新会话展示及发送对象的完整链路验证。测试外部行为和请求契约，不断言内部 helper、effect 或 reducer 的组织形式。尽量复用现有页面测试入口，不为 fork 创建另一套测试框架。

主要测试边界如下，随本设计审阅，尚未单独确认或执行：

- GUI 页面级 Browser 测试：复用当前聊天与历史预览的应用挂载、路由、GUI-host 测试支持和 projection fixtures。现有 `AppNewSession`、`ThreadHistoryDetailContinuation` 提供创建、激活、失败重试与导航先例；`UrlTurnPosition` 提供跨页与末尾 fragment 先例。
- Rust GUI-host 的现有请求过滤和转发契约：验证 `thread/fork` 可经实际 GUI 接入路径到达 app-server，既有过滤约束继续有效。
- 现有 app-server `thread_fork` 公共 JSON-RPC 集成测试：复用已存在的 terminal prefix 和进行中边界拒绝案例；只有现有覆盖不能证明本次行为时才补充相应场景。
- 权威生成产物：按项目生成与检查入口验证前端类型、请求描述与运行时校验来自同一 Rust 协议，不以手写 fixture 代替契约一致性检查。

页面验收覆盖：

1. 当前聊天和历史预览均传入准确的来源 `threadId` 与所选 `lastTurnId`，不发送 `beforeTurnId`。
2. 选择正常完成、失败或中断 turn 均可 fork；进行中的 turn 无可执行入口。
3. 选择较早 turn 时，新会话包含该 turn 且没有后续历史；不能仅验证发出了请求。
4. 来源有正在生成的后续 turn 时操作仍可执行，父会话继续接收输出，未收到本功能发出的 interrupt 或 remove。
5. 成功后新 thread 被激活，路由指向新会话，后续用户输入发送到新 thread；原会话仍可访问。
6. 历史预览的来源不同于当前工作 thread 时，fork 仍使用预览来源；原工作 thread 的草稿与待发送输入不转移。
7. 模型参数不额外覆盖，工作目录继承来源；真实生效结果由后端契约或运行时证据验证。
8. 跨 context page 的 turn 只在其末尾呈现入口；现有已展示但没有最终回答的失败或中断 turn 仍可操作；现有展示规则不变。
9. 创建进行中重复点击不产生重复请求；创建后激活或导航失败的恢复不再创建第二个 thread。
10. 断线、结果未知、页面离开及旧响应返回均保留现有归属和恢复检查，不自动重发未知请求或劫持新导航。结果未知时提示检查历史、没有专门重试按钮；再次点击原入口作为新创建处理。
11. 键盘操作、进行中反馈和错误反馈可访问，窄视口下入口不遮挡正文或输入区域。

后续验证使用项目规定的定向测试、类型检查、lint 与生成检查。真实运行时还需核验持久化后的截断历史、父会话持续生成及新会话发送对象；Browser 模拟结果不能替代这些证据。本次只有源码核验，没有运行测试、构建或 GUI 验收。

## 范围外

- 对现有未展示 turn 新增展示、分页、定位或内容检测逻辑。
- 从聊天最新位置直接 fork，或在未选择具体已结束 turn 时自动选择最新边界。
- 从 turn 开始之前 fork、编辑并恢复历史 prompt、任意 item 级 fork。
- “从聊天中继续”来源入口、回跳父会话、来源分界恢复、children 搜索、fork 关系图。
- 模型选择界面、恢复历史 turn 当时模型、选择其他工作目录、创建或切换 worktree。
- 文件系统快照、回滚或复制；共享目录不提供两会话文件修改隔离。
- 自动复制并发送草稿、自动重放用户输入、额外启动 goal。
- 新增 fork 持久化格式、任意 Rust 分叉粒度、修改 TUI 的既有行为。
- 本轮编写实施计划、修改产品代码、运行验证、暂存或提交、发布远程 issue。

## 补充说明

### 与 TUI 的关系

TUI 普通 `/fork` 使用最新位置，生成期间禁用；历史 prompt 编辑使用 `beforeTurnId`，排除所选 turn，并把 prompt 放回输入框。两条路径成功后切换新会话。

本设计与 TUI 在成功后切换以及历史选择校验排除 `inProgress` 上相符；分叉位置和父会话生成期间的可用性遵循本次 GUI 的明确决策。所需的 `lastTurnId` 已由 Rust 支持，不能把“与 TUI UI 不同”推导成必须新增分叉协议。

### 已知证据与计划前核查

已通过源码确认：Rust `lastTurnId` 包含所选已结束 turn；GUI-host 尚未放行该方法；当前 GUI 新建会话没有额外模型参数；共享 transcript 具有末尾 fragment 映射；会话集合可保留多个成员；现有创建及历史继续操作区分激活和导航失败。

计划拆分阶段补充确认：仅在现有已展示且已结束的 turn 提供按钮，不新增空内容判断；结果未知选择提示先检查历史，不提供专门重试按钮，用户可再次点击原入口发起新请求。

形成实施计划前仍需完整闭合：权威生成链的全部输入输出、已知创建 ID 的恢复入口与生命周期，以及两种历史存储模式在所需场景下的现有测试覆盖。若发现需要改变产品结果或协议能力，应报告具体差异，不以静默降级填补。

本规格采用 `to-spec` 的结构。用户当前请求为本地“落盘设计”，因此只创建此设计文件。未提供本任务的 issue tracker 与 triage 标签配置；若后续需要该 skill 的远程发布流程，请先运行 `/setup-matt-pocock-skills`，并另行明确发布范围。
