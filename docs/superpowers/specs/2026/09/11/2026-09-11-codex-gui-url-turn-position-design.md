# Codex GUI URL 定位到 turn 结尾：设计规格

日期：2026-09-11

状态：设计已落盘，待审阅；未进入计划或实现。本文按 `to-spec` 汇总已确认行为与当前源码证据，不重新访谈。未决行为单独列出，不冒充用户确认。

决策依据：[URL 定位决策记录](../../../../research/2026/09/11/2026-09-11-codex-gui-url-turn-position-decisions.md)。旧记录保留为阶段历史；本次“落盘设计”更新了其“先不设计”的阶段限制。

## 问题陈述

用户需要通过链接回到聊天中的指定 turn，阅读该轮结束时的上下文。只打开聊天最新位置会丢失链接所指的位置；只定位到 turn 开头也不符合从该轮末尾继续阅读的需求。

当前聊天页和历史预览页都需要该能力，且保留各自原有会话行为。此前的 fork 来源入口任务仍停止，本设计仅提供其可能使用的 URL 定位基础能力。

## 解决方案

当前聊天页使用 `/task/<threadId>?turnId=<turnId>&position=end`；历史预览页使用 `/history/<threadId>?turnId=<turnId>&position=end`。

页面取得完整历史后，查找指定 turn，切换到其结尾所在展示页，待目标渲染后将其结尾放在视口底部附近，避开输入框等遮挡。每次打开或刷新执行一次，完成后保留参数并恢复页面原有滚动行为。

完整历史中不存在目标时，显示该聊天最新位置，并给出含义为“未找到指定对话轮次”的临时提示。未加载完成或读取失败不能据此判定目标不存在。

## 用户故事

1. 作为当前聊天的使用者，我希望打开带 `turnId` 的链接后看到指定轮次的结尾，以便接着阅读该处上下文。
2. 作为历史记录的阅读者，我希望历史预览也支持同样的链接，以便查看指定位置。
3. 作为历史记录的阅读者，我希望定位保持预览页原有行为，以便阅读时不因定位而激活来源聊天。
4. 作为长聊天的阅读者，我希望自动切换到目标所在展示页，以便无需手动翻页。
5. 作为阅读跨页轮次的用户，我希望定位到该轮最后一个片段，以便看到真正的轮次结尾。
6. 作为用户，我希望结尾不被输入框遮挡，以便直接阅读目标内容。
7. 作为用户，我希望页面等待完整历史就绪后再判断目标是否存在，以免出现错误提示。
8. 作为用户，我希望找不到轮次时仍能看到聊天最新位置，并获得临时提示，以便理解未定位的原因。
9. 作为用户，我希望刷新链接后重新定位，以便恢复链接表达的位置。
10. 作为用户，我希望地址栏保留定位参数，以便再次打开时保持相同意图。
11. 作为用户，我希望定位完成后仍能自由滚动和翻页，以便继续阅读其他内容。
12. 作为阅读持续输出轮次的用户，我希望 URL 只负责一次定位，之后遵循原有滚动行为，以免定位逻辑反复拉回视口。
13. 作为用户，我希望没有定位参数的链接保持原有行为，以便既有使用方式不受影响。

## 实现决策

以下区分已确认契约与依据当前源码提出的接入设计。接入设计不代表已实现。

### URL 契约与路由边界

- 使用 TanStack Router 的 search 解析与校验，将定位意图纳入当前聊天和历史详情的路由目标。`threadId` 仍由路径表达；`turnId` 与 `position` 由查询参数表达。
- 第一版仅支持 `position=end`，不引入 hash 定位解析器。
- 当前根路由的 `validateEmptyRouteSearch` 拒绝所有查询参数；接入时需要调整校验归属，让支持定位的两个详情路由可以接收其参数，同时保留其他页面原有参数约束，不能简单删除全部校验。
- `GuiRouteTarget` 当前只携带页面类型和聊天 ID，需要能向页面传递定位意图。解析后只保留一个权威来源，不另建读取地址栏的平行状态。
- 不把 URL 中的 `turnId` 当作 DOM 已存在的证据，也不从列表或当前展示页缺少目标推导轮次不存在。

### 历史与展示边界

- 复用现有完整历史读取：历史预览使用 `thread/read(includeTurns: true)`，当前聊天使用 projection 完整历史快照和后续增量；不新增网络延迟加载机制。
- 复用 Transcript State 的 turn、turn fragment 与 context page 关系。一个 turn 可以存在多个片段，`position=end` 选择该 turn 的最后一个片段所在页。
- 当前共享 transcript renderer 内部拥有展示页选择状态。定位与手动分页应使用同一个页选择入口，避免页面和 renderer 各维护一份当前页。
- 目标页渲染前保持定位待处理，不能因为目标 DOM 暂时不存在就退到最新位置。为 turn 结尾提供可测量的渲染边界，包括没有最终 assistant 消息但存在该 turn 的情形；不把结尾限定为最后一条 assistant 文本。

### 定位生命周期与滚动边界

- 一次定位依次等待完整历史、解析目标所在页、等待目标渲染、执行结尾对齐，然后结束。页面离开后不允许旧定位请求影响新页面。
- 页内重渲染、projection 增量或普通状态刷新不能重新触发已完成的定位。重新打开或刷新应产生新的定位机会。
- 一次定位期间需要协调页面原有初始化滚动与目标滚动，防止刚定位就被默认滚动覆盖；结束后交还原有滚动控制，不新增持续跟随目标的策略。
- 对齐依据实际可用阅读区域与遮挡边界计算。不能仅把目标元素贴齐浏览器底边而忽略输入框。
- 定位参数保留在 URL，不写入聊天持久化数据。当前已确认能力的设计使用现有前端数据，不提出新增 Rust 协议或持久化字段；完整入口验证仍需在后续计划前完成。

### 失败与缺失

- 仅在完整数据就绪且确实没有该 turn 时，执行“最新位置 + 临时提示”。
- 会话不可读取、连接中断或页面读取失败继续由现有错误与重试流程处理，不伪装成目标 turn 不存在。
- 参数异常属于未决契约，见后文。本文不擅自为非法输入指定静默忽略、默认 `end` 或提示行为。

## 测试决策

优先从完整页面的 URL 输入验证最终展示与滚动结果，复用既有 App Browser 测试入口及 GUI host 测试支持。仅在页面级测试无法清晰覆盖参数组合时补充已有路由校验测试，不为此创建另一套测试框架。

现有先例包括 `AppProjectionScroll` 的文档滚动测试、`TranscriptContextPagination` 的展示页切换和只读快照测试，以及 `guiRouteTarget` 的路由校验测试。这些入口已通过只读源码核对；本次未执行测试。

验收关注用户可观察的结果，不断言内部 effect 调用次数或辅助状态字段：

- 两类页面通过合法 URL 显示目标结尾；跨展示页和跨片段 turn 均选择正确位置。
- 目标结尾实际处于可读区域，没有被输入框覆盖；窄视口也验证几何结果。
- 完整历史未就绪时不出现缺失提示；完整历史确认不存在后显示最新位置和临时提示。
- 读取失败保持原有错误与重试行为，不显示错误的“轮次不存在”。
- 刷新或重新打开执行定位，地址栏参数保留；定位后手动滚动、翻页和接收增量不被 URL 逻辑反复打断。
- 不带参数时保留既有页面、分页与滚动行为；历史预览定位不额外激活聊天。
- 路由切换后，旧页面尚未完成的定位不能滚动新页面。

上述为设计中的测试范围，随本规格审阅；不是已经执行或单独确认的测试结果。真实运行时的直接打开与刷新还需验证入口能保留查询参数，Browser 测试不能替代该证据。

## 补充说明

实施前用户补充确认：缺少其中一个定位参数、空值、重复参数、未知 `position` 和其他非法参数均拒绝链接，沿用现有错误页，不自动补值。同页切换定位参数、浏览器前进或后退均按一次新导航重新定位；普通重渲染与持续输出不触发。两项选择均为 A。

当前证据已确认路由拒绝查询参数、路由目标缺少定位字段、共享 renderer 拥有分页状态及最后 turn fragment 映射。完整滚动 owner 协调、应用启动时查询参数保留和真实刷新链路尚未完成纵向核验。以上缺口应在形成可执行计划前闭合；本文不宣称已达到直接实施条件。
