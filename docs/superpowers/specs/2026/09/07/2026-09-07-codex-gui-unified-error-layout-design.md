## 1. 目标与边界

统一 Codex GUI 全部报错的布局规则，保留页面、消息流、弹层、菜单及内联提示各自的载体。诊断入口的位置不因是否存在重试按钮而变化。

本设计区分两个区域：诊断属于错误内容，重试属于处理错误的操作。宽屏将操作区放在内容区右侧，小屏将操作区移到完整内容区下方，内容区内部顺序始终保持。

本次不要求将全部提示改成同一种大卡片。现有错误文案、诊断数据、按钮是否存在、禁用条件、调用逻辑、错误归属和状态生命周期继续由各功能负责。布局统一不自动授权将目前直接显示的错误文本移入诊断弹窗，也不为原本没有诊断或重试的提示新增入口。

## 3. 统一布局合同

### 内容区

内容依次排列：标题、错误说明、查看诊断信息。原本没有标题、说明或诊断的紧凑提示只渲染已有内容，不制造占位或重复文案。

诊断入口位于说明下方、与内容左对齐；它始终属于内容区。无重试按钮时，诊断仍保持此位置，不能占用右侧操作区。原本没有诊断数据的提示，不因统一布局出现空诊断按钮。

### 操作区

重试或其他已有的错误处理动作属于操作区。重试按钮是否显示、何时禁用、点击后的行为，继续服从所在功能的现有规则。本设计不新增名为“恢复”的按钮。

| 场景 | 内容区 | 操作区 |
| --- | --- | --- |
| 宽屏，诊断与重试均存在 | 左侧：标题 → 说明 → 诊断 | 右侧：重试，与内容顶部对齐 |
| 小屏，诊断与重试均存在 | 上方：标题 → 说明 → 诊断 | 完整内容区下方：重试，左对齐 |
| 只有诊断 | 标题 → 说明 → 诊断 | 不渲染、不预留空位 |
| 只有重试 | 标题 → 说明 | 宽屏右侧，小屏内容下方 |
| 均不存在 | 保留已有错误内容 | 不渲染 |

小屏完整阅读顺序必须是：**标题 → 说明 → 查看诊断信息 → 重试**。不得先排列重试再放诊断，也不得把诊断与重试合成一排后依赖偶然换行决定顺序。

“位置稳定”指区域归属和相对顺序稳定，不要求固定屏幕坐标；说明变长、字体缩放或按钮消失引起的自然高度变化是正常排版。

### 紧凑载体

菜单、Popover、Drawer 内的错误仍留在原上下文。空间充足时可将已有操作放在内容右侧；空间不足时操作放到完整内容之后。应依据载体可用空间避免挤压，而不能因页面视口宽就强行保持狭窄弹层的双列。

没有按钮的内联提示无需增加操作区。与提示关联的现有编辑器或工具栏控件不因本设计迁入错误容器；本轮调整错误呈现及其自带操作，不改造整个编辑器或工具栏结构。

## 4. 覆盖入口与实现约束

实施计划须逐项核对以下已发现的入口，记录需要调整或已经符合的结论，不按是否使用 `Alert` 筛掉紧凑提示：

- 全局及当前任务：`AppShell`、`CurrentTaskPage`。
- 历史：`ContinueTaskFailureAlert`、`ThreadHistoryListPage`、`ThreadHistoryDetailContent`、`ContinueTaskAction` 中的失败 Toast。
- 消息流：`CommittedTranscriptTurnFragment`、`CommittedTranscriptSurfaceRenderer`。
- 编辑器及队列：`ComposerPersistenceStatus`、`ComposerPendingInputEditor`、`ComposerPendingInputDrawer`、`ComposerTurnControl`、`ContextUsagePopover`。
- 技能与其他载体：`SkillTypeaheadPlugin`、`SelectedSkillToken`、`NotFoundPage`。

已有错误相关警告保留其严重性，不将 warning 改为 danger；普通成功、加载及信息提示不因组件相同而纳入错误重设计。

卡片继续使用 HeroUI `Alert`、`Alert.Indicator`、`Alert.Content`、`Alert.Title`、`Alert.Description`，诊断沿用 `Button variant="secondary"` 与 `FailureDiagnosticModal` 的 `Modal` 组合。重试等按钮按既有操作语义保留 variant，不照抄示例颜色覆盖项目动作语义。沿用 surface、foreground、muted、danger 等主题 token，不硬编码颜色。

可提取最小的纯展示布局以统一区域及顺序；布局组合不接管错误解释、重试策略、状态清除、持久化或消息归属。紧凑载体复用同一布局原则，不强制套用卡片外壳。协议类型、运行时校验及持久化格式不变。

内容和操作应各自保持一个权威渲染来源，优先通过布局响应式变化实现，避免为宽窄屏复制有状态操作或诊断弹窗。键盘焦点顺序应与内容先于操作的阅读顺序一致。
