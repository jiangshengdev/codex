# Codex GUI 新建会话设计

日期：2026-09-07。

状态：设计已获用户确认；本文创建已获授权。尚未编写或确认实施计划，尚未实施或验证本功能。

## 目标与范围

让 GUI 支持新建会话，接入当前多会话模型。本文以当前源码和本次重新确认的产品决策为依据，替代此前对单活动会话切换流程的设计假设。

本次包含导航菜单入口、未创建会话的编辑页、创建及首发衔接、失败恢复，以及 GUI host 对现有创建接口的放行。不增加目录选择器、模型或权限设置页、多目录草稿集合、后端创建去重或自动找回能力。

## 当前实现与设计依据

- `codex-gui/src/features/appShell/AppShellTopBar.tsx` 已包含导航抽屉和多会话列表，尚无新建入口。
- `codex-gui/src/features/browserLaunch/guiRouteTarget.ts` 当前只有当前任务、历史列表和历史详情路由。未创建的草稿不能伪装成已有 `threadId`。
- `codex-gui/src/features/activeThreadSession/activeThreadSession.ts` 的 `selectThread` 保留旧成员并切换查看对象；`removeMember` 才检查运行、队列和恢复等移出限制。新建不应重新引入旧式切换阻塞。
- 同一文件的 `initialize` 已分页查询 `thread/loaded/list`：已加载则直接 `thread/projection/attach`，完整查询未找到才 `thread/resume` 后 attach。新建接入这条现有链路，不要求新会话先有持久化历史。
- `codex-gui/src/features/browserLaunch/browserAuthorizationSession.ts` 保存 `historyCwd`；移除当前会话仅清除活动 ID，保留目录。`ThreadHistoryListPage.tsx` 据此读取历史。
- 历史列表请求按 `cwd` 筛选，但活动成员集合按 `threadId` 保存，没有同目录约束。GUI 没有目录选择入口，不代表所有已激活会话来自同一目录。
- app-server 已实现 `thread/start`。`codex-rs/gui-host/src/filter.rs` 尚未允许该请求，前端 `APP_SERVER_REQUEST_METHODS` 也尚未选择该方法。
- `ThreadStartParams` 未提供创建去重标识。创建已完成但响应丢失时，前端不能仅凭原请求可靠找回同一次创建。

以上为源码核验，不代表本次执行过测试或真实 GUI 验收。其他设计文件中的历史状态不覆盖当前源码事实。

## 已确认的产品行为

### 入口与创建时机

“新建会话”位于导航菜单。点击后进入空白编辑页，不立即创建后端会话，不把草稿加入已激活会话列表。

发送首条消息时才请求创建。取得会话 ID 后接入已有多会话初始化和输入发送流程，进入新会话。未发送就离开，不因浏览或编辑产生后端会话。

### 目录与默认配置

没有既存新建草稿时，采用当前会话的工作目录。没有当前会话时，使用界面保留的历史目录；没有可用目录信息则不可新建，不猜测服务器或进程默认目录。

草稿一旦建立就绑定该目录，并在新建页显示所属目录。后续切换到其他目录的会话，不改变该草稿的目录。

创建使用草稿所属目录下生效的 Codex 默认配置，不复制旧会话的临时模型、推理强度或权限调整，也不在新建页增加设置控件。

### 单份新建草稿

整个浏览器标签页只保留一份新建草稿。再次点击“新建会话”时恢复它，并显示原目录，即使当前查看的会话已属于其他目录。

新建草稿在同一标签页的页面切换期间保留；刷新或关闭标签页后不保留。不按目录建立多份草稿，不覆盖旧草稿以适配当前目录。

新建草稿与已有会话的持久化草稿是不同生命周期。取得会话 ID 并完成输入归属交接后，使用现有按会话隔离的草稿、队列和恢复机制，不以新建草稿的短生命周期削弱已有会话的恢复能力。

### 多会话运行

新会话加入当前多会话集合，旧会话继续保留，后台生成和队列继续运行。

旧会话的排队消息、待恢复输入等不阻止新建或切换查看；它们继续约束移出会话。新建流程不得释放旧会话、取消其投影或隐式中断它。

## 创建、首发与失败边界

创建操作与首条消息发送分开确认，不能把 RPC 已发出当作创建成功，也不能把连接断开当作创建未发生。

| 状态或结果 | 行为 |
| --- | --- |
| 仅编辑，尚未发送 | 仅保留标签页内草稿，无后端会话 |
| 创建请求处理中 | 防止重复提交同一草稿，保留输入 |
| 已明确创建失败 | 展示错误、保留输入，允许用户重试 |
| 创建结果未知，尚未取得 ID | 展示结果未知、保留输入；不自动重试，由用户主动重试，并说明可能留下额外空会话 |
| 已取得 ID，初始化或首发失败 | 保留会话身份和输入；后续操作复用该会话，不再次调用创建接口 |
| 首发结果未知 | 进入现有会话的未知投递和恢复流程，不自动重发消息 |
| 输入已由现有会话接管 | 结束新建草稿职责，后续输入由该会话的草稿和队列管理 |

只有创建成功取得 ID 后才发送首条消息。因此创建阶段的结果未知与重试可能产生额外空会话，但不应在该阶段重复发送用户消息。此限制不等于整个首发流程具有后端幂等保证。

输入归属交接必须有一个权威来源：确认目标会话已接管前不能丢弃输入；交接后不能留下可再次提交的平行新建草稿。具体复用方式在实施计划中闭合，不新增通用兼容层或双写流程。

新建页继续使用当前错误展示方式，保留原始错误的可查看路径；不改造全局错误体系。异步结果必须遵守当前连接和会话生命周期检查，过期操作不能向错误会话提交消息。

## 模块与权威契约

- 导航与路由：在现有导航抽屉添加入口，为尚无 `threadId` 的编辑状态提供独立路由语义。使用项目 HeroUI v3 组件及现有编辑器能力，具体组件与路由字面量在计划中确定。
- 新建草稿：负责单份草稿、固定目录、创建中的状态及已取得的会话 ID，不承担已有会话的运行或队列管理。
- 会话集合：复用现有激活、已加载查询、投影连接、成员隔离和后台运行流程。不创建第二套会话管理器。
- 协议入口：前端选择 `thread/start`，通过现有 command gateway 请求，GUI host 允许该请求。成功响应提供 ID，不因新建功能机械放行无人消费的 `thread/started` 通知。
- 类型权威来源：`codex-rs/app-server-protocol/src/protocol/v2/thread.rs` 与生成的 `codex-rs/app-server-protocol/schema/typescript/**`。前端通过既有 `RequestParams`、`RequestResponse` 派生，不手写重复 DTO。
- 响应校验：使用现有 schema 和 `codex-gui/scripts/protocolValidators/cli.ts` 生成前端校验产物，不手写创建响应校验器。
- 路由契约：既有浏览器契约来源为 `codex-rs/gui-host/schema/typescript/browserContract.ts`。新增路由须同时核对前端匹配与 host 深链接处理，不仅修改菜单。

## 验证要求

实施计划须覆盖以下可观察行为：

- 菜单入口、空白编辑、首发才创建，以及未发送离开不创建。
- 当前目录、无当前会话时保留目录、缺少目录时不可新建。
- 从目录 X 的草稿切到目录 Y 的会话后，再次新建仍恢复唯一的 X 草稿，显示 X，创建请求使用 X。
- 页面切换保留新建草稿，刷新不保留；已有会话的持久化恢复语义保持不变。
- 旧会话运行、排队或待恢复时仍可新建，后台数据与新会话隔离，移出保护保留。
- 创建期间重复点击、明确失败、结果未知后的用户重试，以及已取得 ID 后失败重试不重复创建。
- 新会话尚无持久化历史时仍能初始化并首发；消息未知投递不自动重放。
- 路由重载、连接失效和输入交接不丢失或错投到其他会话；检查适用的真实加载前提。
- 协议类型、生成校验和 host 放行链路一致；用户文案遵循现有 Lingui 流程。

验收分层：Level 1 为相关自动化回归；Level 2 为无头真实 Codex runtime 下的新建、首发及多会话运行验收；本设计不依赖可见桌面，Level 3 不适用。当前各项均未执行。具体命令、前置状态及范围在实施计划中核验，不能把 mock 或静态证据作为真实 runtime 验收。
