## 唯一主目标

修正本机提示词治理，使已确认计划在执行中出现不可恢复失败时立即冻结全部后续操作并原样保护现场；全局系统提示词只保留简洁硬规则，详细判定、冻结和解除冻结协议下沉到唯一 owning skill，前端提示词仅在存在前端专属差异时修改。

本设计只定义计划执行失败的分类、冻结语义、重新授权条件和规则 owner。它不是 implementation plan，不定义任务调度、提交顺序或实施命令，也不授权修改任何提示词或 skill。

## 保证边界

本方案属于提示词层治理，只能降低模型在计划失败后错误续跑、清理、恢复或覆盖现场的概率。它不提供工具调用前的 capability enforcement，也不能保证已经运行的外部进程一定可以无损取消。

规则必须优先保护现有工作与证据，不能把“恢复干净工作树”“释放资源”“完成失败域外节点”或“生成更完整报告”解释成失败后的继续操作理由。

## 已确认设计决策

### 只有不可恢复失败触发全局冻结

普通小错误不触发全局冻结。一个失败只有同时满足以下全部条件时才属于可恢复失败：

- 根因已经明确，不需要新增调查或猜测；
- 修正仍处于已确认计划的目标、文件、行为、风险和授权边界内；
- 修正不会删除、恢复、覆盖、回滚或丢弃现有工作与证据；
- 修正后仍能通过原定权威入口重新验证；
- 失败没有推翻计划前提、命令入口、基线、执行图或完成证据。

任一条件不成立，即为不可恢复失败，必须立即冻结整个计划执行。

若某节点预先声明的完成条件本身是获得预期失败，例如 TDD 红灯、负向验证或故障注入，且实际结果精确满足该完成条件，则该节点是成功，不属于计划执行失败。未被预先声明为完成条件的非零退出、断言失败或异常不能事后改称“预期失败”。

### 不可恢复失败冻结整个计划而不是局部失败域

识别到不可恢复失败后，旧执行图、全部节点能力信封和计划授予的后续动作立即冻结。不得再启动任何新的：

- 工具调用、命令、节点、子代理或验证；
- 只读状态检查、补充调查或为了完善报告而进行的读取；
- 修复、重试、清理、恢复、回滚、删除、覆盖或基线修改；
- 格式化、生成、stage、commit、集成或其他收尾动作；
- 失败域外、无依赖或此前已经 ready 的节点。

冻结规则显式覆盖“计划确认后连续完成”“计划内失败直接闭环”“失败只暂停传递后继”“继续耗尽失败域外 ready/running 节点”等一般规则。

### 在途操作只采用安全停止语义

冻结发生时，不再调度新操作。对已经运行的操作：

- 工具明确提供安全取消语义，且取消不会造成额外写入、半写状态或证据丢失时，可以安全取消；
- 无法证明取消安全时，不追加中断、清理或控制操作，让当前调用自然返回；
- 当前调用返回后，不基于其结果继续任何检查或收尾；
- 不得为了“保护现场”而执行未经重新授权的恢复、回滚或删除。

向用户报告时，只能使用冻结前和当前调用自然返回时已经取得的信息。不得为报告再次读取文件、Git 状态、日志、进程、子代理状态或其他现场。

### 解除冻结必须获得新的精确用户授权

失败报告交付后，旧计划及其授权保持冻结。只有用户在看到失败报告后明确指定新的动作和范围，才能局部解除对应能力，例如：

- 只读检查指定 diff；
- 重新运行指定命令；
- 修改或恢复指定文件。

“继续”“重试”“处理一下”“按原计划走”等笼统表达不能恢复旧计划、重新激活执行图或授权任何现场操作。新的精确授权只覆盖用户指定的动作和范围，不自动解冻其他节点。

## 根因与 owner 分层

### 当前规则缺口

当前全局 `AGENTS.md` 要求计划确认后连续闭环，并把节点失败、失败范围和重新调度交给执行图处理。执行图又要求节点失败后重算 ready set、继续失败域外节点并在终态前耗尽仍获授权的工作。这套局部失败语义没有不可恢复失败的全局熔断。

本次事故中的诊断计划进一步把 `RESTORE` 建模为 Browser 成功或失败后都必须运行的节点，并预先授权 `git restore` 丢弃两个临时源码 diff。实际 Browser 基础设施失败已经推翻命令入口和完成证据，属于不可恢复失败；执行仍按局部失败分支运行 `RESTORE`，破坏了诊断现场。

现有 `managing-work-stages/references/read-only-and-exceptions.md` 已规定调查期诊断测试应持续保留到正式修复阶段，但该生命周期约束没有覆盖执行图的失败后调度，形成规则冲突。

### 全局 `AGENTS.md`

`/Users/jiangsheng/cnb/codex-config/AGENTS.md` 是简洁硬规则 owner，同时是 `/Users/jiangsheng/.codex/AGENTS.md` 的 canonical target。

全局文件只应增加一条结果级不变量：已确认计划执行中出现不可恢复失败时，立即冻结整个计划和全部后续操作，保护现场，并且只有用户对新动作和范围作出精确授权后才能局部解除冻结。

全局文件不得复制五项可恢复条件、执行图状态机、在途取消算法或失败案例。现有连续闭环、局部失败和计划内修正规则必须明确受该硬熔断覆盖。

### `delegating-micro-stages` 执行图

`skills/delegating-micro-stages/references/execution-graph.md` 是已落盘计划执行期节点状态、动态调度、失败域和终态行为的唯一详细 owner，负责承载：

- 五项可恢复失败判定；
- 不可恢复失败的全图冻结状态；
- 冻结对 ready、running、等待和失败域外节点的影响；
- 禁止新增工具、检查、清理、恢复、修正插图和提交；
- 在途操作的安全取消与自然返回边界；
- 仅用已有信息报告的约束；
- 用户精确新授权后的局部解冻和旧计划不自动复活。

现有“失败后立即重算并启动 ready 节点”“失败域外继续”“自动插入修正节点”和“终态前耗尽失败域外工作”只保留给满足全部五项条件的可恢复失败；不可恢复失败必须在这些规则之前短路。

### `managing-work-stages` 与普通委派契约

以下 reference 只消除冲突或路由到执行图 owner，不复制完整冻结算法：

- `skills/managing-work-stages/references/stage-gates.md`：连续完成与计划内修正只适用于可恢复失败；不可恢复失败路由到执行图冻结。
- `skills/managing-work-stages/references/read-only-and-exceptions.md`：计划内失败直接闭环只适用于可恢复失败；保留并强化既有诊断测试生命周期。

- `skills/delegating-micro-stages/references/delegation-contract.md`：普通调研委派仍可保持局部失败语义；执行已落盘计划时必须服从执行图的不可恢复失败熔断。

## 风险与控制

### 把普通小错误误判为不可恢复失败

控制：可恢复必须同时满足五项条件；普通计划内类型、lint、断言或格式问题在根因明确、边界不变、不破坏现场且原入口仍有效时可以继续闭环。

### 模型凭主观判断绕过冻结

控制：禁止使用“看起来可修”“风险较低”“清理更安全”等启发式判断；任一可恢复条件不能证明即冻结。

### 冻结后借只读检查继续操作

控制：冻结覆盖所有新工具调用，包括只读检查。报告只能使用已经取得的信息。

### 强制中断造成第二次损害

控制：只有明确安全的取消语义才允许取消；否则让当前调用自然返回，不追加控制动作。

### 通用规则污染前端或普通调研

控制：不修改前端 `AGENTS.md`；普通调研与非计划委派保留现有局部失败语义，只有已落盘计划执行进入不可恢复失败时触发全图冻结。

### 详细算法复制到全局提示词

控制：全局只保留结果级熔断；详细条件、状态机和解除冻结协议全部由执行图 reference 拥有。

- 任一计划执行失败若不满足全部五项可恢复条件，立即触发本设计定义的冻结；不得以计划内 cleanup 或恢复节点绕过。

## 设计结论

目标结构是一条简洁的全局不可恢复失败熔断、一个详细的执行图 owner，以及四处只负责消除冲突或路由的辅助 reference。普通小错误仍可在原边界内闭环；一旦失败推翻计划前提、入口、基线、执行图或完成证据，或者修正需要新增调查、扩大边界或破坏现场，整个计划立即冻结，直到用户对新的精确动作和范围重新授权。
