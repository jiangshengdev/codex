# Codex GUI 对 `rust-v0.150.1` 协议扩展的适配设计

日期：2026-08-28

状态：已确认

设计分支：`dev`

设计时 HEAD：`d3cc01440`

关联 research：

- `docs/superpowers/research/2026/08/28/2026-08-28-codex-gui-v0.150.1-protocol-adaptation.md`

## 唯一主目标

适配 `rust-v0.150.1` 已经进入 GUI 的 app-server v2 权威协议变化，消除当前 19 条
TypeScript build error，同时保留协议的编译期失败传播、现有 transcript 单一状态所有权和
追加式历史语义。

本设计采用用户已确认的产品语义：成功完成子代理任务时，新增独立的
`Completed <agent>` 活动展示，不回溯更新或重写此前的 `Started` 活动。

## 背景与根因

19 条 TypeScript error 去重后是 9 个唯一错误位置，归并为三组：

1. `CollabAgentTool` 新增 `sendMessage`、`followupTask`、`interruptAgent`、
   `listAgents`，但 GUI 的 started/completed policy 尚未明确处理它们。
2. `SubAgentActivityKind` 新增 `completed`，但 frontend-owned activity title union、selector
   与 surface 尚无对应展示语义。
3. `SkillMetadata.pluginId` 已是必需但 nullable，四处合法测试 fixture 仍省略该字段。

生成的 TypeScript、JSON schema 和 GUI runtime validators 与 Rust 权威类型一致；
`protocol:check-validators` 已通过。因此根因不是生成物漂移，也不是 validator 缺失，而是 GUI
消费者尚未对新增协议成员作出完整、显式的适配。

## 目标

- 对四种当前没有 public `CollabAgentToolCall` producer 的新工具，在 started 和 completed
  transcript policy 中逐项显式返回 `ignore`。
- 为 `SubAgentActivityKind.completed` 增加独立的 frontend 展示语义和可翻译文案。
- 保持每个 `subAgentActivity` item 依据自身 item ID 进入 transcript；`completed` 不查找、替换或
  改写历史中的 `started` item。
- 在四处合法 `SkillMetadata` fixture 中显式写入 `pluginId: null`。
- 保留生成协议类型、`Extract`/`Exclude` 派生和所有 `never` 穷尽性检查，使未来协议变化继续在
  type-check/build 阶段失败。
- 使用现有 unit、Browser Mode 和 validator drift 入口验证受影响行为。

## 非目标

- 不修改 Rust protocol、app-server producer、projection ingress、history 或 rollout policy。
- 不修改任何 app-server TypeScript/JSON/precomputed schema 生成物。
- 不修改 GUI generated validators、generated descriptors 或 projection JSON fixture。
- 不让四种新 collaboration tool 在 GUI 中产生标题、详情、占位或隐藏兼容记录。
- 不把 `pluginId` 改成 optional，不给它增加默认值、旧字段别名或 runtime coercion。
- 不删除、放宽或绕过 `never`、typed method allowlist 或其他编译期契约检查。
- 不新增 frontend-owned 协议 DTO、literal union、schema、parser、fallback、adapter、双读或双写。
- 不改变 activity grouping、middle chunk、placement、scroll、reconnect 或 replay owner。
- 不增加子代理导航、liveness、完成结果详情或新的活动交互。

## 已确认的产品决策

### `completed` 使用独立追加式活动语义

用户已选择：`completed` 显示为独立的 `Completed <agent>` 活动，不回溯更新 `Started`。

这里的“独立”指生命周期语义和 transcript item identity 独立：

- `Started` 和 `Completed` 分别来自各自权威 `subAgentActivity` item；
- 每个 item 继续以 `(turnId, itemId)` 作为 presentation identity；
- completed item 在 projection 到达位置追加到 middle；
- 不跨 item 搜索相同 `agentThreadId` 或 `agentPath`；
- 不修改旧 entry 的 title、revision、chunk 位置或历史内容。

现有 surface 会把相邻、同 title kind 的多个 sub-agent activity 组合成一行 chips。该展示压缩
可以继续存在：`agentCompleted` 是区别于 `agentStarted` 的新 title kind，因此 Started 与
Completed 不会合并成同一行；多个相邻 Completed 可以沿用现有同类活动分组，但底层 transcript
entry 仍保持各自 identity 和顺序。

## 契约所有权与失败传播

### 单向权威链路

本次适配必须保持以下单向链路：

1. `codex-rs/app-server-protocol` 中的 Rust 类型和派生宏是唯一协议权威。
2. `schema/typescript/**`、`schema/json/**` 与 `schema/precomputed/**` 由权威类型机械生成。
3. GUI runtime validators/descriptors 从权威 JSON schema 机械生成。
4. GUI 生产消费者直接引用 `@codex-protocol/v2` 生成类型。
5. frontend-owned transcript model 只表达展示语义，并通过 `Extract`、`Exclude`、indexed access
   等机械类型变换持续依赖权威类型。

Ajv validator 只负责 wire runtime validation，不能替代 TypeScript compile-time contract。
兼容的未消费新增方法不需要人工制造失败；影响当前消费者的字段或 variant 变化必须继续在生成、
validator drift check、type-check、build 或穷尽 switch 中暴露。

### 精确禁止写集合

后续实现不得直接修改：

- `codex-rs/app-server-protocol/schema/typescript/**`
- `codex-rs/app-server-protocol/schema/json/**`
- `codex-rs/app-server-protocol/schema/precomputed/**`
- `codex-gui/src/generated/appServerProtocol/**`
- `codex-gui/src/features/projection/__fixtures__/*.json`

若实现中发现这些文件需要改变，说明当前根因判断或范围前提已经变化，必须停止并重新调查；不能
手改生成物来消除 diff 或类型错误。

## Collaboration tool policy 设计

### 当前 producer 边界

四种新增工具虽然已经进入 `CollabAgentTool` wire union，但当前运行语义是：

- `sendMessage`、`followupTask` 只产生 `SubAgentActivity(kind="interacted")`；
- `interruptAgent` 只产生 `SubAgentActivity(kind="interrupted")`；
- `listAgents` 不产生 public activity item；
- 四者的 `CollabAgentToolCall` 只进入 private analytics。

因此 GUI 不应为当前不存在的 public tool item 创造展示语义。若未来 producer 改为公开这些
`CollabAgentToolCall`，本设计的前提即失效，必须重新决定 present/ignore 语义。

### Started policy

`transcriptItemPolicy.ts` 的 `projectStartedCollabAgentItem` 继续是 started visibility owner。
它应逐项列出：

- `sendMessage`
- `followupTask`
- `interruptAgent`
- `listAgents`

并为每一项返回 `{ kind: "ignore" }`。不得使用 `default`、通配分支、字符串集合强转或提前
catch-all；switch 之后的 `never` 检查必须保留。

### Completed policy

`projectCompletedCollabAgentItem` 继续是 terminal visibility owner。四种新工具在所有非
`inProgress` 状态下也应逐项返回 `{ kind: "ignore" }`，不建立 stored entry，且不落入现有
`present` 结果。

这项处理只决定 tool visibility，不改变 `CollabAgentToolCallStatus` 的权威 union。现有可展示
工具仍按当前 terminal status 和 payload 生成 presentation。

### Stored-entry domain 收窄

当前 `TranscriptCollabAgentStoredEntry` 的 terminal 分支接受完整
`TranscriptCollabAgentItem["tool"]`。当 policy 明确忽略四种工具后，stored-entry domain 也必须
表达“只有可展示工具能被存储”，否则 selector 会被迫处理 policy 永远不会写入的状态。

设计要求从权威 `TranscriptCollabAgentItem["tool"]` 使用 `Exclude` 机械派生 terminal visible
tool 类型，并精确排除上述四种 ignored tools。它不是手写镜像 union：未来新增且未被显式排除的
tool 仍会流入 stored-entry type，并在 selector 的 `never` 检查处触发编译失败，迫使 GUI
重新选择 present 或 ignore。

不得通过 `as`、宽字符串、optional tool、unknown 或 selector fallback 伪造类型收窄。

## `completed` activity 展示设计

### Frontend-owned title 语义

`TranscriptActivityCopy` 是 frontend 展示语义，不是协议 DTO 镜像。它增加：

```ts
{
  kind: "agentCompleted";
  agentThreadId: TranscriptSubAgentActivityItem["agentThreadId"];
  agentPath: TranscriptSubAgentActivityItem["agentPath"];
}
```

字段继续通过 indexed access 依赖权威 `SubAgentActivity` 类型，不复制字段类型。

### Selector 投影

`transcriptStateSelectors.ts` 的 `subAgentActivity` 分支继续是 stored entry 到 presentation view 的
唯一解释位置。`entry.activityKind === "completed"` 时，将其映射为 `agentCompleted` title，保留
原 `agentThreadId` 与 `agentPath`，details 仍为空。

switch 必须继续显式覆盖 `started`、`interacted`、`interrupted`、`completed`，并保留 `never`
检查；禁止把未知 kind 映射为通用 activity。

### Surface 与 Lingui 文案

`CommittedTranscriptSurface.tsx` 的 `SubAgentActivityRow` 增加 `agentCompleted` 分支，沿用当前
chips、omitted count、非交互 activity row 和 HeroUI 结构。英文源文案为：

```text
Completed <sub-agent chips> <omitted count>
```

它必须继续使用 `Trans` macro，并带 translator comment，说明这是“展示已经完成工作的
sub-agents 及省略数量的活动行”。短词 `Completed` 在缺少上下文时可能被误译成静态状态标签，
因此 comment 必须明确它描述子代理完成任务的活动语义，而不是按钮或表单状态。

实现时通过项目入口 `pnpm run messages:extract` 更新 `src/locales/en.po` 和
`src/locales/zh-CN.po`，并为 `zh-CN` 填入准确翻译。不得手写 message ID、绕过 macro 或只改一个
locale catalog。

### 生命周期保持不变

`projectCompletedTranscriptItem` 已把所有 `subAgentActivity` 物化为独立 stored entry；
committed projection 已按 item ID 和 projection 顺序追加 completed-only item；snapshot 路径也使用
同一 policy。因此本设计不新增 completed 专用 reducer、查找表、状态 owner 或跨 item 更新逻辑。

`itemStarted` 对 `subAgentActivity` 仍返回 ignore。这里的 started notification 与
`SubAgentActivityKind.started` 是不同维度：前者是 item lifecycle 通知，后者是已完成
`subAgentActivity` item 所表达的业务活动类型。不得为了显示 `kind="completed"` 而改变
itemStarted 处理。

## `SkillMetadata.pluginId` fixture 设计

权威生成类型要求 `pluginId: string | null`：字段必需，值可空。当前四处 fixture 表达的是“合法
skill metadata，且没有已知 owning plugin”，所以应机械补入：

```ts
pluginId: null,
```

精确位置：

- `codex-gui/src/__tests__/AppShell.browser.test.tsx`
- `codex-gui/src/features/skillCatalog/__tests__/skillCatalogOwner.test.ts`
- `codex-gui/src/features/guiHost/__tests__/generatedAppServerProtocol.test.ts`
- `codex-gui/src/features/guiHost/__tests__/guiHostCommands.test.ts`

这些 fixture 已直接声明为 `SkillMetadata` 或 typed `skills/list` response；补 `null` 保持真实 wire
shape。不得把 `pluginId` 继续传入 `SkillCatalogCandidate`、UI 或 query state，因为当前产品并不
消费它；也不得为了减少 fixture 修改而把字段改成 optional。

## 测试设计

### Policy 与 presentation unit 覆盖

`transcriptItemPolicy.test.ts` 应覆盖：

- 四种新 collaboration tool 在 started policy 中分别得到 `ignore`；
- 四种新 collaboration tool 在 terminal policy 中分别得到 `ignore`；
- `completed` sub-agent activity 物化为 `subAgentActivity` stored entry；
- selector 把它映射为 `agentCompleted` view，并保留 `agentThreadId`、`agentPath` 和空 details。

测试继续使用 `projectionTestBuilders.ts` 的 typed `collabAgentToolCall` 和 `subAgentActivity`
builder，不在测试内新建协议镜像。

### 追加式生命周期覆盖

`transcriptStateCommittedProjection.test.ts` 应用不同 item ID 构造 Started 与 Completed activity，
证明：

- 两个 entry 都存在；
- Completed 按事件顺序追加；
- Started 的 stored/view 内容、identity、revision 和位置不被改写；
- snapshot 与 completed-only 仍收敛为同一 settled view。

该测试验证的是本次已确认的产品语义，不能用“最终只看到 Completed”之类断言替代。

### Browser Mode 展示覆盖

`CommittedTranscriptSurface.browser.test.tsx` 应在现有 sub-agent activity 可访问名称矩阵中加入
completed，并增加相邻 Started/Completed 场景，验证：

- 可见文案为 `Completed <agent>`；
- `zh-CN` locale 下可访问名称使用准确的 Completed 中文翻译；
- Started 与 Completed 因 title kind 不同而形成两条活动行；
- activity 仍使用现有非交互语义、chips 和 omitted count；
- 同类分组规则没有被本次适配意外改变。

Completed 场景应包含超过 3 个相邻 completed item，直接断言前三个 chips 和 omitted count，避免
只用单个 agent 的 happy path 漏掉新 title 分支与现有分组上限之间的接线错误。

这是用户可见文案与分组边界，Browser Mode 必须真实收集并执行该测试文件；只跑 smoke 配置不能
替代，因为当前 smoke discovery 不包含它。本设计不改变布局、响应式几何、焦点、指针或键盘交互，
因此不单独要求真实 GUI 验收。

### Fixture 与 contract 覆盖

四处 `pluginId: null` 由其现有 owner/command/validator/Browser 测试加 TypeScript type-check 覆盖，
不新增只断言静态 `null` 的测试。

validator drift check 必须继续通过，用来证明没有通过手改 generated validator 隐藏协议变化。

## 风险与约束

- 如果只在 policy 中增加 ignore，而不收窄 stored-entry domain，selector 的 `never` 仍会失败；使用
  类型断言压过错误会破坏失败传播。
- 如果 completed 复用 `agentStarted` title kind，surface grouping 会把两个生命周期事实合并，违背
  独立展示决策。
- 如果按 `agentThreadId` 或 `agentPath` 回写 Started，会把追加式历史变成可变历史，并引入跨 item
  owner、replay 与 snapshot 收敛问题。
- 如果给四种新工具增加通用标题，会展示当前运行时从不产生的 public item，并把 private analytics
  能力误当成 transcript 产品语义。
- 如果把 `pluginId` 改成 optional 或省略，会让 GUI fixture 偏离真实 wire contract。
- 如果手改 schema、validator 或 generated fixture，短期 build 可能通过，但下一次生成会重新漂移。
- 如果只跑 Browser smoke，会漏掉本次真正受影响的 committed transcript surface 场景。

## 设计验收标准

- 四种新增 collaboration tool 在 started 和 terminal policy 中均逐项显式 ignore。
- stored-entry tool domain 通过权威类型的机械派生排除 ignored tools，selector 仍保持穷尽。
- `completed` 形成 `agentCompleted` title 和独立追加的 transcript entry，不修改 Started。
- surface 显示可翻译的 `Completed <agent>` 行，并保持现有 chips、分组和非交互语义。
- 四处合法 skill fixture 显式包含 `pluginId: null`，不扩大产品数据流。
- 没有 generated protocol/validator/projection fixture、Rust 或 package script 改动。
- type-check、目标 unit、目标 Browser Mode、catalog extraction 和 validator drift 责任均有明确入口。
- 所有 authoritative type dependency、typed builder 和 `never` 检查继续存在。
