## 唯一主目标

建立一套跨普通对话、目标确认、设计、计划、委派和 realtime 转交的用户指令保真治理：自然语言允许在保持关键语义等价的前提下简洁概括，机器字面量必须逐字保持；全局系统提示词只保留始终生效的短不变量，详细识别和复核流程由专门 skill 承载，realtime 默认前端提示词只负责忠实转交原始用户消息、纠正和持续约束。

本设计只定义提示词与 skill 的责任分层、保真语义、转交契约、失败行为、首轮影响范围和验收边界。它不是 implementation plan，不定义任务顺序、提交拆分、执行图或实施命令，也不授权修改任何提示词、skill、产品代码、配置或 issue 状态。

## 已确认的产品决策

### 自然语言采用语义等价保真，机器字面量采用逐字保真

自然语言可以为了沟通效率进行概括，但概括前后必须保持决定任务结果的对象、动作、预期结果、范围、否定条件、阈值、包含或排除关系、时序和用户自定义术语等价。不能把“展示”扩成“性能优化”，不能把“评估重复”换成“评估覆盖”，也不能把“参考”直接等同于逐行复制或极端删减。

命令、alias/function 调用、代码标识符、协议字段、配置键和值、文件路径、URL、版本号、正则表达式及其他面向机器的字面量必须保留原始字符、token、空格和参数边界。若怀疑用户写错，不得静默纠正；应保留原文，并只在差异会改变结果时请求澄清。

### Realtime 前端不生成结构化语义锚点

realtime 对话前端继续把原始用户输入与对话增量作为权威来源。前端提示词只要求忠实转交当前请求、后续纠正和仍有效约束，不额外生成对象、动作、范围、否定条件或阈值等结构化字段，也不让结构化摘要替代原文。

语义锚点由执行端在消费原始消息时识别。这样避免前端和执行端形成两个可能互相漂移的解释 owner，也不新增协议字段、schema、上下文 fragment 或兼容路径。

### 只治理默认 realtime 提示词

首轮只修改默认 `BACKEND_PROMPT`。请求级 prompt 和 `experimental_realtime_ws_backend_prompt` 配置继续保留“完整替换默认提示词”的现有语义；显式选择 override 的调用方自行承担其提示词保真责任。

本设计不在 Rust 选择逻辑中追加不可覆盖的系统片段，不改变 override 优先级，也不声称覆盖使用自定义 prompt 的 realtime 会话。

## 当前事实与问题校准

### 全局规则已有局部保护，但没有统一保真 owner

本机实际生效的 `~/.codex/AGENTS.md` 是指向 `codex-config/AGENTS.md` 的符号链接。现有规则已经分别保护：

- 目标、动作授权、作用范围和负面约束不能互相推出；
- 产品语义不能因为使用技术载体而被降格为实现细节；
- shell 命令的 token、空格和参数边界必须原样保留；
- 代码标识符、命令、日志、协议字段和路径不得擅自翻译。

缺口不在于完全没有相关规则，而在于这些规则按授权、shell 和语言场景分散，未建立适用于概括、转述、拆任务、目标确认、计划和委派的统一保真不变量。尤其缺少以下通用行为：

- 识别并持续保留自然语言中的对象、动作、边界、否定、阈值和用户术语；
- 对所有机器字面量统一禁止静默规范化、纠错、合并或改写；
- 无法证明改写等价时，回退为引用原文或请求澄清；
- 用户后续纠正只替换相交语义，其他仍有效约束继续保留。

### `codex-gui` 是传输边界，不是语义改写 owner

当前 `codex-gui` 将 Lexical 编辑器内容编译成 app-server `UserInput[]`，排队后复制到 `turn/start` 或 `turn/steer`，再通过 JSON-RPC 发送。文本块换行与结构化 skill 引用属于协议编码；待发送内容的 preview 裁剪只影响展示，不影响真实 payload。

因此，本问题不能通过在 `codex-gui` 新增提示词、摘要器或结构化语义模型解决。GUI 应继续保持原始输入传输与现有协议编码，并作为未来回归验证的字面量边界，而不是成为新的语义裁决层。

### 真正的 realtime 前端提示词位于 Rust prompts crate

`codex-rs/prompts/templates/realtime/backend_prompt.md` 是 realtime 会话默认的对话前端提示词。它要求前端把执行任务交给 Codex、立即转交用户的新指令和纠正，并持续保持任务级表达偏好，但尚未要求交接内容保持关键语义与机器字面量。

该模板经 `codex-rs/prompts/src/realtime.rs` 暴露，并由 `prepare_realtime_backend_prompt` 选择。配置级 prompt 优先于请求级 prompt，请求级 prompt 又优先于默认模板；任一 override 都会完整替换默认模板。这一事实构成本设计“仅覆盖默认提示词”的明确边界。

## 保证边界

本方案是提示词层治理，只能降低模型在理解、概括、转述和交接过程中改变用户意图的概率。它不能提供工具调用前的强制 token 比对，不能在运行时证明命令、过滤表达式或参数与用户原文一致，也不能保证所有未来模型严格遵守自然语言规则。

因此，即使后续完整实施本设计，也不能把提示词约束描述成工具级 enforcement，不能仅凭文案变化宣称所有历史事故已经从机制上不可再现。关联 issue 是否可以关闭，仍需基于实施后的行为验收、当前入口覆盖和剩余运行时风险另行判断；本设计不授权更新 issue 状态。

## 责任分层

### 全局系统提示词：始终生效的短不变量与 skill 路由

`codex-config/AGENTS.md` 只增加或合并为一小段跨任务不变量：

- 任何概括、确认、设计、计划、委派或执行都必须保持决定结果的用户语义等价；
- 机器字面量必须逐字保留，无法确认等价时引用原文或请求澄清；
- 需要识别、记录或跨边界转交这些内容时，使用中央指令保真 skill。

全局文件不展开锚点分类表、逐步检查流程、事故案例或场景矩阵，也不复制 `action-authorization` 的动作族、授权字段、special approval 和生命周期规则。现有 shell 展开检查仍由 Shell 命令安全规则承担，现有授权公理仍由动作授权治理承担。

### `instruction-fidelity`：信息转换保真的唯一详细 owner

在手工维护 skill 的正确位置 `codex-config/skills/instruction-fidelity/` 新建自动发现 skill。它只回答“用户原本表达了什么，以及转换后的表达是否仍然等价”，不回答“当前是否已授权执行”。

其详细职责包括：

- 区分可概括的自然语言与必须逐字保留的机器字面量；
- 识别对象、动作、结果、范围、否定、阈值、包含/排除、时序、引用关系和用户术语等语义锚点；
- 在目标确认、摘要、设计、计划、委派、提示词构造和工具参数准备之间保持锚点等价；
- 以用户最新纠正覆盖相交语义，同时保留未被撤销的其他约束；
- 检测无依据的目标扩张、对象替换、评价维度替换、端点丢失和机器字面量变化；
- 在不能安全证明等价时选择保留原文，只有差异会改变结果且无法由证据闭合时才询问用户；
- 使用合成、无隐私的示例说明边界，不把真实用户历史原文复制到 skill。

主 `SKILL.md` 保留适用场景、核心流程和 reference 路由；条件性分类、转换复核和合成验收案例可按渐进披露放入 references。具体 reference 文件数量和文件名属于后续实现机制，不在设计阶段固定。

该 skill 不维护授权记录，不解释 `grantSource`、`negativeConstraints`、canonical target、special approval 或动作族固有步骤；一旦任务涉及有状态动作，识别出的原始语义交由 `action-authorization` 按其现有模型判断。

### `action-authorization`：继续独占动作授权语义

现有 `action-authorization` 已经拥有目标、动作、参数边界、逻辑与 canonical target、副作用、否定约束、后续指令字段级更新和特殊确认。本设计不修改该 skill，也不让新的保真 skill 建立第二份授权记录。

两者的契约是单向分工：

```text
原始用户消息
  -> instruction-fidelity：识别且保持“说了什么”
  -> action-authorization：判断“这些话授权了什么动作、目标和副作用”
```

保真结果不能自行产生授权，授权 skill 也不能为了便于建模而改写原始命令、路径、字段、阈值或否定条件。

### Realtime 默认前端提示词：只负责忠实转交

`codex-rs/prompts/templates/realtime/backend_prompt.md` 只加入一条简短的 realtime 转交契约：

- 交给执行端的内容必须忠实保留用户当前请求、后续纠正和仍有效约束；
- 不把用户请求重写成新的目标或产品语义；
- 命令、路径、字段、阈值等机器字面量保持原样；
- 原始输入和对话增量继续作为权威来源，不生成结构化语义锚点。

模板不复制中央 skill 的完整分类和复核流程，因为 realtime 前端不加载本机执行端 skills，也不应承担执行端的授权判断。

## 语义保真模型

### 自然语言锚点

自然语言的保真判断不是逐字相等，而是检查下列会改变用户结果的维度是否保持：

- `object`：要处理、观察、解释或修改的对象；
- `action`：展示、评估、修复、提交、参考、删除等动作；
- `outcome`：用户要求得到的实际结果；
- `scope`：文件、模块、时间、平台、数据集或任务阶段边界；
- `negative`：不要、排除、禁止、仅限等限制；
- `threshold`：数值、端点包含关系、上限、下限和排序条件；
- `relation`：参考、替换、比较、来源、先后和依赖关系；
- `term`：用户明确指定的名称、标签和领域术语。

实现不要求把这些维度永久序列化为新的协议结构。它们是 skill 在需要改写或转交时使用的检查视角，原始用户消息始终是权威证据。

### 机器字面量

以下内容默认按不透明字面量处理，不由模型自行正规化：

- shell 命令、alias/function 调用、参数、重定向及 token 间空格；
- 文件和目录路径、URL、Git ref、版本号及哈希；
- 代码标识符、协议字段、配置键和值、环境变量；
- 正则表达式、查询片段、格式字符串及用户指定的精确输出文本；
- 会影响过滤或判断的数值表达、比较符号和端点。

自然语言中的普通排版空白不自动升级为机器字面量；一旦空白参与命令分词、参数边界、格式、正则或精确输出，它就是必须保留的内容。

### 转换前后复核

每次把用户请求变成目标摘要、设计陈述、计划节点、子代理任务、realtime handoff 或工具参数前，执行相同的概念性复核：

1. 找出当前消息及仍有效历史约束中的语义锚点和机器字面量；
2. 生成必要的简洁表达，但不新增原文没有的目标、评价维度或产品语义；
3. 反向比较转换结果是否遗漏、替换、扩大或收窄锚点；
4. 逐字比较机器字面量及其 token、空格和参数边界；
5. 若差异无法由用户原文和当前证据证明等价，则恢复原文或询问用户。

这套复核是信息转换契约，不是固定要求每次向用户展示内部字段，也不要求普通回答机械复述完整请求。

## 修正、歧义与失败行为

### 用户纠正优先覆盖相交语义

用户后续纠正对象、动作、范围、阈值或字面量时，立即停止沿用被纠正的旧表达。只替换发生交集的语义字段，不丢弃没有被撤销的其他持续约束。

例如，用户纠正筛选阈值不自动撤销币种限制；纠正目标文件不自动授权修改相邻文件；纠正命令空格必须回到用户给出的原始 token 边界。

### 不制造无依据的决策

若代码、配置、文档或用户已确认目标能够唯一推出正确解释，模型应自行采用并说明关键依据，不把事实问题包装成用户选择。只有至少两个都符合目标、但会产生不同用户结果或风险的方向真实存在时，才请求决策。

### 无法确认等价时保留原文

保留原文是默认的低风险回退。只有原文存在会改变结果的真实歧义，且无法通过当前 workspace 或其他获准证据闭合时，才询问用户。不得为了显得简洁而猜测，也不得为了避免判断而把所有自然语言都升级成逐字复述。

## 首轮修改边界

后续实施计划应只考虑以下首轮目标：

- 精简补强 `codex-config/AGENTS.md` 中的通用保真不变量与 skill 路由；
- 新建 `codex-config/skills/instruction-fidelity/` 及其必要 metadata/references；
- 修改默认 realtime 前端提示词 `codex-rs/prompts/templates/realtime/backend_prompt.md`；
- 通过 codex-config 的现有安装入口让新 skill 出现在本机 `~/.codex/skills/`，但具体命令、冲突预检和副作用必须在计划阶段核验并展示。

首轮明确不修改：

- `codex-gui/**` 的输入、队列、transport、preview 或 skill catalog；
- `action-authorization/**`、`managing-work-stages/**`、`grilling/**`、`enhanced-message-context/**` 或其他既有 skills；
- realtime prompt 选择逻辑、请求/配置 override 语义、协议字段、schema 和上下文 fragment；
- upstream base instructions、Default collaboration prompt 或项目根 `AGENTS.md`；
- 工具调用前的 runtime validator、capability enforcement、shell 执行器或过滤引擎；
- 关联 issue 的状态与证据正文。

## 验收边界

### 自然语言场景

后续行为验收至少覆盖以下合成类别，而不是把真实历史 rollout 原文写进 skill：

- 对象保持：只改变指定展示元素，不扩成身份、协议或其他对象；
- 目标保持：展示分页不被改写成性能优化；
- 参考保持：逐项分析参考内容的取舍，不默认全量复制或极端删减；
- 评价维度保持：评估重复时不换成覆盖率、重构质量或其他指标；
- 否定保持：排除折扣、币种、平台或来源后，结果继续满足这些约束；
- 阈值保持：包含端点的自然语言条件在转换后仍包含端点。

### 机器字面量场景

- 多 token 命令保持 token 数量、空格和参数边界；
- 路径、字段、配置值、版本和正则不被翻译、纠错或正规化；
- 怀疑字面量错误时先保留原文，必要时澄清，不静默执行改写后的值；
- 向 skill、子代理、计划或 realtime 执行端转交时，字面量前后一致。

### Realtime 默认提示词场景

- 默认 `BACKEND_PROMPT` 明确要求忠实转交请求、纠正、持续约束和机器字面量；
- handoff 继续使用原始 `input_transcript` 与 `active_transcript`，不新增结构化锚点；
- `codex-gui` 的真实输入 payload 不因本设计改变；
- request/config override 继续完全替换默认提示词，并明确不在本轮保证范围内。

### Skill 质量

- skill 名称和 description 能准确触发信息转换保真任务，但不吸引与转述、边界识别或交接无关的普通工作；
- `SKILL.md` 简洁路由，详细分类和案例按需加载，只有一个详细保真 owner；
- skill 不复制动作授权模型，不把提示词约束描述为工具级保证；
- 使用独立上下文对合成事故场景做正向与负向行为检查，验证不会走向“所有自然语言逐字复述”的另一极端；
- 按全局规则使用规定的隔离 `uv` 命令运行 `quick_validate.py`，具体命令留待计划阶段只读核验。

## 实施前门禁

设计落盘不等于设计确认。本文获得用户明确确认后，才能进入独立计划阶段；设计确认也不自动授权创建计划、修改提示词、创建 skill、运行安装入口、验证、stage 或 commit。

任何实施开始前，必须向用户展示拟写入 `~/.codex/AGENTS.md` 的精确内容，并取得面向该受保护文件的单独明确写入确认。由于该文件指向 `codex-config/AGENTS.md`，直接修改 symlink、修改实际目标、脚本改写、恢复或格式化都属于同一受保护资源写入，不能绕过该门禁。

后续若编写并确认实施计划，必须先把本设计及相关计划文档创建为独立本地 Git 提交；提交成功前不得开始任何实施任务。计划还必须分别处理 codex 仓库与 codex-config 仓库的写入、验证、Git index 和提交边界，并遵守不操作 Git 远程、不安装程序以及项目固化入口等现有约束。
