## 唯一主目标

为高风险任务建立可审计的计划前纵向影响面证据闭包：全局与 GUI 提示词只保留简洁、稳定的触发门禁和项目差异，详细调查方法由现有 `$managing-work-stages` 统一拥有；在请求用户确认计划前，必须展示一份精简、可复核的证据摘要，使计划修改范围、验证范围和排除项能够追溯到当前代码证据。

本设计只定义提示词与 skill 的责任分层、纵向闭包语义、用户可见证据契约、失败行为和验收边界。它不是 implementation plan，不定义任务顺序、执行图、提交拆分或实施命令，也不授权修改提示词、skill、issue 状态、Git index 或本地提交。

因此，本设计的方向是去重和补齐证据契约，不是再增加一套平行规则。

## 已确认的产品决策

### 高风险计划确认前强制展示精简证据摘要

用户已选择方案 A：高风险任务在请求确认计划前，必须向用户展示一份精简证据摘要。摘要不是完整搜索日志，也不是把所有文件列表倾倒到对话中；它只保留足以判断计划是否可信的证据结构。

低风险任务继续按风险分级执行轻量核验，不强制展示完整摘要。发现新消费者、未知 owner、未追踪生成物、生命周期或失败恢复路径时，任务立即升级为高风险并补齐完整闭包。

### 可见性是完成条件的一部分

“助手内部已经调查”不能单独证明纵向影响面闭合。高风险任务只有在关键事实已闭合，并且精简证据摘要已展示后，才允许请求用户确认计划。

该摘要是阶段证据，不是新的用户审批点。若没有新的产品语义、范围或授权变化，展示摘要后直接进入既有计划确认，不额外增加一次形式化确认。

## 精简证据摘要契约

高风险任务在请求计划确认前，向用户展示的摘要至少包含以下字段：

| 字段 | 必须回答的问题 | 最低证据要求 |
| --- | --- | --- |
| 权威入口 | 这项行为或契约由哪里定义，真实生产入口在哪里？ | 当前文件、符号或生成源的路径；必要时附行号或入口名称 |
| 已追踪链路 | 哪些 validation、export、生成物、消费者、生命周期和恢复路径适用？ | 每条适用链路至少一个当前代码或配置证据 |
| 修改范围 | 为什么计划需要这些文件、模块或生成物？ | 每个计划范围项能回指上游证据或消费者证据 |
| 验证映射 | 每个受影响行为由哪个真实验证入口覆盖？ | 当前存在且会实际命中目标的测试、类型检查、生成或界面验证入口 |
| 排除项 | 哪些相邻路径已检查但不受影响？ | 支持排除结论的当前证据，不能只写“未发现” |
| 剩余未知 | 还有什么未确认，是否会改变根因、范围或验证方式？ | 标明关键或非关键；关键未知必须阻断计划确认 |

摘要必须精简，但不能把多个缺乏证据的结论合并成一句“影响面已分析”。详细命令、完整搜索结果和长文件清单留在调查上下文、设计文档或计划证据中，不强制全部打印给用户。

## 纵向闭包完成条件

高风险任务只有同时满足下列条件，才允许请求计划确认：

- 权威定义、真实生产入口和预期修改点之间的关系已经由当前代码证明；
- 所有适用的 runtime validation、公开出口、生成链、直接与间接消费者、生命周期、失败恢复和验证层已经追踪；
- 计划修改范围、验证范围和排除项均能回指证据；
- 不存在会推翻根因、扩大计划或改变验证方式的关键未知；
- 独立反向审计没有发现遗漏影响面、未验证假设或约束冲突；
- 用户已经看到精简证据摘要。

不是所有项目都存在每一层。某层不适用时，可以排除，但必须说明为什么不适用并给出证据。不得为了形式完整而虚构不存在的生成链、生命周期或恢复路径。

## 失败与回退行为

- 计划确认前发现关键未知：停留在调查或设计阶段，补证据，不请求用户确认一个已知不完整的计划。
- 独立反向审计发现新消费者或新 owner：将其加入影响链，重新计算范围和验证映射，再生成新的摘要。
- 实施中发现足以扩大计划或改变验证方式的事实：判定前置闭包失败，停止受影响动作并回到对应阶段；不得把它描述成普通实施细节。
- 发现与本次变化无关的预存问题：单独报告并排除，不借纵向闭包扩大修复范围。
- 只有非关键新事实且不改变根因、范围或验证：记录边界并继续，不制造额外确认。

## 验收边界

### 规则与 skill 验收

- 全局事实闭包规则比当前更短，并明确路由到唯一详细 owner；
- `$managing-work-stages` 主文件能在高风险计划前稳定路由到详细 reference；
- reference 覆盖权威输入、纵向链路、证据摘要、排除项、未知项、计划映射和反向审计；
- GUI 提示词只保留前端差异，不复制通用流程；
- 没有新增第二个纵向闭包 skill，也没有扩大 `$codex-gui-toolchain` 的职责；
- skill 结构和 metadata 通过规定的 `quick_validate.py` 验证方式，具体命令在计划阶段按当前规则核验。

### 合成行为验收

后续行为检查至少覆盖：

- contract 变化同时命中 authoritative type、runtime validator、schema 生成物、公开出口和 fixture；
- UI 结构变化命中间接 DOM/ARIA selector 与旧值断言消费者；
- 模块删除命中 barrel export、alias 或残余 import；
- 状态 owner 变化命中 mount/unmount、resume/reconnect 和失败恢复；
- 验证命令存在但实际未发现或未执行目标测试；
- 某纵向层确实不适用，并能以当前代码证据排除；
- 低风险局部改动不被迫输出完整高风险证据摘要。

### 真实效果验收

提示词和 skill 修改、机械验证及合成行为检查只能证明规则层已经落地，不能单独证明原问题已经消失。关联 issue 至多进入“📏 待复核”。

只有后续真实高风险任务中不再在计划确认后发现足以推翻根因、扩大计划或改变验证方式的纵向影响事实，才能考虑将关联 issue 标记为“✅ 已修复”。
