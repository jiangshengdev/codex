# 行动前未形成事实闭包

日期: 2026-08-24
状态: 🔴 仍需处理
范围: Codex 任务调查、设计、计划与执行前置核验
优先级: P0

## 摘要

Codex 多次在精确对象、权威定义、真实入口和完整影响面尚未闭合时开始设计、判断或修改，导致错误方案、错误根因和连续返工。

## 问题

执行过程常把局部搜索、未验证假设或文档描述直接提升为完整事实，未先核对真实代码、页面状态、完整输入输出链、直接与间接消费者、生成链、失败恢复和实际验证入口。执行环境的固定 recipe、cwd、运行用户、必要工具和 sparse 输入也经常到失败后才检查。

## 判断

该问题仍成立，是本月最主要的执行根因。Sparse 缺失只是统一“执行前事实与环境完整性检查”的一个分支，单独扩充 sparse 默认范围不能解决大多数事件。

## 影响

错误假设会进入设计、计划、子代理任务和验证链，造成错误方案、遗漏消费者、计划外文件确认、整轮重验、上下文压缩以及用户在实施后才发现语义或视觉错误。自动测试只能证明当前改动的机械正确性，不能补回缺失的前置事实。

## 后续处理

需要为“行动前事实闭包”单独进入设计阶段；设计确认后再编写独立计划。该入口应覆盖精确对象、权威定义、真实入口、纵向影响面、失败恢复、验证入口和执行环境完整性，但本 issue 不展开 implementation plan。
