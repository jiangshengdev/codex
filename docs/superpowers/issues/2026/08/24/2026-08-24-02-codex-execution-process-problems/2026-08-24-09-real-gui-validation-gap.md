# GUI 自动验证与真实可操作性之间存在缺口

日期: 2026-08-24
状态: 🔴 仍需处理
范围: Codex GUI 布局、交互和视觉状态验收
优先级: P1

## 摘要

自动测试通过不能证明真实 GUI 可操作、布局正确或视觉状态完整，已有任务在测试完成后仍由用户发现明显错位和样式丢失。

## 问题

现有验证偏重类型、lint、单元测试和 Browser 测试中的机械断言，但没有稳定覆盖真实页面中的几何关系、视口裁切、浮层方向、焦点状态和组件视觉契约。

当验证只证明 DOM 节点存在、事件可触发或预设断言通过时，候选面板仍可能溢出、向错误方向展开，迁移后的输入组件也可能丢失原有默认、hover、disabled、invalid 或 `focus-visible` 状态。未实测布局时，代理还曾把视觉空隙归因于错误 CSS 属性，修改和验证后又撤销。

## 证据

- 月度审计保守确认“自动验证没有覆盖真实用户体验”至少涉及 3 条任务链，主要影响是测试通过后仍存在 GUI 错位和视觉状态丢失。
- 未实测布局便归因并修改错误 CSS，完成修改和验证后又撤销：rollout `019ffe1b…` 第 236、353、384–404 行。
- 自动化闭环后，真实页面仍存在几何错位，组件迁移后原有样式和 focus 状态丢失：`/Users/jiangsheng/.codex/sessions/2026/08/19/rollout-2026-08-19T11-41-40-01a0181c-4148-78e2-9c0e-63b634405499.jsonl` 第 5669–5775 行。
- 月度审计明确判断，GUI 验证必须包含真实可操作性、布局和视觉状态，不能用自动测试通过替代实际界面核验。

## 判断

问题仍然成立。自动验证是必要条件，但当前证据表明它不是 GUI 完成标准；真实浏览器中的操作、几何和视觉状态需要成为独立验收面。

## 影响

- 用户在“验证全部通过”后仍遇到不可用或明显错误的界面。
- 视觉问题被延后到用户截图阶段才发现，导致重新调研、设计、计划和实现。
- 机械断言可能固化错误布局，同时给出错误的完成信号。
- 输入、浮层和焦点等跨组件视觉契约在迁移时容易静默丢失。

## 后续处理

需要单独进入设计阶段，定义真实 GUI 验收的最小覆盖面，包括目标路由、代表性视口、关键操作、布局几何、浮层裁切与方向、键盘焦点和组件视觉状态；同时明确环境未就绪、测试未进入用例与真实验收通过之间的状态区别。
