# 03：打通有状态组件预览

**What to build:** 让依赖 Redux 或 Router 的组件在 Storybook 中获得按需上下文，并通过最小可操作预览证明业务状态和导航相互隔离。

**Blocked by:** 01：打通基础真实渲染。消费其已验证预览环境，不依赖任务 02。

**Status:** ready-for-agent

- [ ] 需要 Redux 的 Story 使用现有工厂创建独立 store，不复用产品全局可变单例。
- [ ] 需要 Router 的 Story 获得隔离路由上下文，能够执行最小导航交互。
- [ ] 切换 Story 后业务状态不串入另一 Story，返回预览时可重复得到初始业务状态。
- [ ] 路由操作不替换 Storybook 管理页面，不挂载会启动产品连接流程的整个应用路由树。
- [ ] 主题、语言、Redux、Router 的相对嵌套顺序与应用一致，纯组件不被迫依赖完整业务上下文。
- [ ] 复用权威状态类型，不复制协议或 store 模型，不连接真实业务后端。
- [ ] 可在实际 Storybook 页面证明上下文可用及导航、状态隔离。
- [ ] 与主题分支集成时不新增第二套主题状态，相关回归及质量检查通过。
- [ ] 形成独立本地任务提交，参与父计划的最终合并验收。

测试边界：最小有状态 Story 的用户交互与真实预览导航，辅以现有 Browser 测试方式。具体文件与命令由父计划管理。
