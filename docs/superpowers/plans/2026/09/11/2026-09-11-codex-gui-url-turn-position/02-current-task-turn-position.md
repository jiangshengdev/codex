# 02：当前聊天接入 URL 定位

**What to build:** 用户打开 `/task/<threadId>?turnId=<turnId>&position=end` 后，在当前聊天看到目标 turn 结尾，避开输入框遮挡；定位完成后继续使用页面原有滚动行为，持续输出不被 URL 定位反复打断。

**Blocked by:** [01：历史预览支持 URL 定位](01-history-turn-position.md)提供的稳定共享定位能力及验证证据；同时受[共同门禁](plan.md)约束。

**Status:** blocked — 等待任务 01，且未获实施授权。

## 验收条件

- [ ] 使用任务 01 的共享定位能力，接受既定当前聊天 URL，不增加平行参数解析或定位实现。
- [ ] 等待 projection 完整历史快照就绪后查找目标，不把加载中状态当作轮次缺失。
- [ ] 目标跨展示页或跨片段时定位正确结尾，实际位置避开输入框；窄视口验证遮挡关系。
- [ ] 默认初始化滚动不会覆盖本次目标定位；完成后交还原有滚动控制。
- [ ] projection 增量、重渲染和持续输出不会重新执行已完成的 URL 定位；不改变既有自动滚动策略。
- [ ] 完整历史中目标不存在时显示最新位置与临时提示；连接或读取错误维持原有恢复语义。
- [ ] 重新打开或刷新执行新的定位，URL 参数保留；无参数保持原有行为。
- [ ] 离开页面后，旧定位请求不滚动新页面。
- [ ] 页面级测试覆盖真实滚动结果及增量场景，并回归历史预览能力。
- [ ] 两项任务合并后的状态通过最终组合验证；真实运行时直接打开、刷新与未执行场景分别报告证据。

不增加 Rust 协议或持久化字段，不改变聊天激活及发送流程，不恢复 fork 来源入口任务。任务提交与已有提交修正均遵守共同提交边界。
