### 共享节点字段

- `estimatedCost`：短为单次局部核验，中为一个有界文档产出，长为跨 owner 调查；仅用于调度，不作为停止阈值。
- `deferralEvidence`：空；不因任务编号或 agent 复用串行化。
- `executionContext`：ROOT 当前 `dev` 工作树、当前 Git index；执行前用 Git 查询其实际路径，canonical index 只有 Git owner 可写。
- `resourceLocks`：每个节点的 `readSet` 对应 canonical 文件 read 锁，`writeSet` 对应 write 锁；Git 节点另持实际 index 和当前本地分支引用 write 锁。LOG 只有记录子代理持 write 锁。读取稳定副本或不可变结果时使用其产物身份。
- `stateEffects`：调查、审查、验证节点仅返回对话结果；编辑节点只写其 `writeSet`；Git 节点仅产生所列任务的本地 index/commit 状态。
- `commandScope`：调查限 `cat`、`rg`、路径解析、内容摘要及只读本地 Git 查询；编辑限普通文档编辑；验证限读取产物、内容比较和非 fix 空白检查。Git 节点仅精确路径的普通 `git add`、staged diff 检查和普通本地 `git commit`，不得 force、amend、操作远程或提交 ignore 文件。具体命令必须在对应动作预检后确定。
- `subdelegation`：false；后续任务由主代理重新下发信封。
- `verification`：节点所列证据完整，输入有路径与内容身份，结果区分实际观察、静态判断、未验证项；所有文档写入再读回并检查空白。
- `failureDomain`：失败节点及实际消费其产物的传递后继；无依赖分支继续。
- `replanTriggers`：目标路径或来源漂移、必要证据失效、需要新文件或项目外副作用、发现硬边界冲突、真实验证入口或授权不足。计划内普通修正只重编受影响节点，不修改已确认计划正文。
- `authorizationGate`：当前全部执行节点为 pending。确认执行后只为准备阶段建立 active 信封；后续迁移仍 pending。信封记录当前授权来源、动作、精确参数、读写集合、canonicalTargets、禁止项、特殊确认、到期条件；节点返回后到期。

## 执行失败与最终交付

失败只影响实际消费者。记录具体证据后，在同一已授权范围内继续调查、修正与必要复验；缺工具时报告组件和建议命令，等待用户自行安装，不绕过或自装。新增范围、风险或授权才形成局部门禁。准备阶段不以远程操作、产品构建或桌面验收为依赖。

已形成提交的修正必须创建新独立提交。不得为中间提交添加兼容路径，不把无行为重排混入行为修改。全部任务汇合后的稳定状态才是最终验证对象。

准备阶段交付 DESIGN/PLAN 的文档提交、T1 的提案提交、基线与 owner 清单、冻结场景、候选文字、审查结果、写入提案和执行记录。终态汇报列出实际并行、关键路径、未启动 ready 节点及有效原因，并明确静态评审、真实运行验证与未执行项。达到本阶段完成条件后停止，不自动追加新一轮工作。
