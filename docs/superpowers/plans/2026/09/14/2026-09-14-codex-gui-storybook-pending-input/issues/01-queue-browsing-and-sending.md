# 01：队列查看与普通发送

**What to build:** 在 Storybook 中打开真实待发送队列，查看双通道列表并手动推进普通发送，稳定检查等待、结果与清空状态，为其他场景提供隔离且可重置的预览装配。

**Blocked by:** None (can start immediately)。执行仍须通过总计划的实施授权与文档提交门禁。

**Status:** ready-for-agent

- [ ] 提供独立状态与可操作 Story，复用真实队列组件、应用会话与协调器，不复制产品 UI 或队列状态机。
- [ ] 引导与普通队列各自显示正确数量、分页和长消息展开/收起；不可管理状态保留产品允许的阅读能力。
- [ ] 抽屉从真实入口打开和关闭，键盘可操作且关闭后焦点正确返回。
- [ ] 无消息时遵循现有入口隐藏规则，已打开抽屉在消息清空后显示空态。
- [ ] 普通发送进入等待后不自行完成，模拟控件只能推进所属待处理操作。
- [ ] 请求响应与运行时确认分别按现有语义推进，不收到成功响应就强行移除消息。
- [ ] 重置、切换和重新进入还原独立初态，旧待处理结果不会污染新场景。
- [ ] 使用虚构数据和独立内存存储，不读取真实会话、不产生业务连接或真实发送。
- [ ] 共享装配使用权威类型与现有注入入口，不导入依赖 Vitest mock 的测试运行器设施。
- [ ] 本票测试通过可见文案、数量、列表、动作与焦点验证上述路径，并在现有三浏览器项目中实际通过。
- [ ] 不提前实现编辑失效、排序故障或恢复全流程；交付稳定接口供后三票使用。
