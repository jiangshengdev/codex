# 03：排序与异常反馈

**What to build:** 在队列 Story 中执行四种排序，查看边界与不可管理限制，并演示排序未生效和已移动但刷新失败的不同反馈。

**Blocked by:** 01：队列查看与普通发送。消费其稳定队列预览与分页装配；不依赖 02 或 04 的新增场景。

**Status:** ready-for-agent

- [ ] 提供排序正常、不可排序及两类异常的独立状态和可操作流程。
- [ ] 上移、下移、置首、置尾即时调用真实管理操作并更新顺序，不等待额外模拟完成按钮。
- [ ] 首尾边界与不可管理消息符合产品动作限制，排序不改变消息归属。
- [ ] 排序后的数量、分页内容和焦点保持一致，不出现重复或丢失消息。
- [ ] 明确区分未发生移动与已经移动但更新后列表无法加载，验证各自文案及真实后续行为。
- [ ] 难触发失败使用有界接口替身，保留产品反馈处理路径，不以替身结果宣称验证了生产算法。
- [ ] 不依赖编辑或恢复 ticket 构造阻塞输入，直接消费权威接口表达合法状态。
- [ ] 重置与切换不保留排序结果或旧失败反馈。
- [ ] 本票 E2E 覆盖四种移动、边界和异常结果，通过用户可见列表及动作验证，不锁定内部字段。
- [ ] 不修改排序策略、产品消息或协议契约。
