# 01：当前任务可手动恢复同步

**What to build：** 当任务消息同步暂停时，用户能看到具体原因，点击“恢复同步”重新取得该任务的可信状态，并继续查阅和操作；恢复保持草稿、待发内容与既有发送保护，不连带重连其他任务。

**Blocked by：** None（无其他功能 ticket 阻塞）。执行仍需用户确认实施计划，且设计与计划文档必须先独立本地提交。

**Status：** ready-for-agent（任务描述就绪，尚未授权产品执行）

这是一个完整纵向切片，包含暂停解释、恢复操作、队列与订阅一致性、界面反馈和验证。内部实现节点、精确写集合、工具命令及 Git 边界由同目录实施计划管理，不把内部层次拆成可独立发布的功能。

- [ ] 更新积压、提交链不连续、缺少关联轮次均有通俗原因和相同的恢复入口。
- [ ] 用户手动触发恢复，无自动重试；只替换当前连接对故障任务的订阅，不切换查看任务、不重连其他任务。
- [ ] 非执行时按钮始终为“恢复同步”，执行中显示 Spinner 与“正在恢复…”，失败后恢复相同动作名称。
- [ ] 执行中保留上次错误、诊断和旧正文，按钮位于原操作区；重复点击或键盘触发仅产生一次有效恢复。
- [ ] 失败更新对应错误并允许再次操作，不将 Promise 完成、blocked 或 unavailable 判为成功。
- [ ] 仅在新快照、订阅和必要数据核对均有效后解除同步故障，后续新消息持续更新，再次暂停仍可恢复。
- [ ] 恢复保留 live 会话、队列与编辑器身份；草稿及 retained 未保存编辑不丢失、不自动保存或发送。
- [ ] 暂停立即阻止自动发送；晚到的发送回执、编辑清理或延迟消费不能绕过该保护。
- [ ] 快照更新真实运行轮次，并正确核对发送及中断状态；unknown 无正面证据不清除、不自动重发，恢复暂停确认和保存保护继续生效。
- [ ] 持久化失败不发布成功或丢弃原待处理事实，用户再次恢复能够重新完成核对。
- [ ] 旧订阅 event、delta、closed 及旧恢复结果不能污染新状态；连接替换、任务切换和卸载均有隔离。
- [ ] 压缩与任务状态在恢复后保持一致：未知压缩请求不被当作未执行，旧状态读取不能覆盖新基线。
- [ ] 当前同步故障只有一个主面板；固定历史错误和其他独立错误保留，成功仅解除对应故障。
- [ ] 宽窄屏沿用现有错误布局，说明、诊断与操作顺序稳定，无溢出，键盘及焦点行为可用。
- [ ] 应用级与必要 owner 回归、类型/lint/格式/生成合同检查通过；中英文翻译提取稳定。
- [ ] 真实无头 GUI 场景单独记录通过或未执行，不以 mock/harness 结果代替真实验收。

不包含共享连接断开恢复、其他质量报告缺陷、后台任务重新执行或后端协议变更。不得为中间节点可运行而保留临时兼容、双路径或放宽保护。
