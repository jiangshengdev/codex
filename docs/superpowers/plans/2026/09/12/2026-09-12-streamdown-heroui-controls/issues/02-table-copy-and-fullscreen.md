# 02：表格采用 HeroUI 复制菜单与全屏

**What to build：** Markdown 表格使用 HeroUI 复制菜单与全屏弹层，修复应用侧复制能力判断，并让键盘、焦点和滚动行为符合设计。普通与全屏表格均移除下载，保留纯文本和 HTML 表格复制能力。

**Blocked by：** None（无其他 ticket 阻塞；执行仍需主计划授权与文档提交、工作树预配门禁）。

**Status：** ready-for-agent

- [ ] 静态／流式生产 Markdown 入口使用唯一的 HeroUI 表格操作区；表格正文继续消费 Streamdown 的语义 children，不改用数据表格重建正文。
- [ ] 普通与全屏表格均无下载入口、隐藏下载按钮或下载执行路径。
- [ ] Markdown、CSV、TSV 复制都同时写入对应纯文本与 HTML 表格，直接使用公开提取和序列化函数。
- [ ] 表格能力判断独立检查安全上下文、write 和 ClipboardItem，不以 writeText 代替；仅有 writeText 时隐藏表格复制，支持富文本复制时不额外要求 writeText。
- [ ] 写入成功才显示成功反馈；拒绝或异常有明确、可感知的失败反馈，可再次操作，不静默降级为纯文本。
- [ ] 菜单可通过 Tab、方向键、Enter、Escape 操作，有正确名称与语义，关闭后恢复到触发器。
- [ ] 全屏打开后焦点进入并圈定；全屏内菜单优先处理 Escape，菜单关闭后 Escape 可退出全屏；关闭按钮保持可用。
- [ ] 退出全屏恢复触发器焦点、背景滚动和原表格阅读位置，卸载时不遗留监听、锁或定时资源。
- [ ] 普通表格保留默认限高与内部横纵滚动；流式贴底跟随新增内容，用户上滚时不抢回；全屏显示当前表格正文。
- [ ] 沿用 isAnimating 禁用复制与全屏入口；普通与全屏没有第二套冲突的菜单／弹层 owner。
- [ ] 验证浅色／深色主题、窄屏、portal 可见性及真实键盘焦点；不依赖程序 focus 冒充可达性。
- [ ] 模拟剪贴板验证三种格式载荷、能力矩阵、拒绝和重试；修正已有错误能力断言及下载等待锚点，保留正文、主题和相邻回归覆盖。
- [ ] 本任务完整受影响 Browser 文件、类型、lint、格式和 catalog 稳定性检查通过，形成独立本地行为提交。
- [ ] 不修改第三方库或依赖，不改变 Markdown 安全策略、持久状态和 transcript chunk 边界。

与代码任务的交集由主计划集成处理，不形成 ticket 间阻塞。最终合并验收必须在同一消息中同时验证两类控件、全部下载移除及独立能力判断，并完成适用的真实应用无头验收。
