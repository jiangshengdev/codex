## 目标与边界

重新审计当前 Codex GUI 所有适合采用 HeroUI 的控件，包括此前报告的候选项。优先 HeroUI React 组件，自定义实现须有具体可核实的保留理由；官方允许样式组合与本项目更严格的采用标准分别判断。

每个分区完整贯穿规范对照、生产使用路径、组件适配、适用的无头验证与证据结论。不得以导入搜索代替审计，不预设任何旧发现为真。不修改产品代码、依赖、配置或测试基线；不安装工具、不启动可见窗口、不操作 Git 远程、不构建原生后端。

本次授权仅为计划与本地任务落盘。所有执行节点保持 pending，用户另行明确开始后才能调度。不得将任务文件中的 ready-for-agent 视作启动授权。本轮不创建报告占位、不运行测试、不提交。

## 公共节点契约

以下字段适用于全部节点，节点表和任务文件细化各自范围：

- `operationKind`：T01–T05 为 investigation；T06 为 fan-in，报告写入属于该节点明确交付。
- `completionEvidence`：可复核的结构化证据包，包含基线身份、覆盖项、源码位置、规范依据、验证命令或交互步骤及结果；无法验证项必须带原因。T06 以报告内容及覆盖复核结果为完成证据。
- `readSet`：规格、适用规则、当前前端源码与相关测试、匹配版本本地 HeroUI 文档和源码，以及分区实际依赖的 Lexical/Streamdown 实现。T01 核对 canonical 路径后交接。
- `writeSet`：T01–T05 不修改仓库文件，输出证据包；T06 仅写正式报告。程序正常产生的测试与运行产物按既有规则处理，不授予主动操作范围外文件的能力。
- `stateEffects`：执行阶段允许已授权的有界无头验证运行状态及报告写入；不允许修改真实用户会话、队列或其他业务数据。需要有状态场景时先核对隔离测试载体和具体动作授权，缺口不得以真实用户数据替代。
- `commandScope`：只读搜索和文件检查；验证仅使用 codex-gui-toolchain 规定的受影响测试入口和已有可用无头应用入口；不安装、不运行全量测试或原生构建。T06 可用普通文档编辑工具写报告。
- `owner`：主代理负责基线、协调和唯一报告写入。执行时依 delegating-micro-stages 判断并指定分区调查 owner；子代理只返回证据，不写共享报告、不操作 Git。
- `subdelegation`：禁止子代理继续委派。
- `executionContext`：当前 checkout，沿用现有分支与 index，不创建 worktree 或分支；审计不写 Git index。执行前独立文档提交由主代理串行完成。
- `resourceLocks`：生产源码为 read；正式报告为 T06 独占 write；测试 runner、浏览器会话及其状态目录在 T01 解析真实 canonical 身份，涉及共享可变状态时独占 write。不同逻辑名称不得掩盖同一底层资源。
- `verification`：每个分区核对来源、构造和消费者；运行适用的受影响测试与无头真实应用场景，分开记录静态、Level 1 与 Level 2 结果。Level 3 不执行，不以无头结果替代可见桌面证据。
- `failureDomain`：分区失败影响该分区及 T06；基线变化仅使实际依赖该基线的证据失效。缺少运行环境不阻止独立静态调查，但必须保留验证缺口，不宣称完整运行验收通过。
- `replanTriggers`：需要产品修改、新接口、安装、真实业务数据变更、可见窗口、范围外状态操作，或发现基线/资源身份失真。只暂停受影响动作，继续无依赖的授权工作。
- `deferralEvidence`：当前无；执行时只有实际资源冲突等可核实证据可以暂缓已就绪工作。
- `authorizationGate`：全部 pending。grantSource 为用户确认的任务拆分与计划落盘请求，仅允许本轮文档创建；执行能力信封须在用户明确开始后按动作、readSet、writeSet、canonical target、状态副作用及生命周期重新收紧。未声明能力默认禁止。

## 验证与报告验收

1. 覆盖矩阵囊括生产入口、共享包装、原生交互、样式组合、动态生成及第三方实际启用控件，每项有唯一审计归属。
2. 自定义保留理由核对 HeroUI 匹配版本的实际能力、现有状态所有权、交互语义和性能边界，不凭名称或历史选择推断。
3. 主动作、辅助动作、取消、破坏性动作及状态反馈分别核对语义，不将合法 variant 误报为 API 错误。
4. 验证面向用户行为，包括适用的键盘、可访问名称、焦点、禁用、处理中、弹层与滚动；不写镜像实现测试、不修改断言或基线。
5. 报告分别列出采用遗漏、语义偏差、合理例外和未验证项；每项发现带证据、影响、分级理由及建议。
6. 所有分区证据交叉复核，检查遗漏、重复、冲突及基线一致性后才形成最终结论。允许如实报告环境缺口，但不得将缺失验证记为通过。
7. 最终报告位于用户指定目录；审计完成不自动授权修复、远程发布或新一轮工作。
